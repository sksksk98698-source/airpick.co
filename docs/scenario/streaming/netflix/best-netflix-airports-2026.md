## 二、底层机理：Netflix 到底怎么判断你"在哪一区"

### 2.1 三级判定链：可达性 → 区域归属 → 版权授权

Netflix 客户端的播放链路并不是一个简单的 HTTPS 请求，而是一条多段式判定链：

- **第一级：网络可达性。** 客户端能否与 `fast.com`、`nflxvideo.net`、`netflix.com` 完成 TLS 握手。这一级被墙、被 QoS 限速、被 SNI 阻断的节点，表现为首页转圈或 App 报错 `NW-2-5`。
- **第二级：区域归属。** Netflix 后端会根据你的出口 IP 查询 GeoIP 数据库与 ASN 记录，再叠加 DNS 解析结果。若 IP 归属地与 DNS 解析到的 Open Connect 节点不一致，会触发"代理检测"，降级为仅自制剧。
- **第三级：标题级授权。** 每个 title 有独立的地域授权表。同一部剧在 A 区可播、在 B 区 404，是版权合同决定的，与你的线路质量无关。

**关键推论**：机场宣称"解锁 Netflix"时，必须区分它解锁的是第几级。只过第一级的机场满大街都是。

### 2.2 原生 IP、双 ISP 与广播 IP 的分水岭

Netflix 的风控核心是 **ASN 信誉评分**。一个 IP 段如果长期被爬虫、代理、薅羊毛流量占据，其信誉分会被打穿，随后整个段被 Netflix 拉黑。

- **广播 IP（Announced / Non-native）**：机房从上游租来一段 IP，实际服务器不在 IP 注册地。GeoIP 显示美国，实测路由却绕经欧洲。这类 IP 是重灾区。
- **原生 IP（Native）**：IP 注册信息与服务器物理位置、上游 ASN 完全一致。Netflix 判定上更"干净"。
- **双 ISP / ��宅属性 IP**：在 IP 注册库中带有 ISP 属性而非 Hosting 属性，风控容忍度显著更高，是当前抵抗 Netflix 静默降级最有效的手段之一。

2026 年的现实是：好机场普遍采用"专线中转 + 原生落地"架构——用户侧走 IEPL/IPLC 内网专线避开公网拥塞与 GFW 干扰，落地侧用原生或双 ISP IP 保证解锁。

### 2.3 为什么 IEPL/IPLC 决定 4K 生死

公网中转节点的典型链路是：用户 → 国内入口（BGP 多线）→ 公网隧道 → 海外落地 → Netflix。整条路径上有 15 到 25 跳，任何一跳拥塞都会造成 TCP 重传。

IEPL（International Ethernet Private Line）与 IPLC（International Private Leased Circuit）是**二层专线**，用户流量从入口直接进入运营商内网，全程不经过公网路由。带来的直接收益：

- 丢包率从公网的 1%～8% 降到 `0.01%` 级别；
- RTT 抖动从 30～80 ms 压到 3～10 ms；
- 晚高峰（20:00–23:00）不再出现带宽塌陷。

Netflix 的自适应码率算法（基于吞吐量与缓冲区健康度）对抖动极其敏感。抖动大的线路即便峰值带宽够，也会被强制从 4K（15.6 Mbps）降到 1080p（5 Mbps）甚至 720p。

此外，2026 年主流机场普遍启用 **BBRv3** 拥塞控制与 **TLS Reality / uTLS 指纹伪装**。前者在高丢包链路下提升吞吐，后者对抗 SNI 阻断与主动探测。但要注意：部分 Reality 节点为了伪装牺牲了 MTU 与 UDP 质量，反而拖累 Netflix 的 QUIC 传输——这就是为什么"能上 Google"的节点未必"能看 4K"。

## 四、人群与场景选型

**场景 A：单人 4K 观影党（Apple TV / 电视端为主）**
优先专线档，关注单节点带宽与 UDP 质量。电视端无法灵活切换节点，稳定性权重高于价格。建议选择带 x1 无倍率计费的机场，避免 4K 流量被倍率放大快速耗尽。

**场景 B：多设备家庭共享（3–5 台同时在线）**
需要节点并发与带宽冗余，建议 IEPL 档 + 多落地入口。注意 Netflix 的"家庭同户"策略对 IP 跳变敏感，尽量固定同一落地出口。

**场景 C：出海 / 跨境运营与 AI 研发**
Netflix 只是顺带需求，核心是低延迟稳定链路。选 IEPL 专线档，同时核查 ChatGPT / Claude 的原生解锁能力——同一套原生 IP 池通常能一并解决。

**场景 D：预算有限的轻度用户**
公网优化档可用于 1080p 与自制剧，但不要期待非自制剧全区解锁，也不要作为长期主力。

## 五、分平台实操配置与深度避坑

**Windows（Clash Verge Rev / v2rayN）**：优先使用内核级 TUN 模式，避免浏览器代理插件造成的 DNS 泄漏。规则集中务必启用 `GEOSITE,netflix` 与 `GEOIP,netflix` 双规则，防止 Netflix 流量走直连导致账号风控。

**macOS（Surge / Stash）**：开启 `enhanced mode`，把 `nflxvideo.net`、`nflxso.net`、`fast.com` 一并加入代理规则。只代理 `netflix.com` 会让视频流走本地 ISP，直接触发代理检测。

**iOS / iPadOS（Shadowrocket / Stash）**：关闭"按需连接"中的蜂窝网络乱切，避免中途 IP 跳变。测速请用 Netflix 官方 `fast.com`，而非第三方节点测速工具。

**Android TV / Apple TV**：Apple TV 无系统级代理，需在路由器层做透明代理或使用支持旁路由的方案。路由器建议启用 `full cone NAT`，否则 QUIC 协商失败会回退 TCP，4K 起播变慢。

**常见坑**：
- 只勾选 `netflix.com` 域名规则 → 视频 CDN 走直连 → 只能看自制剧；
- 使用 IPv6 直连泄漏 → 出口 IP 与代理 IP 不符 → 被判定代理；
- 频繁切换不同地区的落地节点 → 触发账号异常登录 → 需要重新验证。

## 六、抓包排障诊断手册

遇到"能打开但只能看自制剧"或"4K 频繁掉码率"，按下面顺序排查。

**第一步：确认链路质量**

```bash
# 看整条路径的丢包与抖动，重点看从第 8 跳之后
mtr -rwzc 100 1.1.1.1

# TCP 层握手延迟与端口可达性
tcping -c 20 -p 443 www.netflix.com
```

**第二步：确认出口 IP 归属**

```bash
curl -s https://ipinfo.io/json
# 重点看 org 字段是 Hosting 还是 ISP，以及 country 是否与预期区域一致
```

**第三步：确认 DNS 是否泄漏**

```bash
dig @8.8.8.8 netflix.com +short
nslookup netflix.com
# 若解析结果与本机 ISP DNS 结果一致，说明 DNS 走直连，存在泄漏
```

**第四步：标题级解锁探测**

```bash
# 自制剧（全球通吃），返回 200 说明网络可达
curl -s -o /dev/null -w "%{http_code}\n" https://www.netflix.com/title/80057281

# 非自制剧（地区限定），返回 200 才算真正解锁该区
curl -s -o /dev/null -w "%{http_code}\n" https://www.netflix.com/title/70143836
```

**判定表**

| 自制剧返回码 | 非自制剧返回码 | 结论 | 处理方向 |
| --- | --- | --- | --- |
| 200 | 200 | 完整解锁 | 正常使用 |
| 200 | 404 | 仅自制剧 / 部分解锁 | 更换落地节点，检查 DNS 泄漏 |
| 404 | 404 | 完全被墙或被拉黑 | 换节点或换机场 |
| 超时 | 超时 | 链路不通 | 检查 mtr 丢包与入口可用性 |
| 200 | 302 跳转 | 区域被强制重定向 | 清理 Cookie 与缓存后重试 |

## 七、行业避坑矩阵

| 宣传话术 | 真实含义 | 核验方法 |

| "解锁全区" | 通常只解锁 3–5 个热门区 | 逐区实测，重点测日区、英区非自制剧 |
| "无限流量" | 多伴随超高倍率或限速阈值 | 查看倍率表与限���条款 |

## 八、常见问题 FAQ

**Q1：为什么我的机场能看 Netflix 自制剧，但《老友记》提示"不在该地区提供"？**
典型的标题级授权问题，说明落地 IP 的 GeoIP 归属与该剧授权区不匹配，或 IP 被 Netflix 标记为代理。换用原生 IP 落地节点通常可解决。

**Q2：4K 标清自动降级，是带宽不够吗？**
多数情况不是。先跑 `mtr` 看丢包与抖动，抖动超过 30 ms 时 Netflix 会主动降码率。专线线路在此项上优势明显。

**Q3：为什么 Apple TV 上完全用不了？**
Apple TV 不支持系统级代理。需要在路由器层做透明代理或使用旁路由方案，并确保 UDP 转发正常。

**Q4：同一账号在不同节点频繁切换会怎样？**
可能触发账号安全验证，甚至被临时限制。建议固定一个落地出口，或使用 Netflix 官方的家庭管理功能。

**Q5：机场宣传的"x1 无倍率"重要吗？**
非常重要。4K 单小时流量约 7 GB，若节点为 3 倍率，实际消耗 21 GB。长期看，无倍率带来的成本差异远大于月费差价。

**Q6：手机能解锁，电脑不行，是什么原因？**
通常是电脑端 DNS 泄漏或 IPv6 直连。关闭系统 IPv6 或在代理软件中强制 TUN 模式即可。

**Q7：为什么换了机场还是只能看自制剧？**
先排除本地因素：清理浏览器 Cookie、关闭 WebRTC、确认没有 IPv6 泄漏。若仍不行，则是机场侧 IP 池问题。
