## 一、TL;DR：老路由器刷 Padavan 值不值得折腾？

先把结论摆在最前面，省得你翻半天还踩坑：

- **硬件门槛**：MT7620A / MT7621A 平台、内存 `≥ 128MB`、闪存 `≥ 16MB` 的老路由器（斐讯 K2P、K2、Newifi 3、小米路由 3G、极路由 4 等）都能刷 Padavan，其中 **K2P A1/A2 版（MT7621A + 128MB RAM + 16MB Flash）是性价比天花板**，闲鱼 60-100 元能收到成色不错的机器。
- **能力边界**：Padavan 的 SFE 快转引擎在千兆内网能跑满 800-950Mbps 有线转发；但**开启 SS/VMess/Trojan 等加密代理后，MT7621A 的实测翻墙吞吐上限大约在 60-120Mbps 之间**，跑 4K 流媒体够用，想要跑满 500M 宽带那就是想多了。**老路由器做“旁路由”或“书房 AP + 二级路由”比做主力网关更明智。**
- **成本对照**：一台刷好的 K2P（80 元）+ 一份中端机场订阅（月付 15 元左右）≈ 100 元启动成本，体验接近市售 400 元级软路由方案的 70%。**注意：瓶颈永远在机场节点的物理链路质量上，而不是路由器的 CPU。**
- **核心坑点**：小内存路由开 Clash 内核极易 `OOM` 掉线，推荐使用 **SSR-Plus 精简版或 PassWall 精简包**，并用 `swap` 虚拟内存做兜底。固件不要迷信“最新版”，老毛子（hiboy）固件的稳定性版本往往比功能最多版本更值得刷。

如果你只是想用最省心的方式享受高速代理链路，**没有必要为固件折腾半个月**。直接选一条优质 IEPL/专线机场，在原生客户端里跑就能达到甚至超越很多自建方案——这也是为什么下文所有实操建议都围绕「链路质量 > 硬件堆料」这个核心逻辑展开。

## 二、底层机理：为什么老路由器翻墙会“卡”，卡在哪一环？

很多玩家一上来就抱怨“这破 K2P 太慢”，但实际上**99% 的“慢”都不在路由器本体**。我们按数据包从客户端到落地的完整路径拆解一次：

**1. 客户端到路由器（LAN 段）**
这一段走的是 802.11n/ac 无线或千兆有线。MT7621A 在 2.4G 频段跑 100-150Mbps、5G 频段跑 350-600Mbps 是常态，**不是瓶颈**。

**2. 路由器 NAT + 加解密（核心瓶颈段）**
这里是老路由器真正吃力的一环。以 Shadowsocks AEAD-2022 为例，单包需要 AES-128-GCM 或 ChaCha20-Poly1305 运算，MT7621A（双核 880MHz，无 AES-NI 硬件加速）单核跑 SS 大约 80-150Mbps，跑 VMess+WS+TLS 会掉到 40-70Mbps，跑 Trojan 大约 60-90Mbps。**这就是为什么很多人发现“直连测速 800M，一开代理测速 70M”。**

**3. 出口链路（真正决定体验的一环）**
你的机场节点到落地服务器之间，走的是 BGP 公网还是 IEPL/IPLC 内网专线，直接决定延迟抖动和丢包率：
- **公网 BGP 中转**：晚高峰 20:00-23:00 国际出口拥塞，丢包率可能从 0.5% 飙升到 8-15%，RTT 抖动 ±80ms；
- **IEPL 内网专线**：走运营商级内网专线，跨境内网直达，晚高峰丢包率通常维持在 `0.3%` 以内，RTT 抖动 ±5ms。
- **IPLC 跨境专线**：端到端物理专线，属于合规跨境电路，稳定性最强，成本最高。

**4. 落地服务器与 QoS**
落地端运营商对国际流量做 QoS 限速、对 TLS 指纹做特征识别，都能让你的 TCP 握手时间从 80ms 涨到 400ms。**BBRv3 拥塞控制算法在这里的价值极高**：它比 Cubic 在高丢包环境下吞吐能高 40%-300%，这也是为什么 2026 年主流机场都在服务端启用 BBRv3。

**5. TLS Reality 与伪装层**
从 2024 年开始，TLS Reality / VMess+WS+TLS+CDN 的伪装方案成为跨境标配。客户端握手增加约 30-60ms 额外 RTT，但换来的是抗封锁能力大幅提升。**老路由器跑 Reality 时注意关闭日志轮询，否则 flash 写坏是早晚的事。**

**结论**：老路由器的翻墙体验 ≈ **min(路由器 CPU 加解密上限, 机场链路质量上限)**。想要突破，先花钱买链路，再谈换硬件。

## 四、人群与场景选型：谁该刷机，谁该住手

**✅ 适合刷 Padavan 的三种人：**
1. **翻墙需求 ≤ 200Mbps、想省电省事的技术玩家**：K2P/Newifi 3 + 一条优质 IEPL 机场，整体成本 &lt; 200 元/年，体验好过很多千元方��。
2. **需要全局透明代理的家庭用户**：老人小孩的设备不用装客户端，路由器层分流（国内直连、国外走代理），一劳永逸。
3. **有软件折腾经验的极客**：想做 advblock 广告拦截、单臂路由、多拨、VLAN 隔离，Padavan 的脚本能力足够。

**❌ 不建议刷 Padavan 的三种人：**
1. **需要 >300Mbps 翻墙带宽**：直接上 N100 软路由或 x86 小主机，或直接上「光速云」高倍率专线在原生客户端跑满。
2. **完全不懂 SSH/命令行**：刷机过程中 brick 变砖的概率不低，恢复需要动手能力。
3. **只想“打开就用”**：Clash Verge / V2rayN / Shadowrocket 这些客户端在 PC/手机端体验已经远好于路由器二次封装。

**场景推荐：**
- **租房党/学生党**：K2 刷 Padavan + 光速云之类轻量套餐，宿舍一人一机一网无压力。
- **家庭主机房**：K2P 做二级路由，主路由只管拨号，代理流量全部走 K2P，故障隔离性好。
- **国行 PS5/Switch 加速**：Padavan 装 UU 加速器插件效果一般，建议直接路由器层做 DNS 白名单 + 代理分流。

## 五、实操配置与深度避坑（分平台）

### 5.1 刷机准备清单
- **固件来源**：优先选 [hiboy 老毛子固件发布页](https://opt.cn2qq.com/padavan/) 的稳定版，冷静看待第三方“多功能整合包”。
- **备份原厂固件**：用 `breed` 引导器在写入前 dump 一份。
- **刷 breed**：K2P 出厂 Bootloader 有签名校验，需要 TTL 拆机写 breed，教程参考站点内 [路由器刷机与 Breed 引导]( /client/device/router/openwrt-openclash-complete-installation-guide.html ) 章节。

### 5.2 Padavan 代理插件选择
| 方案 | 内存占用 | 吞吐 | 推荐场景 |
| --- | --- | --- | --- |
| SSR-Plus 精简版 | 20-30MB | 中 | 64MB/128MB RAM 老机 |
| PassWall 精简包 | 35-55MB | 高 | 128MB+ RAM |
| Clash Premium | 80MB+ | 高 | 谨慎，128MB 极易 OOM |
| OpenClash（Meta） | 100MB+ | 最高 | 256MB+ RAM 专用 |

### 5.3 关键配置项调优
- **开启 SFE 硬件快转**：`网络 -> 硬件加速 -> SFE 全部启用`。
- **关闭无用服务**：SMB、DLNA、Aria2、DDNS 一律关闭，释放内存。
- **配置 swap**：挂一个 U 盘做 `swap 512MB`，能显著降低 OOM 掉线。
- **节点优选**：使用 `tcping` 脚本每日 03:00 自动测速切换延迟最低节点。

### 5.4 特别提醒
- **不要迷信“科学加速”类魔改固件**，很多捆绑挖矿或后门。
- **Flash 写坏是大坑**，务必把日志级别调整到 `warn` 以上，关闭 debug 日志落盘。
- **机场节点质量决定 80% 体验**，路由器固件只影响 20%。这就是为什么我们更推荐**把折腾精力放在选机场上**——像「光速云」这类 IEPL/专线方案，直接让 K2P 跑出接近巅峰的表现。

## 六、抓包排障诊断手册

工欲善其事，必先利其器。以下命令在 macOS/Linux 下直接可用，Windows 用 WSL 或 Git Bash：

**① 判断是链路丢包还是本地问题：**
```bash
mtr -rwzbc 100 1.1.1.1
```
重点看 `Loss%` 与 `StDev`。若第二三跳稳定而末尾跳丢包 > 5%，说明是出口段问题。

**② 单节点 TCP 连通性/延迟测试：**
```bash
tcping -t 20 your-node.com 443
```
- 平均 RTT `< 200ms`、抖动 `< 20ms`：优秀
- RTT 200-350ms、抖动 20-80ms：可接受
- RTT `> 400ms` 或抖动 `> 100ms`：建议切换节点

**③ macOS 客户端网络信息查看：**
```bash
scutil --nwi
scutil --dns | head -30
```
判断默认路由、DNS 解析链路是否被代理劫持。

**④ 代理端口连通性验证：**
```bash
curl -x http://127.0.0.1:1080 -I https://www.google.com
curl -x socks5://127.0.0.1:1080 -I https://www.google.com
```
返回 `HTTP/2 200` 说明代理工作正常，返回 `Connection refused` 检查端口。

**⑤ 路由器侧查看代理进程：**
```bash
ps | grep -E "ss-redir|v2ray|clash" 
netstat -anp | grep ESTABLISHED | wc -l
```
`ESTABLISHED` 连接数超过 3000 且持续增长，通常是内存泄露或节点环回。

**判定速查表：**

| 现象 | 大概率原因 | 处理方式 |
| --- | --- | --- |
| LAN 内 `ping` OK，翻墙全断 | 节点被封或订阅过期 | 换节点/续��� |
| 局部网站慢，其他正常 | 目标站落地 QoS | 换落地国家 |
| 隔 30 分钟掉线一次 | 内存 OOM | 上 swap/换插件 |
| 晚高峰一过就恢复 | 国际出口拥塞 | 换 IEPL/专线机场 |
| 测速达标但视频卡 | TLS 指纹被识别 | 换 Reality 节点 |

## 七、行业避坑矩阵：识别虚假宣传与超售

| 宣传话术 | 真实情况 | 如何识破 |
| --- | --- | --- |
| “独家专线不限速” | 90% 是公网中转包装 | 用 `mtr` 看路径是否走运营商内网（`10.x`/`100.64.x`） |
| “10G 大带宽独享” | 共享带宽超售严重 | 晚高峰 8 点测速对照日常 |
| “全球解锁 Netflix 4K” | 只解锁标题不锁片源 | 直接在节点上播放《怪奇物语》S4 试 |
| “一键小白开箱即用” | 多数是贴牌 OSS 套壳 | 观察节点 IP 段重复率 |

3. 连续 7 天晚高峰 RTT 抖动 > 60ms：建议换供应商。

## 八、常见问题排障 FAQ

**Q1：K2P 刷完 Padavan 网络速度从 800M 掉到 90M，是什么原因？**
A：检查是否误开 SFE 关闭或启用 MTU 分片。若已开启硬件加速，检查代理插件是否走了 `tun` 模式（性能更差），改为 `redirect` 模式。

**Q2：为什么打开代理以后 DNS 解析错误频发？**
A：Padavan 内置 dnsmasq 与代理插件容易冲突。建议关闭路由器 DNS 劫持，改由机场订阅内指定 `DoH`，并在客户端使用系统 DNS。

**Q3：老路由器频繁断连重启怎么排？**
A：优先排查电源适配器老化（供电不足），其次检查是否内存 OOM，最后再看固件本身。极路由 4 常见问题是散热不良导致 CPU 降频。

**Q4：SS 与 Trojan 在 K2P 上谁更快？**
A：实测 K2P 上 **Trojan > SS-AEAD > VMess-WebSocket**。Trojan 因为握手轻量，在 MT7621A 上能多跑 15-25Mbps。

**Q5：Padavan 能不能挂两个机场做负载均衡？**
A：可以，但 MT7621A 单核运算无法并行加密，实际吞吐不升反降。**建议单订阅 + 智能分流，而不是多订阅并发。**

**Q6：老路由器能直接跑 Clash Meta 内核吗？**
A：能跑，但 128MB RAM 会非常紧张。推荐 `Clash.Premium` 而不是 `Meta`；或者直接刷 OpenWrt + Mihomo。

**Q7：光速云的节点能在 K2P 上跑满吗？**
A：单节点 2.5Gbps 是链路能力，K2P 的加解密能力约 100Mbps 是硬上限。**换句话说，你换成 N100 小主机或干脆用 PC 客户端，能拿到 Node 提供商给的全部带宽。**
