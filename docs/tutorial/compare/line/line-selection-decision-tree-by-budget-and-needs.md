## 一、TL;DR：把决策压缩成三句话

1. **月预算 15 元以内**——只能买到「共享入口 + 公网中转」的普通 BGP 机场，别指望晚高峰不卡，你的核心诉求应该是「能用、能连、不跑路」，而不是「能跑 4K」。
2. **月预算 40–80 元**——这个价位段是分水岭，能摸到「优质 BGP 中转 + 部分 IEPL 专线节点」的组合套餐，是 90% 用户的甜点区。看视频吃带宽，打游戏吃抖动，两条线要分开选。

如果你不想读完全文，记住这条决策链：

```
场景 → 峰值带宽需求 → 可容忍抖动 → 可容忍丢包 → 预算 → 线路类型
```

## 二、底层技术背景：你的钱到底买到了什么

不讲物理层谈选线，都是玄学。四个概念讲清楚，后面所有结论都能自己推导。

### 2.1 BGP 中转：调度聪明，但依然走公网

BGP（边界网关协议）的本质是**让数据包在多个运营商之间自动选路**。优质中转机场的做法是：租用国内多线机房做入口（电信/联通/移动三网优化），再通过 BGP Anycast 把用户流量调度到延迟最低的出口。它的优势是便宜、节点多、维护灵活；劣势同样明确——**只要中途任何一跳的公网链路拥塞，你的体验就塌了**。晚高峰 20:00–23:00 的国内骨干网拥塞，跟机场本身的技术水平无关，是物理现实。

所以评价 BGP 机场的核心指标不是「峰值能跑多少 Mbps」，而是**晚高峰的劣化幅度**。一个峰值 500Mbps、晚高峰掉到 80Mbps 的节点，比稳定 150Mbps 的节点更没价值。

### 2.2 IEPL / IPLC：把公网这一跳从路径上删掉

- **IPLC（International Private Leased Circuit）**：点对点国际私有专线，物理层独占，不走公网，延迟可预测。
- **IEPL（International Ethernet Private Line）**：以太网接口的 IPLC 变体，带宽弹性更好，单位成本更低，2026 年主流高端机场基本都在用 IEPL。

它们贵的原因很直白：**带宽是包月买断的，不共享、不超售**。一条 1Gbps 的 IEPL 月成本是普通公网转发的几十倍。这也解释了一个判断技巧——**凡是号称「全员 IEPL」还卖 9.9 元/月的，基本是伪专线**：入口到出口之间大概率后半段还是公网，只是把商标印上去了。

### 2.3 QoS 与 BBRv3：决定你在晚高峰的命运

- **QoS（服务质量）**：机场在出口侧对流量做优先级标记。付费高等级用户走 EF（加速转发）队列，普通用户走 AF/BE。这就是为什么同一节点，高等级套餐用户晚高峰依然顺滑。
- **BBRv3**：Google 的拥塞控制算法第三代，相比 BBRv1/v2 在有丢包的链路上吞吐提升显著。2026 年如果一家机场还在用 Cubic 或 BBRv1，说明内核版本和运维投入都不够，晚高峰体验可以直接打折。

### 2.4 TLS Reality / 双 ISP：抗封锁与抗风控的两条腿

- **TLS Reality**：无需自建域名和证书，直接「借用」目标站点的 TLS 指纹，握手阶段与真实访问无差别。这是当前抗 SNI 阻断的主流方案，比传统 VMess+WS+TLS 更隐蔽。
- **双 ISP（住宅 IP 双线）**：同时接入两家本地运营商，典型用于解锁流媒体与规避风控。ChatGPT、Claude 对机房 IP 段有持续的黑名单机制，**原生住宅 IP 的解锁成功率远高于机房 IP**——这一项在你选「AI 办公型」线路时权重极高。

更详细的原理解析可以对照站内的 [线路技术底层解析](/tech/)。

## 四、预算分层决策树：每个月花多少钱，买什么

### 4.1 月预算 ≤ 15 元：生存模式

**能买到**：入门 BGP 中转、共享 IP、单倍率节点、容量普遍 100–500GB。
**买不到**：稳定的晚高峰、4K、原生 IP、客服。

这个预算段的核心策略是**降级期望**：

- 把目标从「流畅 4K」降到「1080p 可看、网页秒开」；
- 避开 20:00–23:00 做重负载操作，把大文件下载放到凌晨；
- **不要买年付**。这个价位段跑路率最高，季付是风险上限。

选线建议：优先选「入口多线 + 出口日本/新加坡」的中转节点，物理距离短决定了它的下限比欧美节点高。具体节点筛选逻辑见 [场景选型：入门经济型](/scenario/)。

### 4.2 月预算 15–35 元：主流效率区

**能买到**：优质 BGP 中转、部分 IEPL 试用节点、1–3 倍率混合节点池。

这是**学生党和轻办公用户的最优解**。此价位段的关键判断标准只有一个：**晚高峰的劣化曲线**。同一个价位，A 家峰值 300Mbps 晚高峰掉到 60Mbps，B 家峰值 180Mbps 晚高峰只掉到 130Mbps——选 B。峰值是给你看广告的，稳定性才是给你用的。

选购动作清单：
1. 找有「晚高峰测速报告」的机场，没有实测数据的直接跳过；
2. 优先支持**单月付 + 无理由退款**的商家，用一个月验证真实体验；
3. 检查节点列表里是否有至少 2 个不同上游的入口（防单点故障）。

### 4.3 月预算 35–80 元：专线入门区（甜点区）

**能买到**：BGP + IEPL 混合池、部分全专线节点、原生 IP 节点、1–2 倍率。

这个区间是 2026 年性价比曲线的拐点。你的核心诉求变成**「业务区分」**：

- ���**看视频/下载**流量绑到 BGP 节点（大带宽、低倍率）；
- 把**游戏/会议/交易**流量绑到 IEPL 节点（低抖动、稳定）。

Cliash/Mihomo 的分流规则就是为这个场景设计的，配置方法见 [分流规则实操教程](/tutorial/)。

### 4.4 月预算 80 元以上：企业级/重度用户

**能买到**：全 IEPL/IPLC、2.5Gbps 级单节点、专属 QoS 队列、住宅原生 IP、SLA 承诺。

如果你的场景里有以下任意一条：**跨境直播推流、外汇/量化交易、跨国团队远程桌面、TikTok 账号运营**，那么专线的钱不能省。抖动 30ms 和抖动 3ms 之间差的不是体验，是业务能不能跑。

## 五、场景选型：看视频选 BGP，打游戏选 IEPL

这是本文的核心命题，展开讲透。

### 5.1 看视频 / 下载 / 刷流媒体 → 选 BGP 大带宽

视频和下载属于**吞吐型负载**，特征是：能容忍一定抖动（播放器有缓冲区），但对**持续带宽**极度敏感。4K HDR 单流需要 25–35 Mbps 稳定吞吐，8K 需要 80 Mbps 以上。

BGP 中转在这个场景有天然优势：出口机房带宽池大、单位成本低、可以做到 1 倍率甚至更低。你花 30 元买到的 BGP 节点，有效带宽往往超过同价位 IEPL 节点的 3–5 倍。

**关键提醒**：流媒体解锁和带宽是两回事。有些 BGP 节点带宽很猛，但 IP 段被 Netflix 标记为机房 IP，直接报错。所以你真正要测的是 **「4K 起播时间 + 是否被降码率」**，而不是 Speedtest 数字。解锁检测方法见 [流媒体解锁验证手册](/help/)。

### 5.2 打游戏 / 语音 / 远程桌面 → 选 IEPL 低抖动

竞技类游戏（FPS/MOBA）属于**延迟敏感型负载**：带宽需求只有 1–5 Mbps，但对 RTT 和抖动要求苛刻。

- RTT 超过 120ms：射击类游戏基本没法玩（命中判定错位）；
- 抖动超过 20ms���语音通话开始断续；
- 丢包超过 2%：出现「瞬移」和「技能放不出」。

IEPL 专线的价值就在这里：**它把公网拥塞这一变量从路径上删掉了**，晚高峰的 RTT 曲线几乎是平的。这就是「打游戏选 IEPL」的物理依据，不是玄学。

**实操建议**：游戏流量走 IEPL，其余走 BGP，通过 Mihomo 的 `rules` 按进程名或域名分流。具体规则模板见 [游戏与低延迟场景配置](/scenario/)。

### 5.3 跨境办公 / AI 工具 → 选原生 IP + 中等带宽

ChatGPT、Claude、GitHub Copilot 这类服务对 IP 质量的要求高于对带宽的要求。你的核心指标是 **IP 纯净度**（是否被风控标记），其次才是速度。优选住宅原生 IP 节点，带宽 100 Mbps 量级完全够用。

### 5.4 内容创作 / 直播推流 → IEPL + 稳定上行

上行稳定性压倒一切。推流码率 6000 kbps 意味着你需要**持续 8 Mbps 以上的稳定上行**，且不能有超过 1 秒的断流，否则直播平台会直接踢流。BGP 在晚高峰的丢包会造成 OBS 频繁重连，只有专线能兜住。

## 六、分客户端实操配置与深度避坑

### 6.1 Windows / macOS — Mihomo（Clash.Meta）

核心是**订阅转换 + 分组策略**。不要把几十个节点全塞进一个 `select` 组，而是按延迟和倍率拆成三组：

- `PROXY-FAST`：低延迟组，`url-test` 自动选优，interval 300s；
- `PROXY-BULK`：大带宽组，手动指定 BGP 节点；
- `PROXY-GAME`：IEPL 专线组，手动锁定，禁用自动切换。

**避坑点**：`url-test` 的默认探测 URL 是 `http://www.gstatic.com/generate_204`，这个地址在部分网络下会被污染，导致误判全组超时。换成自建探测地址或 `https://cp.cloudflare.com/generate_204` 更稳。

### 6.2 移动端 — Shadowrocket / Surfboard

手机端的最大坑是**省电策略杀后台**。iOS 上开启「始终开启 VPN」后仍可能被系统降频，建议把代理模式设为「规则」而非「全局」，减少无用流量唤醒。

安卓端注意 `TUN` 模式与分应用代理的冲突：部分国产 ROM 的省电白名单会导致 TUN 虚拟网卡间歇性失联，需手动把客户端加入「不受限制」列表。

### 6.3 路由器 — OpenWrt / ImmortalWrt

软路由全局代理是最省心的方案，但要注意：

- 打开 `BBR` 拥塞控制（`net.ipv4.tcp_congestion_control=bbr`），在老旧的 OpenWrt 内核上这一步能提升 20%–40% 的吞吐；
- 不要让路由器的单核 CPU 跑满，AES 加解密是单线程瓶颈，建议选支持 AES-NI 的 x86 平台；
- DNS 分流务必用 `fake-ip` 模式，`redir-host` 在 2026 年的复杂域名环境下误判率显著上升。

完整的配置模板整理在 [客户端配置总览](/tutorial/)。

## 七、��包排障诊断手册

体感差 ≠ 机场差。先用数据定位问题在哪一段，再决定是换节点、换机场还是换本地网络。

### 7.1 三层诊断命令

**第一层：路径质量（判断是本地网络还是机场问题）**

```bash
# 同时发 ICMP + TCP + UDP 探测，定位丢包发生在哪一跳
mtr -rwzc 100 -T -P 443 your-node-domain.com
```

看输出：**前三跳（你的路由器 + 本地 ISP）如果就丢包，问题在你家**，换机场没用。

**第二层：端到端延迟与抖动**

```bash
# TCPing：绕过 ICMP 限速，更贴近真实代理握手
tcping -t 60 -i 1 your-node-domain.com 443

# 关注 P95 / P99，而不是平均值
```

**第三层：应用层真实吞吐**

```bash
# 通过代理测下载曲线，观察是否中途掉速
curl -x socks5h://127.0.0.1:7890 -o /dev/null -w \
"connect:%{time_connect} ttfb:%{time_starttransfer} total:%{time_total} speed:%{speed_download}\n" \
https://speed.cloudflare.com/__down?bytes=104857600
```

### 7.2 判定表

| 现象 | mtr 表现 | 根因判定 | 处理动作 |
|---|---|---|---|
| 网页能开，视频转圈 | 前 3 跳正常，中段无丢包 | 出口带宽被跑满 | 换 BGP 大带宽节点 |
| 晚高峰必卡，白天正常 | 中段（第 5–9 跳）丢包 3%+ | 国内骨干拥塞 | 换 IEPL 专线 |
| TCPing 正常，实际很慢 | 路径无丢包，但 speed 低 | 服务端 QoS 限速或倍率 | 查套餐等级 / 换节点 |
| 全部节点超时 | 第 1 跳就丢包 | 本地网络 / 路由器 | 重启光猫与路由 |
| 频繁断连重连 | 抖动超过 50ms | 出入口切换或 IP 被墙 | 换 TLS Reality 节点 |
| DNS 解析失败 | 路径正常 | DNS 污染 | 切 fake-ip + DoH |

更完整的故障树整理在 [网络诊断手册](/help/)。

## 八、行业常见避坑矩阵

| 宣传话术 | 真实性判断 | 识别方法 |
|---|---|---|
| 「全员 IEPL 专线，9.9 元/月」 | 基本为伪专线 | 专线成本决定售价下限，低于 40 元的「全专线」必然有公网段 |
| 「无限流量不限速」 | 存在隐藏 QoS | 连续跑 100GB 后测速，观察是否被限 |
| 「原生 IP 全解锁」 | 需逐项验证 | 用 Netflix / ChatGPT / TikTok 三件套实测，不看截图 |
| 「永久套餐，一次买断」 | 跑路风险极高 | 2026 年无任何长期运营案例，年付已属高风险 |
| 「万兆入口，跑满光纤」 | 峰值≠可用 | 只信晚高峰测速，不信 Speedtest 峰值 |
| 「0 丢包」 | 物理不可能 | 任何公网链路都有基础丢包，专线也在 0.05% 量级 |

## 九、常见问题 FAQ

**Q1：月预算 15 元，能不能买到能打游戏的线路？**
不能。竞技类游戏需要抖动稳定在 15ms 以内，这个稳定性的带宽成本远高于 15 元。15 元预算下，把期望调整到「网页流畅、1080p 可看」更现实。

**Q2：为什么我买了专线，体感反而不如之前的 BGP？**
大概率是**物理距离**问题。IEPL 专线走的是固定路径，如果出口在美西而你访问的是日本服务，RTT 反而更高。专线的优势是**稳定**，不是**就近**。选专线前先确认出口机房位置与你的目标服务对齐。

**Q3：晚高峰卡顿，换节点有用吗？**
分情况。用 `mtr` 看丢包发生在哪一跳：如果是国内骨干（第 5–9 跳）拥塞，换节点无用，必须换线路类型（BGP 换 IEPL）；如果是出口机房拥塞，换节点有效。

**Q4：倍率是什么？为什么有的节点 0.1 倍，有的 5 倍？**
倍率是**流量计费系数**。0.1 倍意味着用 1GB 只扣 0.1GB 套餐流量，常见于低优先级节点；5 倍常见于高成本地区（如美西原生 IP）。**高倍率不等于高质量**，很多 5 倍节点只是 IP 贵，速度并不突出。全节点 1 倍率的套餐在成本可控性和使用体验上是最均衡的。

**Q5：订阅更新后节点全挂了，怎么办？**
先排除本地问题：用手机热点测试同一订阅，如果依然全挂则是服务端问题。其次检查订阅链接是否被墙——部分机场的订阅域名在国内已被 SNI 阻断，需要走「订阅转换」或本地已有节点代理更新。

**Q6：如何判断一个机场是否在超售？**
两个信号：一是**晚高峰速度衰减幅度**（超过 60% 即为重度超售）；二是**TCP 连接建立时间的方差**（`tcping` 的 P99 与 P50 差距过大，说明队列排队严重）。

**Q7：TLS Reality 和 Trojan 哪个更好？**
2026 年的抗封锁环境里，TLS Reality 的指纹伪装更彻底，主动探测下更难被识别。Trojan 依然可用，但在流量特征分析面前劣势逐渐明显。优选同时提供两种协议的机场，按网络环境切换。

## 结语

选线路这件事，**决策顺序比信息量更重要**。先想清楚你的场景需要什么级别的稳定性，再倒推预算区间，最后在同价位里对比实测数据。任何先看价格再找理由的做法，最终都会用一次晚高峰的卡顿来还账。

2026 年的行业分水岭已经清晰：**BGP 解决「够不够用」，IEPL 解决「稳不稳」，原生 IP 解决「能不能用」**。三者对应三个不同的业务需求，没有一种线路能同时把三件事都做到极致。你的任务不是找到完美线路，而是找到与你业务匹配度最高的那一档。

数据会说话，命令会说话，晚高峰会说话。其余的，都是营销。
