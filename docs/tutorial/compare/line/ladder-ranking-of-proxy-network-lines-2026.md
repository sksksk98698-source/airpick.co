# 翻墙线路技术终极天梯图：直连、中转、BGP、CN2与专线全方位横评

## 一、TL;DR：一句话结论先给你

如果你只想知道"哪种翻墙线路最好"，答案按优先级排序是：

**IEPL/IPLC 企业级内网专线 ＞ CN2 GIA 精品网 ＞ 优质 BGP 多线中转 ＞ 普通 BGP 直连 ＞ 163 骨干直连 ＞ 免费公共节点。**

但真实世界远比这条排序复杂。绝大多数机场宣传的"专线"其实是"中转 + 落地"套壳，标注"CN2"的可能只是 CN2 GT 回程，而"BGP 多线"里混着超售 300% 的垃圾母鸡。真正决定体验的不是标签，而是四个硬指标：**去程路由、回程路由、峰值时段丢包率、单用户可用带宽**。

这篇文章会从物理层一路讲到协议层，给你一套可以自己动手验证的判定方法论——不靠商家话术，靠 `mtr`、`curl` 和 `tcping` 说话。

## 二、底层物理机理：线路为什么天生不平等

### 2.1 跨境流量的三段式结构

一次从国内到海外服务器的请求，物理上分成三段：**接入段（你 → 本地 ISP）→ 跨境段（国内出口 → 海外入口）→ 落地段（海外入口 → 目标站点）**。

90% 的用户抱怨都出在跨境段，但 90% 的商家宣传都在吹落地段（"原生 IP""解锁 Netflix"）。这是信息不对称的核心。

### 2.2 直连：最省钱，也最看天吃饭

直连就是你的流量走中国电信 163（AS4134）、联通 169（AS4837）或移动 CMI（AS58453）这类公众骨干网出境。它的特点是：

- **成本极低**，商家一台海外 VPS 就能开卖；
- **路由完全不可控**，晚高峰（20:00–24:00）骨干网拥塞时，丢包率能从 0% 飙到 40%；
- **QoS 优先级最低**，遇到 DDoS 清洗或出口限速，你的 TCP 会被直接丢包。

直连不是不能用，而是**不能承诺稳定性**。它的延迟曲线像心电图，白天 60ms，晚上 300ms。

### 2.3 中转：用国内中转机"接驳"跨境段

中转的本质是：你 → 国内中转服务器（电信/联通/移动多线接入）→ 海外落地机。中转机的价值在于它通常接入 **BGP 多线机房**，能根据你的运营商自动选最优出口，避免单一骨干网塞死。

中转的问题在于**两段跳**：中转机自身如果超售，你会同时吃两头的亏。而且中转机到落地的这一跳如果走的是公网，那前面省下的钱又还回去了。

### 2.4 BGP 多线与"伪 BGP"

真 BGP 多线意味着机房同时宣告电信、联通、移动、教育网等多个 AS，用户接入时由 BGP 选路决定。伪 BGP 则是"一台机器挂多个 IP，靠 DNS 分线路由"——体验差距在跨网访问时尤其明显。

判断方法：用 `mtr` 看第 3–5 跳的 AS 号。如果只有单一 AS 且属于某家小运营商，那基本是伪 BGP。

### 2.5 CN2 GT vs CN2 GIA：一字之差，天壤之别

| 类型 | AS 号 | 去程 | 回程 | 峰值丢包 |
|---|---|---|---|---|
| CN2 GT | AS4809 | 部分走 163 | 常回 163 | 5%–20% |
| CN2 GIA | AS4809 | 全程 CN2 | 全程 CN2 | 通常 `< 1%` |

CN2 GIA 是电信的精品网产品，带宽资源稀缺、单价高，所以**真正的 GIA 机场定价不会便宜**。市面上大量"CN2"其实是 GT，甚至有商家把 163 直连包装成 CN2。

### 2.6 IEPL / IPLC：物理层的降维打击

- **IPLC（International Private Leased Circuit）**：点对点国际专线，物理隔离，不经过公网出口，理论上是跨境链路的天花板。
- **IEPL（International Ethernet Private Line）**：基于以太网的国际专线，成本略低于 IPLC，同样不走公网。

两者的共同点是：**不经过 GFW 的公共出口，因此不受晚高峰骨干网拥塞影响**。代价是价格——一条 100Mbps 的 IPLC 月费常在数千到上万元，所以机场通常采用"多人共享 + 倍率控制"的模式。

这也是为什么大多数标注"IEPL/IPLC"的机场会设置 `x2`、`x3` 甚至 `x5` 倍率。**全节点 x1 无倍率的专线机场，本质是在用利润换口碑**，非常少见。

### 2.7 协议层：BBRv3 与 TLS Reality

线路是"路"，协议是"车"。同一段烂路上，好的拥塞控制算法能显著改善体验：

- **BBRv1/Bbrv2**：Google 的拥塞控制，抗丢包能力强，能把 5% 丢包下的吞吐提升数倍，但存在与 Cubic 流抢带宽的公平性问题；
- **BBRv3**：2023 年后逐步落地，改进了丢包探测逻辑，在跨境高丢包场景下更稳；
- **TLS Reality / Vision**：TLS 层的指纹伪装方案，让代理流量在 DPI 看来就是一个正常的 HTTPS 握手，抗封锁能力显著优于早期的 VMess 明文特征。

注意：**协议再好也救不回被物理限速的线路**。如果你在晚高峰只有 200KB/s，先怀疑线路，再怀疑协议。

## 四、天梯图：线路等级 T0–T4 分层

**T0 · IPLC / IEPL 专线**
物理隔离跨境段，晚高峰几乎无衰减，是当前技术与体验的双重天花板。缺点只有一个：贵，且容易被商家用"半程专线"（只买海外段）糊弄。

**T1 · CN2 GIA 全程精品网**
电信 CN2 GIA 全程走 AS4809，回程不落 163，延迟稳定、丢包极低。是中高端机场的主力配置。

**T2 · 优质 BGP 多线中转**
国内多线 BGP 中转 + 优质海外落地。性价比区间，选对商家体验接近 T1。

**T3 · 普通 BGP 直连 / CN2 GT**
能用，晚高峰会掉速。适合预算有限或作为备用线路。

**T4 · 163 骨干直连 / 廉价共享**
白天跑满，晚上拉胯。适合非实时场景（备份、下载）。

## 五、按人群与场景选型

- **重度 AI 用户（ChatGPT / Claude / Gemini 高频）**：优先 T0/T1，且必须确认落地是**原生住宅或优质机房 IP**。TLS 指纹与 IP 信誉度比线路速度更影响可用性。
- **4K 流媒体党**：T1 起步，重点看落地段的解锁能力和带宽冗余，单节点建议 `2Gbps` 以上。
- **远程办公 / 视频会议**：对丢包最敏感，丢包 3% 就会导致画面卡顿。T0/T1 是唯一稳妥选择。
- **游戏加速**：看的是延迟抖动（jitter）而非平均延迟。IEPL 的 jitter 通常在 `±3ms`，公网线路常达 `±30ms`。
- **预算敏感 / 轻度使用**：T2 中转足够，把钱花在"节点数量"上是低效的。
- **备用冗余**：建议 T3 直连 + T1 主力双持，避免单一商家故障时全盘瘫痪。

## 六、分客户端实操配置与深度避坑

### 6.1 Windows：Clash Verge Rev / v2rayN

关键配置项：

- `tun` 模式配合 `stack: gvisor` 能显著降低大流量下的 CPU 占用；
- `sniffer` 开启后可正确还原被 SNI 分流的域名，避免误判；
- 分组策略建议：`自动测速（url-test）` 用于日常，`手动选择` 用于流媒体切换。

**避坑**：不要开"全局模式 + 系统代理"叠加，会造成 DNS 泄漏与路由环路。DNS 建议用 `fake-ip` 模式并配置 `nameserver-policy`。

### 6.2 macOS：ClashX Meta / Surge

Surge 的 `Smart Policy` 与 Clash 的 `fallback` 思路不同：前者基于历史延迟动态调整，后者只在节点失活时切换。跨境链路抖动大，**Surge 的动态策略在晚高峰体验更好**。

### 6.3 iOS：Shadowrocket / Stash

iOS 端最大的坑是**后台自动切换导致的重连风暴**。建议关闭"按需连接"中的低电量触发，并把 `url-test` 间隔设为 `300s` 以上。

### 6.4 Android：Clash Meta for Android / v2rayNG

Android 的 Doze 模式会杀死后台代理，需在电池优化白名单中排除客户端。另外部分国产 ROM 会拦截 VPNService，务必在"后台弹出界面"和"自启动"中放行。

### 6.5 路由器：OpenWrt + PassWall

路由级代理的核心是**分流规则**。国内直连走 `chinalist`，国外走代理，避免全流量走代理造成出口带宽瓶颈。同时注意 `fullcone NAT` 对 P2P 与部分游戏的必要性。

## 七、抓包排障诊断手册

### 7.1 三件套命令

**① 路由与丢包定位（推荐首选）**

```bash
mtr -rwzc 100 -T -P 443 your-node-domain.com
```

- `-T -P 443` 用 TCP 443 探测，避免 ICMP 被限速导致误判；
- `-c 100` 采样 100 次，一次性看清每一跳的 `Loss%` 与 `StDev`；
- **判定原则**：中间某跳丢包但后续跳不丢，说明该路由器只是 ICMP 限速，无需担心；若**最后一跳持续丢包**，才是真实丢包。

**② 分段延迟测量**

```bash
tcping -t -p 443 your-node-domain.com 20
```

对比 `tcping` 到"入口节点"和"落地节点"的差异，可以判断问题出在跨境段还是落地段。

**③ TLS 握手与协议验证**

```bash
curl -o /dev/null -s -w "dns:%{time_namelookup} conn:%{time_connect} tls:%{time_appconnect} ttfb:%{time_starttransfer} total:%{time_total}\n" https://www.google.com
```

### 7.2 判定速查表

| 现象 | 最可能原因 | 验证方法 | 处置 |
|---|---|---|---|
| 白天正常，晚 8 点后掉速 | 骨干网拥塞 / 线路等级低 | 22:00 跑 `mtr` | 换 T1 以上线路 |
| 延迟正常但吞吐低 | 单节点超售 / 限速 | 多时段 `curl` 下载测速 | 换节点或换商家 |
| TCP 连不上但 ping 通 | 端口被墙 / SNI 阻断 | 换端口或域名重试 | 更新订阅、启用 Reality |
| 全部节点同时挂 | 商家侧故障 / 被封 IP | 官方频道确认 | 等待或启用备用 |
| 特定网站打不开 | DNS 污染 / 分流规则错误 | `dig` 查解析结果 | 更换 DNS、修正规则 |
| 视频能开但一直缓冲 | 落地带宽不足 | 单线程测速 | 选高带宽节点 |
| 频繁断流重连 | 客户端 mux 或 UDP 问题 | 关闭 mux 重测 | 换传输协议 |

## 九、常见问题排障 FAQ

**Q1：为什么我买的"专线机场"晚高峰还是会卡？**
先确认是"全程专线"还是"半程专线"。另外，专线解决的是跨境段拥塞，如果落地机房超售，同样会卡。用 `tcping` 分别测入口和落地即可定位。

**Q2：延迟 200ms 是不是就不能用了？**
不一定。延迟影响的是"感知响应速度"，`200ms` 对网页浏览几乎无感，但丢包 5% 会让 TCP 重传，体感比 `400ms` 还糟。**丢包比延迟更重要**。

**Q3：CN2 GIA 一定比 IEPL 差吗？**
不一定。GIA 是公网中的精品网，IPLC 是物理专网，理论上 IPLC 更稳，但劣质 IPLC（共享过度）体验可能不如优质 GIA。**实测 > 标签**。

**Q4：节点越多越好吗？**
不是。100 个节点里如果 80 个是同一机房同一 AS，那实际冗余度只有 1。看的是**落地多样性**，不是数量。

**Q5：为什么换了协议还是一样卡？**
协议优化的是抗干扰与伪装能力，不解决物理带宽问题。如果瓶颈在骨干网，换协议无异于换轮胎救发动机。

**Q6：TLS Reality 真的能防封锁吗？**
Reality 通过借用真实站点的证书握手来伪装，抗主动探测能力优于自签证书方案。但没有任何方案是"永久防封"，仍需依赖商家的 IP 轮换能力。

**Q7：如何判断机场是否超售严重？**
同一节点在晚高峰用 `curl` 跑 10 线程下载，观察单线程速度是否剧烈波动。若 10 线程总和远小于标称带宽，基本可判定超售。
