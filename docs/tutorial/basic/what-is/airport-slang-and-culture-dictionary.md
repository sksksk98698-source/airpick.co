# 机场生态全景行话大辞典：一条龙搞懂测速图、审计规则与水友群日常

## 一、TL;DR：先给结论，再讲道理

如果你只看一段话，请记住这三条：

1. **行话不是黑话，是压缩包。** 机场圈几乎每个词都在编码一个技术事实或商业事实。"CN2 GIA 三���回程" 背后是自治系统路由策略，"倍率 0.5x" 背后是计费口径，"落地原生 IP" 背后是 IP 归属与流媒体风控。听不懂行话，本质是看不懂技术与账本。

2. **测速图是营销素材，不是性能证明。** 一张漂亮的多线程测速图，可以只靠"就近测试节点 + 单时段采样 + 只跑下载"三招堆出来。真正决定体验的是晚高峰（20:00–23:00）的单线程首字节延迟与丢包率。

3. **审计规则与 TOS 是你和机场主之间唯一有约束力的合同。** 出事时能救你的不是群里那句"机场主说可以"，而是 TOS 里那段白纸黑字。**不看 TOS 就付款，等于签空白合同。**

下面按"技术行话 → 测速图 → 计费与合规 → 选型 → 排障"的顺序，把整套词汇表拆开讲。

## 二、这门"行话体系"是怎么长出来的

机场生态有三类人：**机场主（供给）**、**上车党（需求）**、**评测者（信息中介）**。三方之间存在天然的信息不对称：

- 供给端要隐藏真实架构（线路、带宽、落地 IP），否则容易被攻击或被同行抄底；
- 需求端想知道"到底值不值"，但没有能力做端到端验证；
- 评测端要生产可传播的结论，于是发明了大量**压缩率极高的黑话**。

再加上关键词敏感性，行话还承担了**规避审查与降低沟通成���**的双重职能。于是"拉鸡"、"落地"、"下车"、"毒药图"这类词就成了圈内通用语。

理解这一点很关键：**行话的密度越高，说明该领域的信息不对称越严重。** 这也是为什么机场圈是"测评文比技术文更好卖"的典型市场。

## 三、底层技术行话拆解

### 3.1 线路层级：直连 / 中转 / 专线

| 行话 | 技术含义 | 典型表现 |
| --- | --- | --- |
| 直连 | 用户侧直接连境外落地机，走公网国际出口 | 便宜、晚高峰抖动大 |
| 中转 | 国内入口机 → 内网/公网衔接 → 境外落地机 | 降低入口暴露，路径可控 |
| IEPL / IPLC 专线 | 跨境以太网专线 / 国际私有租用电路，二层专线不经过公网路由 | 延迟稳定、丢包低、成本极高 |
| 隧道 | 中转机之间用 GRE / WireGuard / IPIP 打通 | 成本低于专线，质量介于两者之间 |

一句话记忆：**专线买的是"不排队"，中转买的是"抄近路"，直连买的是"便宜"。**

### 3.2 三网与回程：CN2 GIA / 9929 / 4837 / CMI / CMIN2

这些数字都是**自治系统号（ASN）**：

- **CN2 GIA（AS4809）**：电信最贵的企业级承载网，晚高峰抗拥塞能力强；
- **CN2 GT（AS4809 的普通版）**：比 163 好，比 GIA 差；
- **163 骨干（AS4134）**：最便宜，晚高峰最堵；
- **联通 9929（AS9929）**：联��精品网；
- **联通 4837（AS4837）**：联通普通国际线路，量大管饱；
- **移动 CMI（AS58453）** / **CMIN2**：移动国际出口，CMIN2 是较新的优化方向。

"三网回程优化" 意味着电信走 4809、联通走 9929、移动走 CMI 分别最优，而不是一条线路三网通吃。**只写"三网优化"不写具体 ASN 的宣传，默认按普通线路估值。**

### 3.3 协议栈行话

- **SS / SSR**：老牌轻量代理，SSR 已基本淘汰；
- **VMess / VLESS**：V2Ray 系，VLESS 更轻；
- **Trojan**：伪装成 HTTPS，兼容性好；
- **Reality（XTLS）**：当前抗主动探测能力较强的一档，无需自备域名与证书；
- **Hysteria2 / TUIC**：基于 QUIC，弱网抗丢包能力强，但对 UDP 质量敏感，部分网络会被 QoS 限速；
- **Snell**：Surge 生态专用。

### 3.4 调度与质量行话

**BGP** 决定多线入口的选路；**QoS** 是运营商对特定流量（尤其 UDP）的限速与降级；**BBRv3** 是拥塞控制算法，能显著改善高丢包链路吞吐，但**不能降低物理延迟**；**双 ISP** 指落地同时接入两家运营商，用于分散单点故障与被封风险。

## 四、毒药测速图：六种幻觉与识破方法

"毒药测速图"指的是**看起来很美、但无法反映真实使用体验**的测速截图。常见六种手法：

| 手法 | 原理 | 识破方法 |
| --- | --- | --- |
| 多线程刷分 | 16/32 线程并发聚合带宽，单线程可能只有几分之一 | 要求提供**单线程**结果 |
| 就近节点 | Speedtest 选测试服务器时挑同城/同运营商 | 看测试服务器名称与 ISP |
| 挑时段 | 只在凌晨或上午跑，避开晚高峰 | 要求 20:00–23:00 数据 |
| 只测下载 | 上传与双向延迟被隐藏 | 看是否含 upload 与 ping |
| 缓存命中 | 测试目标走 CDN，回源根本没出境 | 换非 CDN 源（如自建 iperf3）复测 |
| 只跑最优节点 | 从几十个节点里挑一个最好的 | 看是否给出**全节点**分位数据 |

一个可复现的判据：**晚高峰单线程下载能跑到标称带宽的 60% 以上，且丢包 `< 1%`，才算及格。** 低于这个水位，多漂亮的图都不必当真。

## 五、计费与合规行话：倍率、超售、审计规则与 TOS

### 5.1 计费类

- **倍率**：使用该节点时流量按倍数扣减。0.5x 表示用 1GB 只扣 0.5GB，2x 表示翻倍扣；
- **流量重置**：分自然月重置、购买日重置、一次性（不重置）三种，购前务必确认；
- **限速**：常见为单账户限速、单端口限速、单线程限速，写法差异极大；
- **超售比**：售出带宽 / 实际带宽。行业常见 1:5 至 1:20，超过 1:30 基本可判为"晚高峰必然崩"。

### 5.2 审计规则是什么

**审计规则（Audit Rule）是机场在服务端对用户可访问目标施加的黑名单/白名单策略**，通常作用于域名、IP 段与端口三个维度：

- **端口类**：封禁 25（垃圾邮件）、6881–6889（BT）、常见 P2P 端口；
- **域名/IP 类**：封禁 BT Tracker、挖矿池、部分高风险站点；
- **行为类**：限制并发连接数、限制单日流量峰值、识别扫描行为。

触发审计的后果通常是：**限速 → 断连 → 临时封禁 → 清退且不退款**。注意，审计规则一般**不会在客户端可见**，你只有在被限速或断连时才会感知到。

### 5.3 TOS 服务条款

TOS（Terms of Service）里真正值得逐字读的只有四块：

1. **禁止事项清单**（对应审计规则）；
2. **退款政策**（是否支持、时限、扣费方式）；
3. **账号共享条款**（设备数上限、IP 数上限）；
4. **责任限制**（数据留存、服务中断免责）。

**避坑提示：** 群里"机场主口头承诺"不具备任何效力。所有结论以官网 TOS 页面与公告留档为准。

## 七、细分人群与场景选型

- **轻度用户（网页 + 社交 + 学术搜索）**：优先选**低倍率、低门槛**的专线小套餐，不必为"大带宽"付费。
- **远程办公 / 视频会议**：优先**稳定性与丢包**，而非峰值带宽，专线档是刚需。
- **流媒体与风控场景**：优先**家宽落地 / 原生 IP**，机房 IP 被流媒体标记的概率显著更高。
- **游戏加速**：优先**UDP 友好 + 低抖动**，注意部分网络对 QUIC 有 QoS。
- **多设备 / 家庭���享**：先确认 TOS 的设备数与并发 IP 上限，再谈套餐大小。

## 八、分客户端实操配置与深度避坑

**通用原则：先解决 DNS，再谈速度。** 90% 的"能连但打不开"问题根源在 DNS 泄露或解析污染。

- **Clash / Mihomo / Clash Verge**：确认 `dns.enable: true`，优先使用 `fake-ip` 模式；分流规则建议启用 `rule-set` 而非全量 GeoIP，减少内存占用与误判。切勿同时开启系统代理与 TUN 模式的两套 DNS。
- **sing-box**：注意 `route.rules` 优先级顺序，`sniff` 需开启否则域名分流失效。
- **Shadowrocket / Stash / Quantumult X**：iOS 端重点是"按需连接"与"绕过大陆"策略的取舍，避免后台频繁掉线重连导致的电量消耗。
- **Surge / OpenWrt 软路由**：软路由场景先做 `tcpdump` 抓包确认流量确实走了代理，再排查客户端配置。

**高频坑位：**

1. 用订阅转换服务时，第三方可能记录你的订阅链接 → 优先自建 Sub-Store；
2. UA 识别错误的客户端会被下发错误配置 → 手动指定 UA；
3. 多客户端同时挂同一订阅，触发并发审计被限速；
4. 把测速节点当作日常节点，导致倍率流量被快速耗尽。

## 九、抓包排障诊断手册

### 9.1 常用命令

```bash
# 1. 三网路径与丢包（Linux / macOS）
mtr -rwzc 50 1.1.1.1

# 2. 分段延迟拆解：DNS / TCP / TLS / 首字节
curl -o /dev/null -s -w "dns=%{time_namelookup}s tcp=%{time_connect}s tls=%{time_appconnect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n" https://www.google.com

# 3. TCP 层连通性与抖动（需安装 tcping）
tcping -c 20 -i 0.5 8.8.8.8 443

# 4. 路由跳数与 ASN 归属
traceroute -n -w 1 -q 1 1.1.1.1

# 5. TLS 握手证书与协议版本
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null | openssl x509 -noout -dates

# 6. 端到端吞吐（需对端 iperf3 服务）
iperf3 -c <peer> -t 30 -P 1   # 单线程
iperf3 -c <peer> -t 30 -P 16  # 多线程对比
```

Windows 对应命令：`tracert -d`、`Test-NetConnection -ComputerName x -Port 443 -InformationLevel Detailed`。

### 9.2 判定表

| 观察现象 | 最可能原因 | 处理方向 |
| --- | --- | --- |
| dns 耗时高，tcp 正常 | DNS 污染 / 上游解析慢 | 换 DoH / 开 fake-ip |
| tcp 握手 > 300ms，tls 正常 | 跨境链路拥塞 | 换节点或换线路 |
| tls 握手慢、tcp 正常 | 目标站风控或证书链问题 | 换落地 IP |
| ttfb 高、total 正常 | 服务端慢，与代理无关 | 排除代理问题 |
| ping 低但丢包高 | 链路拥塞或 QoS | 优先看丢包，不看延迟 |
| 单线程慢、多线程正常 | 单线程限速 | 查 TOS 限速条款 |

**核心判据：延迟决定"手感"，丢包决定"能不能用"，带宽决定"多久下完"。排障顺序永远是：丢包 → 延迟 → 带宽。**

### 10.2 FAQ

**Q1：审计规则会不会误伤正常使用？**
会。常见误伤场景包括：开 BT 同步、使用 P2P 下载工具、访问被误判的域名。遇到限速先自查端口与并发连接数。

**Q2：倍率是越高越好吗？**
不是。倍率描述的是扣费口径，与质量无必然关系。同价位下，低倍率通常意味着你买的是"流量"而非"线路等级"。

**Q3：为什么测速很快但网页很卡？**
多为单线程能力差或丢包高，典型特征是"多线程刷分高、ttfb 波动大"。用第 9 节的命令复测即可定位。

**Q4：年付一定更划算吗？**
只有在你已跑满一个计费周期、确认稳定性之后才成立。新站年付是典型高风险行为。

**Q5：水友群里的"下车"是什么意思？**
指退出某个机场、停止续费。群里"下车"密集出现时，通常意味着该机场近期出现了稳定性或合规问题，值得警惕。

**Q6：订阅链接泄露了怎么办？**
立即在面板重置订阅地址，并检查是否有异常设备/IP 消耗流量的记录。

**Q7：怎么判断一个机场是否超售严重？**
看晚高峰单线程下行占标称带宽的比例，连续多日低于 40%，基本可判为超售。
