# 科学上网核心术语权威大字典：零基础看懂节点参数与选线指标

## 一、TL;DR：先记住这六条，你已经超过 80% 的用户

如果你只想知道结论，直接看这里：

1. **节点列表里 90% 的形容词是营销语言，真正决定体验的只有五个硬指标**：线路拓扑（直连/中转/专线）、峰值带宽、丢包率、并发连接数、计费倍率。
2. **Ping 值不等于速度**。Ping 只反映 RTT（往返时延）的物理下限，吞吐量取决于带宽、拥塞窗口和丢包。`12ms` 的窄管道可能比 `120ms` 的宽管道慢十倍。
3. **丢包率是隐形杀手**。连续 1% 的丢包会让 BBR 之外的拥塞控制算法吞吐断崖式下跌，视频会议直接卡成 PPT；`0.1%` 以下才算"可用"。
4. **倍率是计费权重，不是速度权重**。`0.1x` 倍率的节点通常意味着更拥挤的共享出口，倍率低不等于快。
5. **专线（IPLC/IEPL）买的是"确定性"**，不是"绝对速度"。它的价值在于绕开国际出口拥塞与 QoS 限速。
6. **新手选线顺序**：先看月流量需求 → 再看倍率与价格 → 最后看地区与协议，不要被"解锁全流媒体"绑架决策。

下面把这六句话背后的东西拆开讲透。

## 二、底层物理机理：你的一个请求到底走了哪几跳

理解术语的前提，是理解路径。你在浏览器里敲下回车，数据包大致会经过：

**本机 → 家庭路由器 → 本地 ISP 城域网 → 国际出口（GFW 检测点）→ 海外中转入口 → 落地服务器 → 目标站点**

每一跳都有专属术语，逐层解释：

### AS 与 BGP

**AS（Autonomous System，自治系统）** 是互联网的行政单位，每个 AS 有一个 **ASN 编号**。运营商之间通过 **BGP（边界网关协议）** 交换路由——本质上是"我这里能到哪些网段"的互相喊话。BGP 的选路不只看跳数，还看商业关系（客户/对等/上游）和本地策略，所以"绕路"是常态。

**Anycast（任播）** 是同一个 IP 在多地同时广播，用户被路由到最近的一台。Cloudflare 的 `1.1.1.1` 就是典型 Anycast，这也是它延迟低的原因。

### 国际出口与 QoS

中国大陆访问境外，必须经过三大运营商的国际出口。晚高峰（20:00–24:00）出口带宽被挤满，就会出现**拥塞丢包**。更麻烦的是 **QoS（服务质量策略）**：运营商可能对特定协议做差异化限速，其中对 UDP 的处理往往最粗暴。

这解释了一个常见现象：白天 `50Mbps`，晚上 `2Mbps`。不是你买的套餐缩水，是出口在晚高峰塌了。

### 直连、中转与专线

- **直连**：落地服务器直接连国际出口。便宜，但完全暴露在出口拥塞下。常见优质直连线路包括 **CN2 GIA**（电信高端国际线路）、**CMI**（移动国际）、**CUII/9929**（联通国际）、**4837**（联通普通国际）。
- **中转**：入口在国内或近岸（如香港、日本），落地在远端（如美西）。入口到落地走内网或优质互联，用户只需连入口。**中转的质量取决于中转段是否拥堵**。
- **专线：IPLC（International Private Leased Circuit，国际私有租用电路）** 与 **IEPL（International Ethernet Private Line，国际以太网专线）**。两者都是运营商级点对点链路，**不经过公网 BGP 选路，也不经过 GFW 的公网检测点**，因此不受国际出口拥塞��响，延迟与丢包都极其稳定。IEPL 是更现代的以太网封装，通常按带宽包月计价，成本高昂——这也是专线机场普遍更贵的原因。

### 拥塞控制：CUBIC 与 BBR

**CUBIC** 是 Linux 默认算法，靠丢包判断拥塞，一旦丢包就大幅降窗。**BBR（Bottleneck Bandwidth and Round-trip propagation time）** 由 Google 提出，通过测量瓶颈带宽和最小 RTT 建模，对随机丢包不敏感。**BBRv3** 是目前较新版本，进一步优化了公平性与收敛速度。

一句话结论：**高丢包链路上，BBR 系算法的吞吐可能是 CUBIC 的 5–10 倍**。所以机场服务端的拥塞控制算法，比节点名字重要得多。

### 协议层术语速查

| 术语 | 通俗解释 |
| --- | --- |
| Shadowsocks / SS | 轻量加密代理协议，AEAD 加密，性能好但特征较明显 |
| VMess / VLESS | V2Ray 系协议，VLESS 去掉了 VMess 的加密层，更轻 |
| Trojan | 伪装成标准 TLS 流量，抗主动探测能力强 |
| TLS Reality | 无需自购域名证书，直接"借用"真实大站 TLS 握手特征，伪装度极高 |
| Hysteria2 | 基于 QUIC/UDP，弱网高丢包环境下吞吐极强，但吃 UDP QoS |
| TUIC | 同样基于 QUIC，多路复用与 0-RTT 表现好 |
| AnyTLS | 新一代 TLS 伪装方案，注重连接池与会话复用 |
| 双 ISP | 指 IP 的归属信息同时指向两家运营商，风控场景下"看起来更干净"，仅说明属性 |

请务必在服务商条款与当地法律允许的范围内使用上述技术。

## 三、拆解一行节点配置：字段级解释

典型的一行节点长这样：

`🇭🇰 香港 01 | IEPL 专线 | 1x | 流媒体解锁 | 无审计 | 500Mbps`

逐字段拆：

- **🇭🇰 香港**：落地机房所在地区。注意区分"入口地区"和"落地地区"——很多节点的入口在香港，落地在新加坡。
- **01**：同地区节点序号。序号越小不代表越快，只是编号。
- **IEPL 专线**：线路类型，含金量最高的字段。
- **1x**：**计费倍率**。跑 1GB 流量扣 1GB 套餐额度。`0.5x` 表示扣一半，`3x` 表示扣三倍。
- **流媒体解锁**：声称能访问流媒体区域库。需实测验证，见第八节。
- **无审计**：不记录访问日志。属于承诺性描述，无法技术验证。
- **500Mbps**：宣称峰值带宽，通常指共享出口的理论上限。

**新手最容易踩的坑：把倍率当成质量分。** 倍率高的节点通常是高成本线路（专线），确实更好；但倍率低的节点也可能只是被塞满了用户。两者的相关性远没有想象中强。

## 五、按人群与场景选型：对号入座

**轻度用户（月流量 50GB 以内）**：网页、社交媒体、学术搜索为主，对延迟不敏感但对稳定性有要求。优先选**低倍率 + IEPL 小流量套餐**，因为低流量用户最怕的是"晚会话无法用"，而不是带宽不够。

**中度用户（50–200GB）**：YouTube 1080P、GitHub 拉代码、远程办公。建议选择 **1x 倍率的 CN2 GIA 或优质中转**，预算允许时上专线。

**重度用户（200GB 以上）**：4K 流媒体、大文件同步、多设备。必须看**峰值带宽与并发连接数**，倍率反而是次要因素——你已经被套餐规模绑定。

**实时通信刚需（视频会议、跨境直播、游戏）**：**只能选 IEPL/IPLC**。丢包率超过 0.5% 的链路，视频会议体验是无法接受的。

**学术与开发者**：关注 IP 纯净度与端口稳定性，优先支持 `git clone`、`pip`、`docker pull` 不中断的节点。

## 六、分客户端实操配置与深度避坑

### Clash / Mihomo 系（Windows / macOS / Android）

核心是**分流规则**。把国内域名、GeoIP 走 `DIRECT`，其余走 `PROXY`。常见问题：

- **Fake-IP 与真实 IP 冲突**：开启 Fake-IP 后，`ping` 得到的 `198.18.x.x` 是虚拟地址，不具参考意义。测延迟请用 `tcping` 目标真实域名端口。
- **TUN 模式**：能接管所有流量，但会增加 CPU 占用。桌面端建议开启，移动端按需。
- **DNS 泄漏**：务必禁用系统 DNS，把 DNS 查询交给代理内核，否则你的访问域名会暴露给本地解析器。

### sing-box / Shadowrocket / Surge

- **sing-box**：配置文件语法严格，缩进错一格直接启动失败。建议用 `sing-box check` 校验。
- **Shadowrocket**：iOS 上注意"全局路由"与"配置"的区别，很多人误开全局导致国内 App 也被代理。
- **Surge**：规则集性能好，但策略组嵌套不宜超过三层，否则匹配开销明显。

### 通用避坑清单

1. 不要用代理跑 P2P 下载，绝大多数机场明确禁止，且极易触发限速��
2. 不要在高峰期做大文件同步，那是用自己的体验换别人不骂你。
3. 不要频繁切换节点，TLS 握手与会话建立也有成本。
4. 订阅链接不要外泄，等于把你的额度交给陌生人。

## 七、抓包排障诊断手册：六条命令定位一切问题

排障的核心是**分层定位**：先确认本地网络，再确认到入口的链路，最后确认入口到落地。

**第一层：确认本地是否正常**

```bash
ping -c 20 223.5.5.5
```

丢包或延迟异常，说明你家宽/手机网络本身有问题，与机场无关。

**第二层：测试到节点入口的 TCP 握手**

```bash
tcping -t 20 hk01.example.com 443
```

或使用 `nc -vz hk01.example.com 443`。关注**握手成功率和握手耗时稳定性**。

**第三层：逐跳定位丢包发生在哪一段**

```bash
mtr -rwzc 100 目标IP
```

`mtr` 是排障的核武器。判定规则：

| 现象 | 判定 |
| --- | --- |
| 前 3 跳就丢包 | 本地网络或路由问题 |
| 中间某跳丢包，但后续跳正常 | 该路由器 ICMP 限速，属正常，可忽略 |
| 从某跳开始持续丢包直到终点 | 该段链路确实拥塞 |
| 全程无丢包但延迟抖动大 | 路由抖动，可能是 BGP 震荡 |

**第四层：测真实吞吐与首字节时间**

```bash
curl -o /dev/null -s -w "connect:%{time_connect} ttfb:%{time_starttransfer} speed:%{speed_download}\n" https://speed.example.com/1MB.bin
```

`time_connect` 反映 TCP 握手延迟，`time_starttransfer` 反映 TTFB，`speed_download` 反映实际吞吐。三者对照，能区分"延迟高"和"带宽小"。

**第五层：确认 DNS 解析路径**

```bash
dig +short example.com @1.1.1.1
```

如果代理环境下解析结果异常，说明 DNS 走了泄漏通道。

**第六层：确认 UDP 是否通畅（QUIC 系协议必需）**

用 `nslookup -type=TXT` 走 UDP 53 端口测试，或在客户端日志里观察 QUIC 握手是否超时。UDP 被 QoS 限速时，Hysteria2 的表现会反而比 TCP 系协议差。

## 八、行业避坑矩阵：识别虚假宣传

| 宣传话术 | 真相 | 验证方法 |
| --- | --- | --- |
| "1000Mbps 独享带宽" | 几乎一定是共享出口的理论上限 | 连续三日高峰期实测吞吐 |
| "无限流量" | 通常有公平使用条款，超量限速或断流 | 查阅 ToS 中的 Fair Use 条款 |
| "全线 IPLC 专线" | 常见做法是少数旗舰节点专线，其余中转 | 用 `mtr` 看路径是否经过公网跳 |
| "全流媒体原生解锁" | 解锁是动态的，平台风控一变就掉 | 购买前索要当日实测截图，或选可退款套餐 |
| "0.1x 超低倍率" | 低倍率节点往往超售严重，晚高峰拥挤 | 高峰期实测，观察丢包率 |
| "无审计、绝对安全" | 承诺无法技术验证 | 视为营销话术，不要作为决策依据 |
| "买三年送三年" | 长期预付风险极高，服务商可能跑路 | 优先选择可月付、可退款的 |

**超售（Overselling）的识别**：同一入口 IP 下节点数量异常多、晚间测速曲线呈"断崖"、同一地区不同节点延迟几乎一致——三条中占两条，基本可以判定超售。

**伪解锁的识别**：声称解锁流媒体但实际使用的是公共 DNS 重定向，表现为"能打开首页，点进具体内容提示不可用"。真正的解锁需要落地 IP 本身在该区域库内。

## 九、常见问题排障 FAQ

**Q1：Ping 很低，但网页就是打不开，为什么？**

典型是 TCP 握手能过但数据传输被丢包拖垮，或 MTU 不匹配导致大包被丢弃。用 `mtr` 看是否中段丢包，用 `curl` 测实际 TTFB。也可能是 DNS 污染，换加密 DNS 试试。

**Q2：为什么晚高峰速度暴跌？**

国际出口拥塞 + 运营商 QoS 限速。这不是机场能完全解决的问题，只能靠专线绕开。参见 [/tech/](/tech/) 中的线路原理解析。

**Q3：倍率 0.5x 的节点比 1x 的快，是不是说明倍率没用？**

不矛盾。倍率只反映计费权重。某个 `0.5x` 节点如果恰好用户少，自然快；而某个 `1x` 专线节点如果被塞满，也���慢。**倍率要看，但不能单看。**

**Q4：同一个订阅，手机快电脑慢？**

常见原因：电脑开了 IPv6 导致部分流量绕过代理、DNS 配置不一致、系统代理与 TUN 模式冲突、或安全软件拦截了 UDP。

**Q5：节点显示"超时"但实际能用？**

延迟检测用的通常是 ICMP 或 TCP 短连接，部分节点主动屏蔽探测包。以实际访问结果为准。

**Q6：Hysteria2 节点速度忽高忽低？**

QUIC 对 UDP 丢包敏感且受 QoS 影响。若运营商对 UDP 限速，Hysteria2 反而不如 Trojan 稳定。建议同一地区保留 TCP 与 UDP 两套协议备用。

**Q7：如何判断一个机场是否值得长期续费？**

看三点：连续三个月高峰期丢包曲线是否稳定、客服响应时效、是否有明确退款政策。价格最低的往往不是性价比最高的。
