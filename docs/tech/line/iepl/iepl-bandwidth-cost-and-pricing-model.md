# IEPL 专线单价与运营成本揭秘：为什么一兆带宽每个月要几十块钱

> 本文由 AirPick 实验室基于 2026 年 Q1 华南、华东、香港三地实际采购报价单、12 家中大型机场的成本结构访谈，以及 30 天连续链路探测数据整理而成。所有价格区间均为不含税裸价，单位统一为人民币。

## 一、先给结论：一兆几十块，贵在哪一层？

如果你只在网上买过"机场"，很容易产生一个错觉：带宽应该是白菜价。毕竟家宽千兆一个月才一百多块。但当你真正去问运营商要一条深港 IEPL，报价单上的数字往往是 **每 Mbps 每月 25 到 60 元**——也就是说，一条 200 Mbps 的专线，光月租就是 5000 到 12000 元。

这不是运营商在宰你，而是三层成本在叠加：

1. **跨境段是稀缺资源**。深港之间有物理光缆容量上限，且牌照与结算价由几家持牌运营商控盘，这不是自由市场。
2. **两端都要落地**。香港侧要机柜、电力、本地带宽；内地侧要入口机房、三线 BGP、备案或白名单。
3. **带宽是"预留"不是"共享"**。IEPL 承诺的是 CIR（承诺信息速率），不是 BEST EFFORT。你订了 200 Mbps，运营商就得为你留出 200 Mbps，哪怕你凌晨三点跑零流量。

**TL;DR**：

- IEPL 真正的成本大头是**跨境专线月租**（占 45%–60%）和**两端机房托管**（占 20%–30%）；
- 一兆几十块的定价，本质是"专线月租 ÷ 可售带宽"后的必然结果，而不是营销溢价；
- 判断一个机场是不是真专线，看**晚高峰抖动**比看峰值速度靠谱 10 倍；
- 便宜机场不一定假，但你得接受它在**超售比**和**冗余线路**上省下来的钱。

## 二、底层机理：IEPL 不是"更快的公网"，它是别人的内网

很多人把 IEPL 理解为"优化过的公网线路"，这是最根本的误解。

**IEPL（International Ethernet Private Line）本质是一条二层以太网点对点专线。** 你在深圳机房的交换机上配一个 VLAN，在香港机房的交换机上就能收到，中间经过的是运营商的 MPLS 骨干或裸纤，**完全不进入公网 BGP 路由表**。

这带来三个技术后果：

- **没有 BGP 选路抖动**。公网中转最怕的就是晚高峰国际出口拥塞触发 BGP 路径切换，一走绕路延迟瞬间从 40 ms 飙到 300 ms。IEPL 的点对点是静态配置的，路径不会变。
- **不经过 QoS 优先级竞争**。公网出口普遍对跨境流量做整形和限速，IEPL 是 SLA 承诺的 CIR，运营商要按合同保证。
- **延迟下限由物理距离决定**。光在光纤中的传播速度约为 20 万公里/秒，深圳到香港直线约 30 公里，理论单程延迟 0.15 ms，实际因为走线绕行通常在 3–8 ms 之间。这是物理极限，任何"优化"都突破不了。

对比之下，**IPLC** 是更老一代的 TDM/SDH 专线，带宽粒度以 E1（2 Mbps）为单位递增，线路质量同样顶级但单价更贵，常见于金融行业；**BGP 中转**则是租用香港机房的公网出口带宽，再在国内做转发，本质还是走公网，只是机房侧的出口质量比家宽好；**公网直连隧道**就是普通代理，完全不控路径。

关于 BGP 选路、AS 号与 IX 互联的更多细节，可以参考 [/tech/bgp/](/tech/) 中的专题拆解。

## 三、逐项拆解：一条 200Mbps IEPL 机场的月度账单

我们用一条典型的"深港 IEPL + 香港落地"架构来算一笔真实的账。

| 成本项 | 规格 | 月成本（元） | 备注 |
| --- | --- | --- | --- |
| 跨境专线月租 | 200 Mbps 深港 IEPL | 6,000 – 8,000 | 单价 30–40 元/Mbps |
| 香港侧托管 | 1/4 机柜 + 10A 电力 | 2,000 – 3,000 | 含本地带宽与 IP 基础费 |
| 内地入口 | 深圳三线 BGP 转发 | 1,500 – 3,000 | 含机位与电力 |
| IP 资源 | /29 原生段 | 400 – 700 | 纯净度越高越贵 |
| 面板与授权 | 商业面板 + 订阅 | 200 – 500 | 含 CDN 与备份 |
| 运维人力 | 约 0.3 人份 | 3,000 – 6,000 | 7×24 值班、故障响应 |
| 支付通道 | 3% – 6% 手续费 | 500 – 1,500 | 波动大，易被风控 |
| 冗余线路 | 备用中转/第二专线 | 1,500 – 2,500 | 防单点故障 |
| **合计** | | **约 1.5 万 – 2.4 万** | 不含营销与推广 |

再看收入侧。假设这个机场有 1500 个活跃付费用户，平均客单价 12 元（因为大量用户走年付折扣）：

- 月营收 ≈ **18,000 元**
- 月度净利 ≈ **-3,000 到 +2,000 元**

**这就是为什么"专线机场"必须做到 3000–5000 付费用户才能稳定盈利。** 而绝大多数中小机场其实长期在盈亏平衡线附近挣扎——这也解释了为什么你会看到那么多"运营半年就跑路"的站。

还有一个隐蔽成本：**带宽是阶梯定价的**。50 Mbps 的单价可能是 45 元/Mbps，200 Mbps 谈到 35 元，500 Mbps 才能压到 25 元以下。所以大机场的单价优势是结构性的，小机场根本没有议价权。

## 五、细分人群与场景选型建议

**远程办公 & 跨国会议（Zoom / Teams / Google Meet）**
核心诉求是低抖动而非高峰值。IEPL 深港或沪日线路是首选，会议卡顿几乎都源于抖动而非带宽不足。选型时优先看是否提供"独立线程/独享端口"。

**4K 流媒体重度用户**
Netflix、Disney+ 的码率在 15–25 Mbps，重点是**带宽峰值的持续性**而非延迟。这类用户可以接受 BGP 中转，但要确认落地 IP 是原生而非 DNS 解锁。更多场景化建议见 [/scenario/](/scenario/)。

**AI 工具用户（ChatGPT / Claude / Gemini）**
最重要的是 **IP 纯净度与 IP 归属地**。共享 IP 池最容易触发风控，原生住宅 IP 或独立 IP 段是刚需。这一点上，专线机房的原生段优势明显。

**游戏玩家（外服 / 联机）**
延迟敏感度最高，深港 IEPL 的 3–8 ms 是硬优势，中转线路基本没法比。

**预算有限的轻度用户**
不必强行上 IEPL。年付 100–200 元的 BGP 中转方案，只在晚高峰体验打折，日常够用。

## 六、分客户端实操配置与避坑

**Windows / Clash Verge Rev**
规则模式优先，避免全局代理导致的本地流量绕行。开启 TUN 模式时务必排除内网网段，否则会出现 DNS 泄漏与局域网设备失联。测速时先关闭 IPv6，很多"速度上不去"其实是 IPv6 走了默认路由。

**macOS / sing-box**
sing-box 的 `urltest` 探测间隔建议设为 3 分钟以上，过于频繁的探测本身就会消耗带宽并造成误判切换。

**iOS / Shadowrocket**
开启"绕过中国大陆"时注意不要勾选 `bypass-tun` 里的私有地址段以外的选项，否则会出现部分国内 App 走代理反而更慢。

**路由器 / OpenWrt**
建议用 Xray 而非旧版 SS-libev，内存占用和并发性能差距明显。CPU 弱于 MT7621 的设备不要开 TLS Reality，握手开销会把路由器 CPU 打满。

更多客户端配置细节可查阅 [/tutorial/](/tutorial/) 的保姆级教程。

## 七、抓包排障诊断手册

当你怀疑线路是"伪专线"或正在被限速时，按下面的顺序执行：

```bash
# 1. 连续 100 个包的路由追踪，观察每一跳的丢包与抖动
mtr -rwzc 100 -T -P 443 your-node.example.com

# 2. 分离 DNS / TCP / TLS / TTFB 各阶段耗时
curl -o /dev/null -s -w "DNS:%{time_namelookup} TCP:%{time_connect} TLS:%{time_appconnect} TTFB:%{time_starttransfer} Total:%{time_total}\n" https://your-node.example.com/

# 3. 多线程反向吞吐测试（-R 表示服务端发送）
iperf3 -c your-node.example.com -p 5201 -t 30 -P 8 -R

# 4. 分时段采样，晚高峰 20:00–23:00 每小时跑一次
for h in 20 21 22 23; do date; mtr -rwzc 50 -T -P 443 your-node.example.com | tail -3; sleep 3600; done
```

Windows 用户可用：

```powershell
tcping.exe -t -p 443 your-node.example.com
ping -n 100 your-node.example.com | findstr /C:"平均" /C:"丢失"
```

**判定表：**

| 观测指标 | IEPL 正常区间 | 中转正常区间 | 异常信号 | 可能原因 |
| --- | --- | --- | --- | --- |
| 首包 RTT | 深港 3 – 8 ms | 25 – 60 ms | 突然翻倍并持续 | 路由绕行 / 专线降级 |
| 抖动 jitter | 低于 2 ms | 5 – 30 ms | 持续超过 30 ms | 拥塞或 QoS 限速 |
| 丢包率 | 低于 0.1% | 1% – 5% | 持续超过 5% | 超售 / 线路故障 |
| TLS 握手 | 低于 80 ms | 150 – 400 ms | 超过 1 s | 中间盒干扰 |
| 下行吞吐 | 达标值的 80% 以上 | 达标值的 60% 以上 | 长期低于 30% | 倍率 / 限速 / 超售 |
| 第 2–4 跳变化 | 固定不变 | 随机变化 | 每 10 分钟变一次 | 公网 BGP 抖动 |

如果你的"MTR 显示国内就出了公网"、"第 3 跳出现 202.97 段"、"晚高峰丢包 10% 以上"——那基本可以判定它不是 IEPL，而是中转。排查思路详解见 [/help/](/help/)。

| 宣传话术 | 真实情况 | 识别方法 |
| --- | --- | --- |
| "全节点 IEPL" | 实际只有 1–2 条专线，其余是中转 | 对比不同节点的 RTT 差距，专线节点延迟高度一致 |
