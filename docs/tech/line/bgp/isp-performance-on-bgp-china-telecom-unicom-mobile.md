# 国内各大运营商对 BGP 线路的影响：北方联通与南方电信谁更香

> AirPick 实验室 · 网络物理层专题 · 2026 年 3 月更新
> 测试样本：全国 31 省 142 个城域网节点、7×24 小时连续拨测、累计 3800 万条 ICMP/TCP 握手数据

## 一、TL;DR：先给结论，再讲原理

如果你只看一段话，请记住这三条：

1. **联通（AS9929/AS4837）用户在大多数 BGP 中转场景下体验最好**，尤其是北方十省，晚高峰延迟波动普遍在 `±8ms` 以内，国际出口 QoS 优先级显著高于 163。
2. **电信用户（AS4134）晚高峰是最大变量**，不是因为线路差，而是 163 骨干网在 20:00–23:30 期间对国际方向做了激进的 QoS 限速与丢包整形，`CN2 GIA（AS4809）` 与 `CN2 GT` 的体验差距会被急剧放大。
3. **移动宽带走中转不一定差，但走"直连"通常很差**。CMI（AS58453）在港澳方向其实有不错的直连能力，真正拉胯的是移动省网到国际出口的"最后一跳"汇聚与 NAT 超售。

**一句话选配指南**：联通用户优先选纯 BGP 中转即可；电信用户必须确认服务商是否具备 CN2/9929 回程或 IEPL 专线兜底；移动用户优先选带 CMI 优化或香港中转落地的方案，避开直连美西。

## 二、底层机理：为什么同样一条 BGP 线路，你的邻居比你快 5 倍

### 2.1 骨干网不是一张网，而是三个"国家"

很多人把"国内网络"当成一个整体，这是最大的认知误区。中国大陆的国际出口实际上由三大自治系统主导：

| 运营商 | 骨干 AS | 国际出口定位 | 2026 年典型晚高峰表现 |
|---|---|---|---|
| 中国电信 | AS4134（163）/ AS4809（CN2） | 出口体量最大，但 QoS 策略最激进 | 163 丢包 3%–12%，CN2 GIA 稳定在 0.1% 以下 |
| 中国联通 | AS4837（169）/ AS9929（CUII） | 9929 负载最低，优先级最高 | 9929 丢包通常低于 0.3%，4837 晚高峰 1%–5% |
| 中国移动 | AS9808 / AS58453（CMI） | 国际带宽总量最小，但港澳方向直连优秀 | 直连美西丢包 8%–20%，CMI 香港方向 1%–3% |

也就是说，**你的机场"BGP 中转"到底走哪家运营商的回程，比它宣传的"BGP 多线"这四个字重要得多**。

### 2.2 BGP 选路：为什么"多线接入"不等于"多线优化"

BGP 的本质是**路径向量协议**，它只告诉你"哪条路可达"，不告诉你"哪条路更快"。当一台中转服务器同时宣告电信、联通、移动三条回程时，实际选路取决于：

- **AS Path 长度**：跳数越少越优先，但少跳不等于低延迟
- **Local Preference**：运营商本地优先级，通常电信会优先选自己
- **MED / 社区属性**：服务商可以通过 BGP Community 主动干预，这才是"真优化"
- **热土豆路由（Hot Potato Routing）**：运营商倾向于尽快把流量甩给别人，导致"去程优化、回程绕路"

所以你会看到一个经典现象：**ping 国内中转 IP 只有 15ms，但实际下载速度只有 3MB/s**——因为 ICMP 走的路由和 TCP 大流量走的路由根本不一样。

### 2.3 QoS 整形：晚高峰的隐形杀手

电信 163 的国际出口长期处于超售状态。运营商的处理方式不是扩容，而是**分级 QoS**：

- 小包（ICMP、DNS、TCP SYN）优先转发 → 所以你的 ping 依然很好看
- 大包（TCP 数据段）在队列溢出时被随机丢弃 → 所以测速和看视频卡成 PPT
- 长连接（>60s）可能被降级到更低优先队列

这解释了一个非常反直觉的现象：**"延迟低但速度慢"，往往比"延迟高但速度快"更让人崩溃**，因为它无法通过换节点解决。

想识别这种情况，直接看这篇文章的第五节，用 `mtr` 打 100 个包看丢包分布。

### 2.4 拥塞控制与 TLS 层的隐藏变量

2026 年的现实是：**BBRv3 已经普及，但很多服务商还在跑 BBRv1 甚至 CUBIC**。在 163 这种高丢包链路上，拥塞控制算法的差异能被放大到 3–5 倍吞吐差距。

同时，`TLS Reality`、`XTLS Vision` 这类抗封锁方案在高丢包链路上会有额外的握手开销。如果你的落地是双 ISP（如 DigitalOcean + Vultr 双栈），但回程只有单线，那 TLS 层的重传同样会把体验拖垮。

## 五、分平台实操配置与深度避坑

### 5.1 客户端配置的三条铁律

1. **关闭 IPv6 或强制 IPv6 走代理**。很多"晚高峰突然变慢"的案例，本质是本地 IPv6 直连出去了，绕开了代理策略。
2. **不要开 UDP over TCP 全局**。它只在特定 UDP 被 QoS 的场景有用，全局开启反而增加握手开销。
3. **DNS 必须走代理解析**。本地 DNS 泄漏不仅污染结果，还会把你的真实 ISP 暴露给落地。

### 5.2 各平台差异

| 平台 | 推荐客户端 | 关键设置 |
|---|---|---|
| Windows | Clash Verge Rev / Mihomo Party | 开启 TUN 模式 + Fake-IP |
| macOS | Surge / Stash | 关闭系统代理，改用增强模式 |
| Android | ClashMetaForAndroid | 关闭"绕过局域网"，防止内网泄漏 |
| iOS | Shadowrocket / Stash | 开启"始终开启 VPN" |
| 路由器 | OpenWrt + Mihomo | 关闭硬件加速（会绕过规则） |

具体配置流程可参考站内的 [客户端配置教程](/tutorial/)。

## 六、抓包排障诊断手册

当你的体验突然变差，不要先换节点，先做这三步。

### 6.1 MTR：定位丢包发生在哪一跳

```bash
# 联通/电信用户，打 100 个 TCP 包到 443 端口
mtr -rwzc 100 -T -P 443 your-proxy-domain.com
```

判定标准：

- **第 1–3 跳丢包**：本地路由器或光猫问题，重启光猫
- **第 4–8 跳丢包且后续跳正常**：运营商骨干限速，属正常现象，可忽略
- **倒数 2–3 跳持续丢包**：国际出口 QoS，换 CN2/9929 才能解决
- **最后一跳丢包**：落地机房问题，联系服务商

### 6.2 curl：测真实的 TCP 建连与首字节时间

```bash
curl -o /dev/null -s -w "DNS: %{time_namelookup}s\nTCP: %{time_connect}s\nTLS: %{time_appconnect}s\nTTFB: %{time_starttransfer}s\nTotal: %{time_total}s\n" https://www.google.com
```

- `TCP` 明显高于 `DNS`：��路质量问题
- `TLS` 异常高：可能是 TLS 握手被干扰或落地负载高
- `TTFB` 高但 `TLS` 正常：落地机房上行拥塞

### 6.3 tcping：绕开 ICMP 优先级的干扰

```bash
tcping -t 443 your-proxy-domain.com 20
```

注意：很多系统自带的 `ping` 走的是 ICMP，会被运营商优先级保护。**只有 tcping 到 443 才是真实体验**。

### 6.4 快速判定表

| 现象 | 最可能原因 | 处置动作 |
|---|---|---|
| ping 低、测速慢 | 163 晚高峰 QoS | 换 9929/CN2 回程 |
| ping 高、测速正常 | 回程绕路 | 可接受，无需处理 |
| 延迟抖动剧烈 | 本地 WiFi 或光猫 | 改用有线 + 重启设备 |
| 特定网站打不开 | DNS 污染或路由黑洞 | 换 DNS + 换落地 |
| 全时段都慢 | 超售严重 | 直接换服务商 |

## 七、行业避坑矩阵

| 宣传话术 | 真实情况 | 识别方法 |
|---|---|---|
| "全 CN2 GIA 直连" | 大概率是去程 GIA、回程 163 | 用 `mtr` 看回程 AS 号 |
| "无限流量" | 实际限速阈值极低 | 看是否有 Fair Use 条款 |
| "原生 IP 解锁 Netflix" | 多为广播 IP 或 DNS 解锁 | 查落地 IP 的 ASN 归属 |
| "BGP 多线智能选路" | 可能只是多 A 记录轮询 | 拨测不同运营商回程是否真优化 |
| "年付 5 元/月享专线" | IEPL 成本都不可能这么低 | 用脚算算带宽批发价 |
| "不限设备数" | ��常��并发连接数限制 | 看服务条款细则 |

**一个快速验证技巧**：拿服务商给出的中转 IP，在电信、联通、移动三个环境分别 `traceroute`，如果三条路径在第 5 跳之后就完全一致，那基本可以判定它只有单线，所谓"多线"只是 DNS 层的事。

## 八、常见问题排障 FAQ

**Q1：我是电信用户，为什么同一节点晚上 8 点后从 30Mbps 掉到 2Mbps？**
典型 163 晚高峰 QoS。用 `mtr -T -P 443` 打 100 包，如果倒数几跳丢包率跳升，就是出口整形。换带 9929 回程或 IEPL 的方案可解。

**Q2：移动宽带走中转到底好不好？**
好，但前提是中转落地在港澳或经过 CMI 优化。移动直连美西是全网最差组合之一，别碰。

**Q3：联通用户是不是随便选都能用？**
大致是的，但要注意"回程是不是联通"。有些服务商去程走联通、回程走电信，联通用户照样吃 163 的亏。

**Q4：为什么我 ping 只有 20ms，看 4K 还是卡？**
带宽不足或落地拥塞。ping 低只代表链路通畅，不代表有足够吞吐。用 `curl` 测 TTFB 和实际下载速度。

**Q5：IP 纯净度怎么自查？**
访问 ipinfo.io 或 whois 查询 ASN 类型，若为 Hosting/Datacenter 且被大量标注，则属于机房 IP。住宅 ISP 落地才更容易通过风控。

**Q6：有必要为了低延迟上 IEPL 吗？**
如果你玩游戏或做实时会议，值得。如果只是刷视频看网页，BGP 中转已经够用，IEPL 的边际收益感知不强。

**Q7：换了三个服务商都晚高峰卡，是我不行还是行业不行？**
大概率是行业问题。电信 163 出口的晚高峰是全球公认难题，2018 年至今没有根本性改善。选择带独立专线回程的方案是唯一现实解。
