# 什么是 BGP 线路：边界网关协议工作原理与三网优选核心机制

## 一、TL;DR：先给结论，再拆骨头

如果你只有 30 秒：**BGP 不是「一条线路」，而是一套让不同运营商网络（AS）互相宣告「我这儿能到哪个 IP 段」的路径向量协议。** 机场商家嘴里的「BGP 中转」「三网优选」，本质上说的是同一件事——他们从多家上游 ISP 手里拿到了 IP 广播权，通过 BGP 的 LOCAL_PREF、AS_PATH 等属性调优，让电信、联通、移动的用户**各自走到离自己最近的入口**，而不是统统一条路绕到广州再出海。

关键结论三条：

1. **BGP 解决的是「入口就近」，不是「全程高速」。** 国内入口再好，出境那一段如果是 163 骨干网（AS4134）在晚高峰挤成沙丁鱼，该丢包还是丢包。真正的稳定来自「BGP 接入 + IEPL/IPLC 专线出境」的混合架构。
2. **BGP 机房 ≠ 优质机房。** 有独立 AS 号、能多线广播，只代表它「合规且有路由权」，和带宽质量、超售比、IP 纯净度完全是三件事。
3. **对普通用户，唯一有意义的验证方式是实测。** traceroute 看路径、mtr 看丢包、tcping 看握手延迟，任何宣传文案都比不上这三条命令。

下面我们从物理机理开始，一层层剥开。

## 二、BGP 的物理底座：AS 号、路由表与「不是三次握手能解决的事」

互联网不是一个整体，而是由几万个**自治系统（Autonomous System, AS）**拼起来的联邦。每个 AS 有一个全球唯一的编号，比如中国电信 163 骨干是 AS4134，CN2 是 AS4809，联通 9929 是 AS9929。AS 内部用 OSPF/IS-IS 这类 IGP 协议跑路由，AS 之间则靠 **BGP-4** 交换信息。

BGP 的几个硬核特征决定了它的行为方式：

- **跑在 TCP 179 端口上**，是典型的应用层路由协议。这意味着它天然具备可靠性，但收敛速度远慢于 OSPF（全球路由表收敛通常需要几十秒到几分钟）。
- **路径向量而非距离向量**。BGP 传递的是完整的 AS_PATH 列表，天然防环——如果收到的路由里已经有自己的 AS 号，直接丢弃。
- **策略驱动，而非最优驱动**。这是最容易被忽略的一点：BGP 选路的第一优先级从来不是「最快」，而是「管理员最想走的那条」。这就是为什么同样是「BGP 机房」，A 家的电信用户走 AS4809，B 家的却全甩到 AS4134。

2026 年全球 IPv4 路由表规模已逼近 **95 万条前缀**，IPv6 约 22 万条。这么大的表，任何一次上游抖动都可能引发重收敛，这就是「BGP 抖动」的物理来源。

顺带说一句安全：BGP 诞生时互联网还是个互信的小圈子，没有原路验证。RPKI/ROA 就是给路由加签名，防止别人冒充你的 IP 段做**路由劫持**。2026 年主流 Tier-1 已强制 RPKI 校验，但中小机房覆盖率参差不齐——这本身就是判断机房专业度的隐藏指标。

## 三、BGP 选路七大权重：为什么你的千兆宽带跑不满

厂商设备上的 BGP 选路顺序（以 Cisco 体系为例，华为/思科顺序略有差异）大致如下，从上往下逐级比较，平手才看下一项：

| 优先级 | 属性 | 作用域 | 实战含义 |
| --- | --- | --- | --- |
| 1 | Weight | 本地私有 | 管理员手动指定，最高优先 |
| 2 | LOCAL_PREF | AS 内传播 | **最常用的调优旋钮**，决定出向流量走哪条上游 |
| 3 | 本地起源路由 | — | 自己宣告的优先 |
| 4 | AS_PATH 最短 | — | 经过的 AS 越少越优先 |
| 5 | ORIGIN | — | IGP 优于 EGP 优于 Incomplete |
| 6 | MED | AS 间 | 影响**入向**流量，邻居可以无视 |
| 7 | eBGP 优于 iBGP / 最近 IGP 邻居 / 最低 Router ID | — | 收尾判决 |

这张表解释了一个常见困惑：**为什么同一条 BGP 线路，电信用户丝滑，移动用户却在绕圈？** 因为机房侧的 LOCAL_PREF 只控制**出方向**；你家的**入方向**（联通/移动怎么走进来）取决于对方运营商的 MED 和 AS_PATH 策略，这是你花钱也未必买得到的东西。所以真正高端的做法是——机房直接向三大运营商**各自建立 eBGP 邻居并广播多份等价路由**，让三网用户各自走进来。这就是「电信移动联通三网直连」的技术内涵。

想深入了解不同中继方式带来的实际差异，可以对比阅读 [IEPL 与 IPLC 专线架构拆解](/tech/line/)，理解「入口 BGP + 出境专线」为什么是目前的最优解。

## 四、什么是 BGP 机房：单线、双线、多线、BGP 的四种形态

很多商家把「BGP 机房」当卖点，但行业内它其实有清晰的分级：

- **单线机房**：只接一家运营商，电信用户快，联通移动绕路甚至丢包。成本最低，常见于老式 IDC。
- **双线机房**：电信 + 联通，通过双网卡或双路由表实现。移动用户仍然吃亏（移动国际出口本就薄弱）。
- **三线/多线机房（非 BGP）**：同时接三家，但用**多个独立 IP** 分别服务不同运营商——你需要手动切换线路，体验割裂。
- **真 BGP 机房**：拥有独立 AS 号与 IP 段，和至少两家运营商建立 eBGP 邻居，**同一个 IP 段向所有上游广播**。用户无论来自哪家运营商，都自动走最优入口，无需手动切换。

判断一个机房是不是「真 BGP」，最直接的方法不是看宣传页，而是：

```bash
# 查 AS 号归属
whois -h whois.cymru.com " -v <你的节点IP>"

# 查该 IP 段被几个 AS 宣告（上游越多越接近真 BGP）
curl -s "https://bgpview.io/api/prefix/<你的IP段>" | jq '.data.upstreams'
```

如果查出来只有一个上游 AS，那它更可能是「单线转售」，所谓 BGP 只是话术。

## 五、核心参数对比矩阵：10 项量化指标横向对照

下面这张表是选型时的核心参照系。请把「延迟」「丢包」「超售比」「IP 纯净度」四列当作硬指标，其余为加分项。

| 指标 | 单线直连 | 双线/三线（多IP） | 真 BGP 多线 | BGP + IEPL 混合 |
| --- | --- | --- | --- | --- |
| 国内入口延迟 | 20–40ms（同网） | 25–60ms | 25–55ms | 25–50ms |
| 晚高峰丢包率 | 5%–15% | 3%–8% | 1%–5% | `< 1%` |
| 电信/联通/移动覆盖 | 仅一家 | 需手动切换 | 自动最优 | 自动最优 |
| 出境路径 | 公开骨干，易拥塞 | 公开骨干 | 公开骨干 | 私有专线，不参与公网拥塞 |
| 线路抖动（Jitter） | 高 | 中 | 中 | 低（`< 5ms`） |
| IP 纯净度 | 视机房 | 视机房 | 较好 | 较好（独立段） |
| 常见超售比 | 1:10 以上 | 1:8 | 1:5 | 1:3 ~ 1:4 |
| 抗封锁能力（TLS 指纹） | 弱 | 中 | 中 | 强 |
| 成本量级 | 低 | 中 | 中高 | 高 |
| 适用场景 | 单网轻量 | 预算敏感 | 通用出海 | 生产力/直播/跨境办公 |

> 表内延迟为「国内任一城市 → 香港/日本入口」的典型区间，实测受本地 ISP 与时段影响浮动 ±15ms。

需要补充的是**超售比**这个隐形杀手。机房卖给你「100M 独享」，实际上是 1:8 甚至 1:20 复用。白天你测速满速，晚高峰掉到 3MB/s，这就是超售被挤爆。识别方法很简单：**连续 7 天、每天 20:00–23:00 各测一次**，如果夜间速率长期低于标称值 40%，几乎可以坐实超售。

## 七、分平台实操配置与深度避坑

**Windows（Clash Verge / v2rayN）**
- 开启 TUN 模式接管全局流量，避免部分应用绕过代理导致 DNS 泄漏。
- 在配置中显式设置 `dns: { enable: true, enhanced-mode: fake-ip }`，并使用 `nameserver-policy` 把国内域名交给运营商 DNS，海外交给加密 DNS。
- 避坑：不要迷信「延迟测试」里的 ICMP Ping 数字，很多节点回 ping 但 TCP 握手极慢——那通常是 ICMP 被优先应答的假象。

**macOS（Surge / ClashX Meta）**
- Surge 建议开启 `tcp-fast-open` 与 `mptcp`（若服务端支持），跨境场景下首包延迟能降 20–30ms。
- 避坑：macOS 的系统代理不会覆盖部分命令行工具，`curl` 测试请务必加 `-x` 显式指定代理。

**Android / iOS**
- iOS 上 Shadowrocket 优先选 `Reality` 或 `Hysteria2` 类协议，抗封锁更强。
- 避坑：移动网络下的 IPv6 优先策略常导致「明明有 IPv4 优质线路却走 IPv6 绕路」。若节点质量差，考虑在系统层面关闭 IPv6。

**软路由 / OpenWrt**
- 建议按运营商分流（电信走 A 节点、联通走 B 节点），这恰恰是 BGP 多线价值的延伸——家庭侧复刻机房侧的策略。
- 避坑：软路由 CPU 性能不足时，加密解密会是瓶颈，千兆宽带只跑出 200M，别怪机场，先看 `top` 里的 CPU 占用。

关于协议选择与参数调优，可延伸阅读 [TLS Reality 与抗封锁协议实战配置](/tutorial/) 及 [BBRv3 拥塞控制调优指南](/tech/)。

## 八、抓包排障诊断手册：三条命令定位 90% 的问题

**第一步：看路径（谁的锅）**

```bash
# Linux/macOS
mtr -rwzc 100 <节点IP或域名>

# Windows 可用 WinMTR 图形版
# 关注第 2–5 跳：如果国内骨干就丢包，是入口问题；出境后丢包，是专线/境外问���。
```

**判定表：**

| 现象 | 最可能原因 | 处置建议 |
| --- | --- | --- |
| 第 1–2 跳就丢包 | 本地路由器/光猫 | 重启光猫，检查网线 |
| 第 3–5 跳丢包但末跳正常 | 运营商骨干拥塞 | 换 BGP 入口，或换时段 |
| 出境后开始丢包 | 国际出口挤兑 | 换 IEPL 专线，BGP 救不了 |
| 全程不丢但延迟高 | 路径绕行 | traceroute 看是否绕美/绕日 |
| 末跳丢包但连接正常 | 目标禁 ICMP | 属正常，��误判 |

**第二步：看握手（TCP 层是否健康）**

```bash
# 测 443 端口握手延迟与抖动，比 ping 更贴近真实体验
tcping -t 100 <节点IP> 443

# 若 tcping 稳定而 ping 抖动大，说明 ICMP 被限速，以 tcping 为准
```

**第三步：看吞吐与首字节（应用层真相）**

```bash
curl -o /dev/null -s -w "DNS:%{time_namelookup} TCP:%{time_connect} TLS:%{time_appconnect} TTFB:%{time_starttransfer} Total:%{time_total}\n" https://www.google.com
```

判读逻辑：**TLS 耗时占比过高 → 加密协商被干扰或线路 RTT 高；TTFB 高而 TCP 快 → 服务端或出口拥塞；Total 高但各项都正常 → 带宽不足或超售。**

如果你懒得分步做，直接跑一遍 [AirPick 实验室的延迟与丢包基准测试](/help/)，把结果和上面这张判定表对照即可。

## 九、避坑矩阵：识别虚假宣传、超售与伪解锁

| 宣传话术 | 真实情况 | 验证方法 |
| --- | --- | --- |
| 「原生 IP / 家宽 IP」 | 多为机房段伪装 | 查 ASN 类型、看流媒体风控评分 |
| 「BGP 三网直连」 | 可能只是多 IP 切换 | whois 查上游 AS 数量 |
| 「不限流量不限速」 | 必然超售或限速阈值 | 连续 7 天晚高峰测速 |
| 「解锁 Netflix / Disney+」 | 可能只在特定区服可用 | 实测目标区服 + 4K 码率 |
| 「10G 独享口子」 | 独享的是端口不是带宽 | 看合同是否写「保证带宽」 |
| 「永久有效」 | 无 SLA 的口头承诺 | 看是否支持月付试水 |
| 「CN2 GIA 直连」 | 可能只有部分回程走 CN2 | traceroute 双向验证 AS4809 |

**特别提醒**：所谓「伪解锁」，指的是 DNS 层面解开了区域限制，但实际播放时码率被锁在 480p，或 10 分钟后就触发风控。测试时务必播放 5 分钟以上并查看实际分辨率码率，而不是只看「能不能打开首页」。

## 十、常见问题 FAQ

**Q1：BGP 线路一定比非 BGP 快吗？**
不一定。BGP 优化的是**入口就近**，如果出境段是拥塞的公共骨干，再好的入口也是白搭。BGP 的价值在于「稳定一致」而非「绝对更快」。

**Q2：为什么我用移动宽带，测出来比其他人都慢？**
移动的国际出口（CMI，AS58807）本身资源紧张，且部分机房未与移动建立直连邻居。建议优先选明确标注「移动优化」或 BGP 多线广播的产品。

**Q3：节点 ping 只有 30ms，为什么打开网页还是卡？**
Ping 走的是 ICMP，优先级通常最高。真实体验取决于 TCP 握手、TLS 协商与带宽。用 `tcping` 和 `curl -w` 复核。

**Q4：晚高峰掉速严重，是机场的问题吗？**
大概率是。要么超售，要么出境带宽被挤兑。先用 mtr 定位是国内段还是出境段丢包，再决定是否换服务商。

**Q5：同一个节点，昨天好用今天很慢？**
检查是否 BGP 路由发生了重收敛或改动（上游策略调整很常见）。用 `mtr` 对比前后路径，若 AS_PATH 变了，说明是路由层面的问题。

**Q6：IP 被流媒体封了怎么办？**
机房 IP 段有信誉分。优先选提供**独立 IP 段**且定期更换段的服务商，避免使用被大量滥用的共享出口。

**Q7：要不要为了 BGP 多花钱？**
如果你只有单一运营商且使用强度低，多花的钱收益有限。但如果你有多设备、多运营商、或者对稳定性有要求，BGP 多线带来的体验提升是实打实的。
