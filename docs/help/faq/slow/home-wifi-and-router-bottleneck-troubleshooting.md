# 本地 WiFi 与路由器瓶颈排查：别让家里的老旧路由器拖垮百兆梯子

## 一、TL;DR：先给结论，再讲物理机理

如果你的机场订阅标称 2.5Gbps 出口、测速节点显示「延迟 38ms、带宽 800Mbps」，而你本地 YouTube 只有 1080p 且频繁转圈，**请先别急着骂机场跑路**。在过去三年我们处理的上千条「梯子变慢」工单里，超过八成的问题根源不在服务端，而在你家那台服役六年、塞在电视柜夹缝里的百兆老路由。

三条可以直接落地的结论：

1. **只要你还连着 2.4GHz 频段跑大流量，任何高端机场都是浪费钱。** 城市公寓环境下 2.4G 的实际吞吐经常掉到 20–60Mbps，抖动超过 80ms，这对走 TLS 加密的隧道流量是灾难级。
2. **路由器 CPU 比带宽跑分更值得关注。** 一台双核 880MHz 的老平台开启 QoS 或软件 NAT 后，转发能力会从 900Mbps 断崖式跌到 200Mbps 左右，而且 CPU 一旦跑满，握手延迟会飙升到几百毫秒——表现为「能连上但一卡一卡」。
3. **有线 + 硬件 NAT + 5GHz 三件套，是性价比最高的升级路径。** 在绝大多数场景下，换一台 AX3000 级别的 WiFi 6 路由（或加一台 N100 软路由），带来的体验提升远大于把机场套餐从 100M 升到 500M。

## 二、底层机理：数据包在你家经历了什么

### 2.1 无线物理层：2.4GHz 为什么天然不适合跑隧道

2.4GHz ISM 频段总共只有 83.5MHz 频谱，全球通用不重叠信道只有 **1 / 6 / 11** 三个（国内 1–13 可勉强排 1/5/9/13 四个）。在一栋 30 层的居民楼里，你打开 WiFi 分析工具往往会看到 40–80 个 SSID 同时挤在这三个信道上。

WiFi 是**载波侦听多路访问（CSMA/CA）**机制，本质是「谁先抢到谁说话」。信道越拥挤，退避等待时间越长，表现为：

- 空载时延迟 5–15ms，一旦邻居开始下电影，延迟立刻冲到 50–300ms；
- 数据包重传率上升，而 TCP 会把重传解读为拥塞，主动砍半窗口；
- 隧道协议（Reality / XTLS Vision / WireGuard）对延迟抖动极其敏感，抖动比总带宽更致命。

再叠加 2.4G 频段的现实污染源：蓝牙耳机、无线键鼠、微波炉、婴儿监视器、Zigbee 智能家居。这些设备的发射功率不小，且都是「突发式占用」，正是延迟抖动的主要来源。

### 2.2 5GHz / WiFi 6 / WiFi 6E / WiFi 7 的差异到底在哪里

5GHz 频段可用频谱接近 900MHz，非 DFS 信道就有一大把。关键增量在于：

- **信道宽度**：2.4G 最多绑 40MHz（还极不稳定），5G 常见 80MHz，WiFi 6 支持 160MHz，WiFi 7 甚至 320MHz。
- **调制方式**：802.11ac 是 256-QAM，WiFi 6 升级到 1024-QAM，同条件下速率提升约 25%。
- **OFDMA**：WiFi 6 把信道切分为资源单元（RU），多设备并发时不再需要逐个排队，对「手机 + 电脑 + 电视同时在线」的家庭意义重大。
- **MU-MIMO 与 BSS Coloring**：后者能降低邻居 AP 的同频干扰判定，密集住宅楼实测有效。
- **WiFi 6E** 新增 6GHz 频段，几乎无干扰，但穿墙能力更差，且国内合规设备极少。

一句话结论：**如果你家宽带在 300M 以上、且跨境流量想跑满，5GHz 起步，WiFi 6 是甜点，6E/7 目前只在设备齐全时才有意义。**

### 2.3 路由器 CPU：被 90% 用户忽视的真凶

家用路由器做的不只是「转发」，它还要承担：

1. **PPPoE 拨号**（如果光猫桥接）——这是纯 CPU 消耗大户；
2. **NAT 地址转换**——连接数越多越吃 CPU；
3. **QoS / SQM 流量整形**——几乎全部靠 CPU 软算；
4. **防火墙规则、DNS 转发、IPv6 处理**；
5. **如果你在路由器上跑代理插件（OpenClash/PassWall 等）**，加密解密也是纯 CPU。

现代 SoC 普遍带**硬件 NAT 卸载（NAT Offload / Flow Offload / HNAT）**，开启后可以达到近线速转发。但一旦你打开 QoS 或者跑代理插件，这条卸载链路就被旁路掉了，转发能力打回原形：

| 平台 | 核心与频率 | 硬件 NAT 转发 | 开 QoS / 代理后 |
| --- | --- | --- | --- |
| 老款百兆路由（MT7620A） | 单核 580MHz | 约 90Mbps（受百兆口限制） | 20–50Mbps |
| 经典千兆（MT7621A） | 双核 880MHz | 800–940Mbps | 150–300Mbps |
| 主流 WiFi 6（MT7981 / Filogic 820） | 双核 A53 1.3GHz | 1.8–2.0Gbps | 500–900Mbps |
| x86 软路由（N100） | 4 核 Alder Lake-N | 2.35Gbps 线速 | 1.5–2.3Gbps |

当你看到路由器管理页的 CPU 占用在测速时飙到 95% 以上、且 `%si`（软中断）占比极高，那就是转发路径被拉进了慢速通道。此时的典型症状是：**单线程测速只有几十兆，多线程能跑到几百兆；延迟忽高忽低。**

### 2.4 传输层：BDP、窗口与 BBRv3

跨境链路的 RTT 通常在 150–280ms。按带宽时延积公式 `BDP = 带宽 × RTT`，要跑满 100Mbps、RTT 200ms，TCP 窗口至少需要 2.5MB。老设备的默认接收窗口往往只有 256KB–1MB，导致**单线程速度被封顶**。

这也是为什么很多人「单线程测速 30Mbps、多线程 200Mbps」。在路由器侧开启 BBR（如果固件支持）或让终端使用现代拥塞控制算法，可以显著改善高丢包高延迟场景。相关内容我们在 [BBR 与拥塞控制实战](/tech/) 里有专门拆解。

## 四、人群与场景选型

**单身公寓 / 一室户（宽带 300M 以内）**：一��� AX3000 级别的 WiFi 6 路由足够，重点是把 2.4G 和 5G 拆成两个不同 SSID，终端手动连 5G，避免设备「自作聪明」黏在 2.4G。

**城市老破小 / 承重墙多**：不要指望单台路由穿三堵墙。正确做法是**有线回程 Mesh** 或电力猫 + AP。无线中继会直接把带宽砍半，且延迟翻倍，是跨境流量的头号杀手。

**多设备家庭（20 台以上）**：WiFi 6 的 OFDMA + 上行 MU-MIMO 是刚需。同时路由器内存建议 512MB 起步，否则大量 NAT 会话会导致表项溢出。

**软路由玩家 / 技术选型**：N100 或 J4125 是最稳的入门，配 2.5G 网卡，跑 OpenWrt 或 iStoreOS，卸载代理压力，主路由只做 AP。可参考 [软路由与代理分流配置教程](/tutorial/)。

**移动应急**：手机热点本质是单频 2.4G + 高功耗降频，只能应急。想稳定还不如直接笔记本有线接光猫测试。相关经验见 [移动网络应急排查](/help/)。

## 五、分平台实操配置与避坑

### 5.1 路由器端（收益最大）

1. **拆分 SSID**：2.4G 命名 `Home_2.4G`，5G 命名 `Home_5G`，关闭「双频合一 / Smart Connect」，让设备别乱跳。
2. **信道固定，不用自动**：2.4G 手动选 1/6/11 中最空闲的一个；5G 优先 UNII-3 的 149/153/157/161，避开 DFS 信道（涉及雷达检测，可能瞬间断连）。
3. **信道宽度**：5G 选 80MHz。160MHz 在国内 5G 环境干扰大，反而更不稳。
4. **开启 WMM**：不开启会导致 802.11n/ac 速率协商失败，被降级到 54Mbps。这是最常见的「隐形掉速」。
5. **关闭 Airtime Fairness**（多数家用场景适得其反）与「802.11b/g 兼容模式」，避免老设备拉低整体速率。
6. **QoS 慎重**：小包优先可以开，但传统带宽限制型 QoS 会吃掉大量 CPU，慎用。
7. **关闭 IPv6 或做正确分流**：IPv6 走本地、IPv4 走代理的混合模式，如果实现不规范会造成 DNS 泄漏和连接打洞失败。

### 5.2 Windows

- 设备管理器 → 网卡 → 高级：关闭「节能以太网」「省电模式」，开启「802.11ax 模式」；
- 无线适配器设置 → 电源管理 → 最高性能；
- 关闭「按流量计费的连接」标记，否则部分客户端会自动降频更新；
- 用 `netsh wlan show interfaces` 确认当前协商速率、频段和信道。

### 5.3 macOS / iOS

- macOS 按住 Option 点 WiFi 图标可看 PHY 模式、信道、MCS 索引、噪声；
- `sudo wdutil info` 查看详细链路质量；
- iOS 关闭「无线局域网助理」，避免在 WiFi 弱时悄悄切蜂窝导致隧道中断。

### 5.4 Android

- 开发者选项 → 「WiFi 扫描调节」关闭；
- 关闭「智能网络切换 / 自适应 WiFi」；
- 使用 WiFi Analyzer 类工具查看同频干扰，把信道调到最空的位置。

## 六、抓包与链路诊断手册

排查遵循**逐跳收敛**原则：终端 → 路由器 → 光猫 → 运营商 → 中转入口 → 落地。

### 6.1 关键命令

```bash
# 1) 终端到路由器网关：看无线这一段稳不稳
ping -c 100 192.168.1.1

# 2) 到公网第一跳：判断运营商侧质量
mtr -rwzc 100 1.1.1.1

# 3) 单线程 HTTP 下载细分耗时
curl -o /dev/null -s -w "code=%{http_code} connect=%{time_connect}s ttfb=%{time_starttransfer}s speed=%{speed_download}B/s\n" https://speed.cloudflare.com/__down?bytes=104857600

# 4) 局域网吞吐基准（需 iperf3 服务端）
iperf3 -c 192.168.1.2 -t 20 -P 4

# 5) TCP 端口连通性与握手耗时
tcping -n 20 你的节点域名 443

# 6) Windows 无线链路详情
netsh wlan show interfaces
```

### 6.2 判定表

| 现象 | 最可能原因 | 验证方式 |
| --- | --- | --- |
| `ping` 网关丢包且抖动大 | 无线干扰 / 距离远 | 换 5G 或靠近路由重测 |
| 网关延迟正常，`mtr` 第一跳就丢 | 光猫 / 上行链路 | 直连光猫 PPPoE 复测 |
| 单线程 30M / 多线程 300M | TCP 窗口 / 路由器 CPU | 看 CPU 软中断占比 |
| 握手慢但下载快 | DNS / 代理握手开销 | 换 DNS、开 TCP Fast Open |
| 有线正常、WiFi 异常 | 无线侧问题 | 对比有线 iperf3 |
| 白天好、晚上差 | 同频拥塞 / 运营商高峰 | 分时段 `mtr` 对比 |

## 七、行业避坑矩阵

| 宣传话术 | 真实情况 | 识别方法 |
| --- | --- | --- |
| 「AX3000 穿墙王，五天线」 | 天线数量 ≠ 性能，多天线常常只对应 2x2 | 看是否标注 MIMO 空间流数 |
| 「支持 160MHz，速率翻倍」 | 国内干扰大，实际协商常退回 80MHz | 用 `netsh wlan show interfaces` 看实际带宽 |
| 「WiFi 放大器 / 中继扩展全覆盖」 | 带宽砍半、延迟翻倍 | 中继节点测速对比主路由 |
| 「全屋 Mesh，无线回程即可」 | 无线回程在三跳后速率损耗 60% 以上 | 优先有线回程 |
| 「梯子节点 100% 解锁流媒体」 | 大量节点为共享 IP，随时被锁 | 实测解锁 + 看是否标注原生 IP |
| 「不限速不限量」 | 常见于超售严重的低价机场 | 高峰期多次测速比对 |

选机场时同样要把「本地链路」和「服务端链路」分开评估。机场侧的线路类型（IEPL / IPLC / BGP 中转）与倍率策略，详见 [线路类型科普](/tech/) 与 [机场评测总览](/reviews/)。

## 八、常见问题 FAQ

**Q1：我已经连了 5GHz，为什么还是卡？**
先确认协商速率。`netsh wlan show interfaces` 中若显示 200Mbps 以下，说明被降级到 11n 或窄带宽，检查是否开了 WMM、信道宽度是否被设成 20/40MHz。

**Q2：路由器 CPU 一直 100%，怎么办？**
确认是否开了 QoS、代理插件或大量连接数的 BT 下载。临时方案是关掉软算功能，长期方案是换 MT7981 以上平台或上 x86 软路由。

**Q3：手机很快，电脑很慢，是机场的问题吗？**
大概率不是。优先检查电脑网卡驱动、是否连到 2.4G、是否开启了节能模式与第三方杀毒的网络过滤驱动。

**Q4：晚上必卡，白天正常，是节点超载吗？**
先用 `mtr` 做分时段对比。若第一跳就开始丢包，就是你所在小区的同频干扰或运营商高峰，跟节点无关。

**Q5：换 WiFi 6 路由器真的有用吗？**
有用，但前提是终端也支持 WiFi 6。仅路由器支持而手机不支持，只会在多设备并发时略有改善。

**Q6：软路由值得投入吗？**
如果你宽带 500M 以上、家里设备多、又想在路由侧做分流和代理，值得。N100 平台性能够用且功耗低，配合独立 AP 是最佳架构。

**Q7：一定要有线吗？**
对跨境流量来说，有线是确定性最高的方案。至少要保证「路由器到光猫」这一段是有线，避免整条链路都跑在无线之上。

## 结语

跨境网络体验是一条**端到端的长链路**，任何一段掉链子，整体都会塌方。机场给你的是从入口到落地的那一段，而你家路由器、光猫和 WiFi 频段，是你唯一能完全掌控的那一段。把本地这一段先做到「有线 + 硬件 NAT + 5GHz/WiFi 6」，再去挑节点和套餐，你会发现**绝大多数「机场变慢」的抱怨，其实从来就不是机场的问题**。

如果你已经排除了全部本地因素，仍然在高峰期出现断流、延迟暴涨，那才真正到了评估服务商质量的时候。届时建议用固定时间段、固定节点、固定测速方法做横向对比，避免被瞬时波动误导。
