# 跑路风险评分天梯：AirPick 基于资金、运营时长与线路的风险等级模型

> 本文属于 AirPick「防跑路与资金安全」系列，配套阅读：[/help/guide/scam/](/help/guide/)、[/help/](/help/)。评测数据来源与更新日志见 [/reviews/](/reviews/)。

## 一、导言：跑路不是玄学，是一道可以打分的概率题

先给结论，不绕弯子：

**机场跑路的本质，是「预付费现金流池」与「长期履约成本」之间的错配。** 用户一次性付了一年甚至三年的钱，服务商却只需要按月支付上游带宽账单。只要现金流断裂速度超过履约周期，跑路就是必然结果，而不是意外事件。

这决定了三件事：

1. **跑路是可以提前量化的。** 运营时长、线路持有方式、支付通道类型、超售比、客服响应曲线——这五个维度足以在跑路发生前 30–90 天给出预警信号。AirPick 安全评测体系把这套逻辑固化为 9 项客观指标的打分模型，本文完整公开。
2. **低价年付是最高危的结构。** 当一家机场的月付价压到成本的 60% 以下，同时用「年付立减 50%」把现金流提前锁定，它的模型本质上就是庞氏——用新用户的钱兑付老用户的带宽。识别方法在第八章的避坑矩阵里有完整判定树。
3. **不要把「线路好」等同于「不会跑」。** 技术能力和财务健康度是两条正交的轴。我们见过大量 IEPL 专线做得极漂亮的小团队，因为只有 2 个人运维、没有备用资金池，在一次上游机房调价后 45 天内直接关站。

**TL;DR（给没时间的人的 60 秒版本）：**

- 风险评分 = 运营时长(20%) + 资金透明度(15%) + 线路归属(15%) + 支付通道(10%) + IP 原生度(10%) + 客服响应(10%) + 超售比(8%) + 文档完整度(7%) + 社群口碑(5%)。
- 总分 85+ 归入 S 级（低风险长期持有）；60 分以下直接判定 E 级，不要碰。
- 单次充值金额不应超过「你愿意在 90 天内完全损失」的额度。这是唯一的硬性风控纪律。
- 真正的排障能力 = 会用 `mtr`、`curl -w`、`tcping`、`openssl s_client` 四件套把「线路问题」和「服务商问题」区分开。

## 二、底层机理：跑路的资金流断点与链路断点

要建立评分模型，先得理解一条机场的服务链是怎么断的。

### 2.1 资金面：预付费池 vs 月度账单

一家中型机场的成本结构大致是：

- **上游专线/中转带宽**：按月或按季度结算，通常要求预付 1 个月押金。
- **落地机房机柜与 IP 租用**：按月结算，原生 IP 单价更高。
- **面板授权与中转服务器**：一次性 + 月度。
- **运维人力**：这是最容易被低估的一块，1–2 人的小团队一旦有人退出，服务立刻降级。

收入端则是典型的「年付占大头」。当一家机场的年付占比超过 70%，它的现金流健康度就高度依赖**新增用户增速**。增速一停，次月账单就付不出。这跟 SaaS 的订阅模��有本质区别——SaaS 的边际成本趋近于零，而机场的边际成本是**线性**的：多一个用户，就多一份真实带宽消耗。

### 2.2 网络面：线路「突然变差」往往是跑路前兆

跑路前 2–8 周，通常会出现可观测的链路劣化，顺序大致是：

1. **峰值时段丢包抬升**：从 `0.2%` 涨到 `3%–8%`，因为超售比被偷偷调高。
2. **节点数量静默减少**：原来 40 个节点变成 25 个，公告里不说，只在面板上悄悄下线。
3. **IP 归属地漂移**：`whois` 一查，原本的日本原生 IP 变成了某个公共云的美西机房 IP。
4. **计费倍率暗改**：标称 x1 的节点在后台改成 x2、x3，用户流量消耗速度翻倍。
5. **客服响应从 3 小时变成 72 小时**，最后只剩一个 TG 频道禁言。

这五步是**可测量的**，第七章给出的命令组合就是用来抓这些信号的。

### 2.3 BGP / IEPL / IPLC 与风险的关系

很多用户以为「用了 IPLC 就不会跑」，这是误判。正确的理解是：

- **IEPL/IPLC（二层专线）**：端到端内网直达，不过公网 QoS，抗封锁强、抖动低，但**成本极高且多按带宽包月**。能长期持有专线的服务商，至少说明它有稳定的现金流去支付月账单——这是加分项，但不是保险。
- **BGP 中转**：走公网 + 优化路由，成本低、弹性大，抗打击能力取决于中转入口质量。这是大多数中端机场的选择。
- **直连 + 公共隧道**：成本最低、最容易被 QoS 限速，也是跑路率最高的档位。

关于 BBRv3、TLS Reality 与双 ISP 落地这些技术点，本文不展开，详见 [/tech/](/tech/) 的技术专栏；对风险模型的影响只有一个结论：**技术栈越依赖「自研 + 长期持有资产」，跑路成本越高，风险越低；越依赖「现租现卖」，跑路成本越低，风险越高。**

## 三、核心参数对比矩阵：9 项客观指标的量化标准

下面这张表是 AirPick 安全评测体系 v2.6 的评分底表。所有指标都可以通过公开信息和终端命令验证，不接受服务商自述。

| # | 指标 | 权重 | 低风险区（满分） | 警戒线（半分） | 高危区（0 分） | 验证方式 |
|---|------|------|------------------|----------------|----------------|----------|
| 1 | 运营时长 | 20% | 连续 ≥ 36 个月 | 12–36 个月 | `< 12` 个月 | 域名注册时间 + 历史评测存档 |
| 2 | 资金透明度 | 15% | 官网明码标价、条款清晰、有退款政策 | 仅月付、无条款 | 低价年付诱饵、条款缺失 | 阅读 ToS / 退款页 |
| 3 | 线路归属 | 15% | 自持 IEPL/IPLC 或长期合约中转 | 短期 BGP 中转 | 纯直连 / 公共隧道 | `mtr` 路径 + ASN 查询 |
| 4 | 支付通道 | 10% | 正规商户（Stripe / 支付宝企业号） | 混合通道 | 仅加密货币 / 个人收款码 | 结算页观察 |
| 5 | IP 原生度 | 10% | 多地区原生 IP，归属地稳定 | 混播、部分漂移 | 集中单一机房、频繁漂移 | `whois` + 流媒体解锁实测 |
| 6 | 客服响应 | 10% | 工单平均 `< 6` 小时 | 12–24 小时 | `> 48` 小时或仅 TG 单聊 | 实测提工单计时 |
| 7 | 超售比 | 8% | `< 3:1` | 3:1 – 8:1 | `> 10:1` | 晚高峰 20:00–23:00 测速对比 |
| 8 | 文档完整度 | 7% | 有完整帮助中心 + 状态页 | 简单 FAQ | 单页落地页 | 站点结构勘察 |
| 9 | 社群口碑 | 5% | 长期活跃社群 + 第三方评测 | 小规模群 | 水军刷评、删帖控评 | 跨平台交叉验证 |

**总分计算公式：**

```
Score = Σ (单项得分 × 权重)

S 级：85 – 100   （长期持有，可考虑年付）
A 级：72 – 84    （稳定，建议半年付）
B 级：60 – 71    （观察期，只月付）
C 级：45 – 59    （高风险，随时准备迁移）
D 级：30 – 44    （强烈不建议）
E 级：`< 30`       （不要碰）
```

注意第 7 项「超售比」的测法：晚高峰用同一台机器、同一协议，先测一个非热门节点，再测标称「专线」的主推节点。如果两者带宽差距超过 3 倍，说明主推节点超售严重。

## 四、风险等级天梯：S 到 E 六档画像

**S 级（85+）——长期持有型。** 典型特征：运营 3 年以上、自持专线、有多地原生 IP、客服工单体系化、公开状态页。这类服务商跑路概率低，但通常价格不便宜。年付可以接受，但依然建议分批充值。

**A 级（72–84）——稳健型。** 运营 1.5–3 年，线路以 BGP 中转 + 部分专线为主，支付通道正规。最常见的「性价比主力」档位。建议半年付，避开超长周期。

**B 级（60–71）——观察期。** 运营不满 18 个月，或者有明显短板（客服慢、节点少）。只月付，绝不年付。每 30 天复评一次。

**C 级（45–59）——高风险。** 典型画像：上线 6–12 个月、宣传「年付 3 折」、节点清一色美西、TG 群禁言。这类机场的平均存活周期在 8–14 个月之间。

**D 级（30–44）——不建议。** 单页官网 + 个人收款码 + 无客服渠道。不用评了。

**E 级（`< 30`）——远离。** 上线时间无法确认（域名新注册）、只有加密货币支付、节点描述与实测完全不符、社群全是新号刷评。

**天梯示意（简版）：**

| 等级 | 分数区间 | 建议付���周期 | 迁移预案 |
|------|----------|--------------|----------|
| S | 85–100 | 年付 | 无需 |
| A | 72–84 | 半年付 | 备用 1 家 |
| B | 60–71 | 月付 | 备用 2 家 |
| C | 45–59 | 月付 / 短期 | 备用 2 家 + 数据备份 |

## 五、细分人群与场景选型推荐

**1. 跨境电商 / 多店铺运营。** 核心诉求是 IP 纯净度与稳定性，一旦 IP 被风控关联，损失远超订阅费。建议只选 S 级或 A 级，必须是原生 IP，且准备至少两家做冗余。参考 [/scenario/ecommerce/](/scenario/)。

**2. 出海开发者 / 远程办公。** 诉求是低延迟、高可用。优先看线路归属（指标 3）和超售比（指标 7）。可以用 B 级试水，但生产环境必须挂 A 级以上。

**3. 流媒体与 AI 工具用户。** 诉求是解锁能力，本质是 IP 的原生度问题。这类需求最容易被「伪解锁」欺骗，验证方法见第八章。参考 [/scenario/streaming/](/scenario/streaming/)。

**4. 学生 / 轻度用户。** 单次预算有限，最容易被低价年付吸引，也是跑路受害重灾区。强制纪律：任何情况下不年付，月付即可。参考 [/tutorial/](/tutorial/)。

**5. 团队 / 多设备场景。** 诉求是账号共享与并发数。注意并发数限制是超售的隐蔽手段之一——标称「不限设备」但实际单 IP 限 3 连接。

## 六、分平台实操配置与深度避坑

**Windows（Clash Verge / Mihomo）。** 订阅导入后务必检查 `rules` 是否被服务商塞了自定义规则重定向。风险点：部分机场的订阅里会内嵌「流量统计上报」域名，属于隐私风险。建议在配置里加 `

`DOMAIN-SUFFIX,你的机场域名,DIRECT` 之外的屏蔽规则。

**macOS（Surge / ClashX Meta）。** Surge 的 `enhanced mode` 建议关闭自动更新订阅，改为手动更新，避免服务商在跑路前通过订阅更新推送恶意配置。

**iOS（Shadowrocket / Stash）。** 风险点在于「一键导入」的链接通常是短链，跑路后短链失效你会失去所有配置。**务必在导入后导出配置文件本地备份。**

**Android（Clash Meta for Android / v2rayNG）。** 注意后台保活与电量优化，同时检查是否有节点被标记为「实验性」——这类节点通常是临时租用的公共中转，跑路后第一批下线。

**路由器 / 软路由（OpenWrt + PassWall）。** 建议把订阅转换成静态配置文件，落盘到本地，然后关闭自动更新。这是最抗跑路的方案：即使服务商关站，配置还在，换订阅源即可。

**通用纪律三条：**

1. 订阅链接截图 + 配置导出，存本地。
2. 支付时使用可追溯的通道（信用卡、支付宝），不要用不可逆的加密货币。
3. 每一次续费前，重新跑一遍第三章的 9 项指标。

## 七、抓包与链路排障诊断手册

当服务出问题时，第一件事是**判断是线路问题还是服务商问题**。下面四条命令足以完成 90% 的归因。

### 7.1 路由与丢包：`mtr`

```bash
mtr -rwzbc 100 1.1.1.1
mtr -rwzbc 100 --tcp --port 443 你的节点域名
```

判读要点：

- 中间跳丢包但末端不丢 → 正常，路由器限速 ICMP，忽略。
- 从某一跳开始持续丢包并延续到终点 → 该段链路真实拥塞或故障。
- 全程 `0%` 但应用层卡 → 问题在服务商侧的策略（限速/超售）。

### 7.2 连接质量：`curl -w`

```bash
curl -o /dev/null -s -w 'connect=%{time_connect} tls=%{time_appconnect} ttfb=%{time_starttransfer} total=%{time_total}\n' https://www.google.com
```

判定表：

| 现象 | 可能原因 | 归属 |
|------|----------|------|
| `connect` `> 1.5s` | 路由绕行 / 中转拥塞 | 线路 |
| `tls` 与 `connect` 差值 `> 1s` | TLS 握手被干扰 | 线路 / 封锁 |
| `ttfb` 波动大但 `connect` 正常 | 服务端限速或超售 | 服务商 |
| 全部正常但无法打开 | 本地 DNS 污染 | 本地 |

### 7.3 端口连通性：`tcping`

```bash
tcping -t 10 你的节点域名 443
```

连续 10 次，观察抖动。丢包 `> 5%` 且 `mtr` 显示中间段正常，基本可以判定为服务商侧限速。

### 7.4 TLS 指纹验证：`openssl s_client`

```bash
echo | openssl s_client -connect 你的节点域名:443 -tls1_3 -servername 你的节点域名 2>/dev/null | openssl x509 -noout -subject -issuer -dates
```

看证书颁发者和有效期。如果证书是一个泛域名自签证书、且有效期只有几天，通常是临时拼凑的中转节点，稳定性极差。

## 八、行业避坑矩阵：识别虚假宣传、超售与伪解锁

| 宣传话术 | 真实含义 | 验证方法 | 风险等级 |
|----------|----------|----------|----------|
| 「年付立减 60%」 | 提前锁定现金流续命 | 对比月付价，若折扣 `> 50%` 高度可疑 | 🔴 高 |
| 「无限流量」 | 必然超售，靠限速兑现 | 晚高峰连续测速 3 天 | 🔴 高 |
| 「全节点解锁 Netflix」 | 通常只有 1–2 个节点真解锁 | 逐节点实测，看是否落在同一 /24 段 | 🟡 中 |
| 「企业级 IPLC 专线」 | 可能只是 BGP 中转换皮 | `mtr` 看是否全程内网跳、ASN 是否单一 | 🟡 中 |
| 「不限设备数」 | 单 IP 限连接数 | 多设备并发测试 | 🟡 中 |
| 「7×24 在线客服」 | 一个 TG 单聊窗口 | 实测提工单并计时 | 🟠 中高 |
| 「老牌运营十年」 | 域名可能是新注册 | `whois` 查创建时间 | 🔴 高 |
| 「支持任意退款」 | 通常有苛刻条件 | 阅读退款条款细则 | 🟡 中 |

**伪解锁的三步识别法：**

1. 用 `curl -I` 请求流媒体检测页，看返回的区域标识是否与标称一致。
2. 连续 7 天对同一节点重复测试，观察区域是否漂移。
3. 检查该 IP 的 ASN，如果和另外 20 个节点落在同一个 ASN，说明是同一批「共享落地」，很容易被平台批量封禁。

## 九、常见问题排障 FAQ

**Q1：节点突然全部超时，怎么判断是跑路还是故障？**
先 `ping` 官网域名，再 `tcping` 节点端口。如果官网还在但节点全挂，多半是机房事故；如果官网也 404、TG 群禁言、支付页下线，三者同时出现，基本可以判定跑路。此时立即导出配置、截图订单、走支付通道申诉。

**Q2：晚高峰只有 5Mbps，是超售吗？**
先排除本地网络。用 `mtr` 看是否在本地出口就丢包。如果本地正常、`ttfb` 波动大，则是服务商侧超售。建议立即降级为月付并准备迁移。

**Q3：订阅链接失效，配置还在，还能用吗？**
能。只要节点 IP 和密钥没变，本地配置照常工作。这也是为什么我们反复强调要导出配置本地备份。

**Q4：服务商说要「迁移机房」，停服 3 天，正常吗？**
不正常。合规的运维迁移会提前公告并给出补偿方案。突然停服 + 无补偿 + 客服失联，是典型的撤退前兆。

**Q5：年��还剩 8 个月，服务商跑了，能追回吗？**
取决于支付通道。信用卡/支付宝通常有争议申诉窗口（一般是 120–180 天），加密货币基本无法追回。所以**支付通道类型是评分模型里的独立指标**。

**Q6：怎么知道一家机场的域名到底运营了多久？**
`whois 域名` 看创建时间。注意：域名可能是从别人手里买来的老域名，要结合历史评测存档、社群创建时间交叉验证。更多验证技巧见 [/help/faq/](/help/faq/)。

**Q7：我需要同时备用几家？**
B 级及以下建议 2 家，A 级 1 家即可。备用机场不需要买贵的，能跑通基础需求就行——它的价值在于「主用挂掉时不用现找」。
