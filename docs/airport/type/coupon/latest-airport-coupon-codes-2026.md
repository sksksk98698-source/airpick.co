## 一、为什么 2026 年的机场优惠码，比以前「不值钱」了

先摆一个反直觉的事实：**2023—2024 年那种「3 折年付 + 无限流量 + 全节点 IEPL」的优惠码，在 2026 年基本已经绝迹**。原因不是商家良心变好了，而是成本结构变了。

三个硬成本同时上涨：

1. **IEPL/IPLC 专线端口费**：广深出口到香港、日本、新加坡的企业内网专线，单 Gbps 月费较 2022 年上涨约 30%—45%，且运营商开始对「跨境混合业务」做流量画像，灰产属性的 IP 段会被强制降级或要求整改。
2. **住宅 IP 与原生 IP 溢价**：ChatGPT、Claude、Gemini 的风控在 2025 年集体升级到设备指纹 + ASN 信誉双层判定，机房 IP（Datacenter ASN）几乎 100% 触发验证。机场要维持「原生解锁」，必须采购住宅 IP 或原生 ISP 段，成本是普通机房 IP 的 5—15 倍。
3. **协议对抗成本**：TLS Reality、Hysteria2、TUIC v5 的部署与维护需要持续跟进，境外中转节点一旦被 GFW 主动探测识别，整段 IP 需要更换。

所以，当你看到一个优惠码能打到 2 折、3 折，只有两种解释：**要么在超售比上动手脚，要么在落地出口上偷工减料**。这篇文章的核心，就是教你用工程手段验证「折扣背后到底砍了什么」。

## 二、底层机理：折扣价买的到底是什么

### 2.1 入口段：BGP 多线 vs 单线接入

国内入口决定了你晚高峰（20:00—23:00）能不能跑满。市面上的接入方式分三档：

- **单线接入**（只有电信或只有联通）：非对应运营商用户走公网绕行，晚高峰丢包率轻松突破 15%。
- **BGP 多线接入**：电信/联通/移动三线 Anycast 或本地 BGP 宣告，理想状态下延迟差在 10ms 以内。判断方法很简单：分别用三家运营商的移动网络做 `mtr`，看第一跳之后是否出现明显分叉。
- **双 ISP / 双入口**：同时在两个不同机房做入口，用 DNS 智能解析或客户端分流做冗余。这是 2026 年中高端机场的标配，也是「大牌机场折扣券」很少低于 7 折的原因——冗余机房的月租是固定支出，不打折也不亏。

### 2.2 中转段：IEPL / IPLC / 公网中转的本质区别

- **IEPL（International Ethernet Private Line）**：二层以太网专线，逻辑上是一条「内网网线」，不经过公网路由，理论上不会被 GFW 的公网探测命中。缺点是端口带宽贵，通常按 100Mbps / 500Mbps / 1Gbps 阶梯售卖。
- **IPLC（International Private Leased Circuit）**：三层点对点专线，比 IEPL 稍老但更稳定，常见于香港—日本、香港—新加坡链路，RTT 稳定在 25—45ms。
- **公网中转（CN2 GIA / 9929 / 4837）**：本质还是公网，只是走的是优质 AS。价格便宜一半以上，代价是晚高峰仍受公网拥塞影响，且 IP 段被墙概率显著更高。

**关键判断**：优惠码宣传页写着「IEPL」的，去客户端配置里看节点地址。如果落地 IP 的 ASN 属于常见云厂商（某 AWS、某 GCP、某 Oracle），那它 100% 不是真 IPLC——真专线的落地通常挂在中小型 IDC 或原生 ISP 段下。

### 2.3 出口段：QoS、BBRv3 与拥塞控制

出口侧能做手脚的地方最多。2026 年主流机场的拥塞控制算法分布：

- **CUBIC**：Linux 默认，丢包敏感，跨太平洋链路在 3% 丢包下吞吐会掉到峰值的 30% 以下。
- **BBR v1/v2**：谷歌方案，抗丢包能力强，但队列延迟高，游戏场景不友好。
- **BBRv3**：2023 年后开源，在多流并发下表现最好，也是目前高端机场的常见选择。
- **QoS 限速**：最隐蔽的一招。机场在入口侧对单用户做 **per-flow 限速**（比如单 TCP 流限 50Mbps），这样测速单线程永远跑不满，但多线程（Speedtest）看起来很快。**鉴别方法**：用单线程 `iperf3` 或单连接 `curl` 下载大文件，对比多线程结果，差距超过 3 倍就是被 QoS 了。

### 2.4 协议层：TLS Reality 与流量特征

2026 年还在用 VMess + WS + TLS 的机场，基本可以判定为「技术栈陈旧」。当前主流方案：

- **VLESS + XTLS-Vision + Reality**：无证书、借用真实目标站握手，抗主动探测能力强。
- **Hysteria2**：基于 QUIC，弱网表现极佳，但 UDP 易被 QoS，部分运营商对 UDP 大流量有整段限速策略。
- **TUIC v5**：QUIC 系，低延迟场景（游戏、视频会议）优于 Hysteria2。

**折价陷阱**：把 Hysteria2 标成「游戏专线」卖高价的，要警惕——多数省份的移动/联通对 UDP 443 之外的端口有隐性限速，实测 RTT 抖动可能比 TCP 还大。

## 五、分客户端实操配置与避坑

### 5.1 Windows：Clash Verge Rev

- **订阅转换**：优先使用机场自带的 Clash 订阅，不要用第三方免费转换站——部分转换站会记录你的订阅链接。
- **核心参数**：在 `Settings` 中开启 `TUN 模式`，但务必关闭「严格路由」以外的 DNS 劫持选项，否则会造成国内 App 走代理导致速度骤降。
- **测速建议**：用「延迟测试」而非「速度测试」筛选节点，速度测试会真实消耗流量。

### 5.2 macOS：Shadowrocket / Surge

- macOS 上 Shadowrocket 需配合 `Network Extension`，首次安装后要在「系统设置 → 隐私与安全性」中手动允许。
- 命令行排查 DNS 是否被劫持：

```bash
scutil --dns | grep nameserver | head -5
networksetup -getdnsservers Wi-Fi
```

若返回的 DNS 不在你配置的范围内（例如出现运营商 DNS），说明分流规则未生效。

### 5.3 iOS：Shadowrocket / Stash

- iOS 上最容易踩的坑是**「按需连接」与「低数据模式」冲突**，导致后台断流。建议关闭「低数据模式」。
- 订阅更新失败时，先切换一次节点再更新，多数是入口 IP 被临时限速。

### 5.4 Android：sing-box / Clash Meta

- sing-box 配置里 `sniff` 与 `domain_strategy` 必须开启，否则 Reality 节点无法正确分流。
- 避免使用来源不明的「一键机场导入」App，2026 年已出现多起订阅链接被中间人劫持的案例。

### 5.5 路由器：OpenWrt + PassWall2

- 建议将机场节点以「订阅」方式导入，而非手动添加，避免节点 IP 变更后失效。
- 关键坑：路由器 CPU 性能不足时，Reality 握手会拖慢整机转发，建议先在 PC 上验证该机场在 Reaalty 下的实际吞吐，再决定是否上路由。
- 相关配置细节见 [/client/](/client/)。

## 六、抓包排障诊断手册

当你拿着折扣码买的机场，发现「宣传 2.5Gbps、实测 20Mbps」，按下面流程走一遍，基本能定位到问题层。

### 6.1 链路质量：mtr

```bash
# macOS / Linux：持续 100 个包，显示 ASN
mtr -rwzbc 100 1.1.1.1

# Windows（需安装 WinMTR 或使用 wsl）
mtr -rwzc 100 1.1.1.1
```

**判定表：**

| 现象 | 可能的层级 | 处理建议 |
| --- | --- | --- |
| 第 1—3 跳就有 10% 以上丢包 | 本地 ISP 或本地路由器 | 换网络、重启光猫，与机场无关 |
| 第 4—8 跳丢包高，之后恢复 | 国内骨干拥塞 | 换入口节点，或改走 BGP 多线入口 |
| 全链路丢包集中在出口段 | 机场出口拥塞 | 反馈客服，或换节点 |
| 延迟正常但抖动超过 100ms | QoS 限速 / 队列管理问题 | 单线程测速验证 |

### 6.2 TCP 连通性与握手耗时

```bash
# 测试 443 端口 TCP 连通与握手时间
curl -o /dev/null -s -w "connect: %{time_connect}s  tls: %{time_appconnect}s  total: %{time_total}s\n" https://www.google.com

# 检查 TLS 版本与 ALPN（验证 Reality 伪装是否正常）
openssl s_client -connect your-node:443 -tls1_3 -alpn h2 -servername www.microsoft.com
```

重点看 `time_connect` 与 `time_appconnect` 的差值。差值超过 800ms，说明 TLS 握手被中间设备干扰，通常是入口 IP 已被标记。

### 6.3 单线程 vs 多线程吞吐对比

```bash
# 单线程下载测试（推荐用 Cloudflare 的测速文件）
curl -o /dev/null --limit-rate 0 -w "%{speed_download}\n" https://speed.cloudflare.com/__down?bytes=104857600
```

把结果与 Speedtest 多线程结果对比：

| 单线程 / 多线程 | 判定 |
| --- | --- |
| 比值大于 0.8 | 无 QoS，带宽真实 |
| 比值 0.4—0.8 | 轻度 QoS 或链路抖动 |
| 比值小于 0.4 | 明确被 per-flow 限速，宣传带宽不可信 |

### 6.4 DNS 污染与泄漏检测

```bash
dig +short @1.1.1.1 www.google.com
dig +short @8.8.8.8 www.google.com
```

两者返回结果不一致，或返回内网保留地址（如 0.0.0.0、127.0.0.1），说明本地 DNS 被劫持，需要在客户端开启 `fake-ip` 或 `redir-host` 模式。

### 6.5 端口级连通测试

```bash
# tcping（需单独安装）
tcping -t 5 your-node.com 443

# 或使用 nc
nc -vz -w 3 your-node.com 443
```

若 `tcping` 通但浏览器打不开，问题在协议层（Reality 参数不匹配 / SNI 错误），而非网络层。

## 八、常见问题排障 FAQ

**Q1：优惠码提示「已过期」或「不适用于当前套餐」，怎么办？**
多数机场的折扣码有使用范围限制（仅限新用户 / 仅限年付 / 仅限特定套餐）。先确认三点：账号是否为首次下单、结算周期是否为年付、是否已叠加其他优惠。部分机场的优惠码与「新客首月半价」互斥。

**Q2：用了折扣码买的年付，中途想退怎么办？**
先看退款条款。2026 年行业内较通行的规则是「7 天内且流量使用小于 10GB 可全额退」。超过这个窗口基本只能按剩余月份比例折算，且部分商家会扣除「优惠码差额」——也就是把折扣补回来再退，实际到手可能只有原价的 40%。

**Q3：为什么同一个机场，别人能跑满带宽，我只能跑 30%？**
先排除本地因素：光猫是否千兆、路由器是否支持 NAT 硬件加速、网线是否为超五类以上。再用第六节的单线程测试验证是否被 QoS。仍不正常，考虑换入口节点或联系客服换线路。

**Q4：机场的「原生 IP」到底是不是原生？**
用 IP 查询工具看 ASN 类型。真正原生的标志是 ASN 归属为 ISP（如 NTT、KDDI、Verizon），而非云厂商（AWS、GCP、Oracle）。另外可以看 IP 的「滥用评分」，评分高于 60 的基本已被 AI 服务拉黑。

**Q5：多个机场同时订阅，客户端怎么管理最稳？**
建议用订阅组 + 规则分流，而非全局模式。把 AI 类域名、流媒体域名分别指向不同订阅组，避免单一机场故障时全盘断网。配置模板见 [/client/](/client/)。

**Q6：为什么晚高峰速度掉得特别厉害，白天却很快？**
这是超售的典型特征。白天用户少，带宽池充足；20:00 后并发上来，超出实际端口带宽，就会排队。判定方法：连续 7 天在 20:30 做单线程测试，若稳定衰减到峰值的 30% 以下，可判定为超售严重。

**Q7：优惠码可以叠加使用吗？**
绝大多数机场不支持叠加，但支持「优惠码 + 年付折扣」这种优惠类型组合。少数平台会在周年庆期间开放「折扣码 + 赠送流量」的活动，这类是性价比最高的窗口，通常在每年 3 月、6 月、11 月出现。
