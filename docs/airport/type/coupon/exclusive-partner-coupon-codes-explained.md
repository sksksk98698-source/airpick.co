## 二、底层机理：一条优惠链接从落地页到 postback 回传的完整链路

大多数用户以为"输个码减个价"就完事了，实际上一条专属链接背后至少跑着四套独立系统。我们把「光速云」这类头部服务商的合作链路拆开看：

**第一层：落地页参数解析。** 你点开的链接通常长这样——`https://example.com/#/?code=ABC123&ref=airpick`。注意这里用了 `#/` hash 路由，这是绝大多数机场官网用的 SPA 架构。**技术要害在于：hash 之后的参数不会被浏览器发送到服务器**，只能由前端 JavaScript 读取后再用 XHR 提交。所以一旦落地页的前端资源被广告拦截插件拦掉、被 CDN 回源失败阻断、或者本地 DNS 污染导致 JS 加载超时，`?code=` 参数就会**静默丢失**——页面照样打开，但你输的专属码根本没被记录。

**第二层：归因 Cookie 下发。** 落地页解析参数后，会在首方域写入一枚归因 Cookie（常见命名如 `aff_ref`、`click_id`、`_ap_src`），TTL 行业常见 30 / 60 / 90 天三档。部分中小服务商为了省事改用 localStorage，后果是你清一次浏览器缓存，归因就没了——这也是"折扣偶发消失"最常见的原因。

**第三层：注册写入与 coupon 表校验。** 注册时后端读取 Cookie 里的 `aff_id` 写入用户表。支付时结算页拿你输入的 coupon 字符串去查 `coupon` 表，校验四个字段：`valid_from`、`valid_to`、`max_uses`、`first_order_only`。**"长效专属打折码"在数据库里就是 `valid_to` 为空或写死 2099，而"首购券"则是 `first_order_only = true`。** 很多人骂服务商"第二次买就不打折了"，其实不是骗人，是字段设计如此。

**第四层：S2S postback 回传。** 支付成功后，服务商通过服务端回调把 `click_id`、订单金额、币种、状态推送给 affiliate 平台（自建或第三方如 Affise、Post Affiliate Pro）。结算周期通常 T+30 到 T+60，小厂甚至有 T+90 或直接不结��的。

**关键推论：归因采用 Last-click 覆盖机制。** 如果你先点了 A 渠道的码，隔了 20 天又点了 B 渠道的码，多数系统按最后一次点击归因，A 渠道的返佣归零。这就是为什么大促期间各渠道疯狂抢首触——也是为什么我们建议：**决定付费前，先清 Cookie 或无痕重走一次专属链。**

## 三、独家渠道专享码的四种形态与真伪判定

市面上流通的"商务合作专属优惠"实际只有四种形态，识别清楚才好比价：

- **形态 A · 纯折扣型**：结算价直接乘系数，8 折即 ×0.8。风险在于折扣基数可能被悄悄抬高。
- **形态 B · 时长赠送型**：付 12 个月得 14 个月，折算折扣约 85.7%。**这种对复购用户最友好，因为它不改动单月原价基准。**
- **形态 C · 额度加成型**：+50% 流量、+3 台设备并发。适合重度用户，但对轻度用户是伪收益。
- **形态 D · 混合型**：折扣 + 加成 + 续费同价。这才是真正的商务合作级，通常只有头部评测站能谈到。

**四个真伪判定指标，逐条对照：**

1. **码的熵值**。真独家码一般是无规律高熵字符串（如 `keqgvT5Y`）；伪独家码常常是 `VIP2026`、`AIRPICK88` 这类可猜的低熵串——低熵意味着它会被全网爬虫抓取、被无数人共用。
2. **落地页一致性**。点击专属链和手动输入码，结果必须完全一致。若不一致，说明折扣来自链接本身而非码，换个设备就失效。
3. **时间稳定性**。隔 7 天、换 IP、换设备、换支付方式复测一次。真长效码结果恒定。
4. **���因可见性**。用 `curl` 看响应头里的 `Set-Cookie`，能看到归因下发才算链路完整。

## 五、细分人群选型：谁该用独家码，谁纯属浪费时间

- **轻度用户（月流量需求低于 20GB、单设备）**：优先选「时长赠送型」。折扣型对你收益有限，因为基数本来就小；送的月份是纯增量。
- **中度用户（单人多设备，2～4 台终端）**：优先选「混合型」，尤其看重"全节点 x1 无倍率"这条——倍率是机场最隐蔽的成本，一个 5 倍率节点意味着你 100GB 只能跑 20GB，再大的折扣也填不平。
- **重度用户 / 跨境工作室（多账号、多地区 IP、频繁切换）**：必须盯着「设备并发数 + 原生解锁」两个指标。折扣是次要的，IP 池的干净程度决定你账号能不能活。
- **团队与商务场景（合规咨询、海外社媒运营、跨境店铺）**：唯一应该看的是「售后直达能力」和「线路稳定性 SLA」。这类用户用 96 折的官方码但配一条 IEPL 专线，体验远好于用 7 折码配一条拥堵中转。

**一句话原则：轻度看折扣，中度看倍率，重度看 IP 池，商务看 SLA。**

## 六、分平台实操：从浏览器到客户端的正确落地路径

激活一个专属码，顺序错了就白搭。以下是各平台的标准动作。

**浏览器层（决定归因成败）：**
1. 先开无痕窗口，或至少清空当前站点 Cookie，避免旧归因覆盖。
2. **临时关闭 uBlock Origin / AdGuard / 1Blocker 等拦截插件。** 原因很硬核：`aff`、`ref`、`click_id`、`utm_*` 是 EasyPrivacy 规则的高频命中关键字，落地页的归因 XHR 极可能被直接拦掉。
3. 从专属链进入 → 注册 → **在结算页先确认折扣已生效，再付款**。如果没生效，别急着付，先按下一节排查。
4. 支付方式（支付宝 / USDT / 信用卡）不影响归因，但部分网关回跳会重置 session，建议用同一浏览器窗口完成全流程。

**桌面客户端：** Clash Verge Rev、Mihomo Party、ClashX Meta 均可直接导入订阅链接；订阅转换建议用自建 subconverter，避免第三方转换服务记录你的订阅地址。配置模板细节参考 [/client/](/client/)。

**iOS：** Shadowrocket / Stash / Quantumult X 导入时注意关闭"订阅时自动更新节点"以外的第三方脚本，部分脚本会改写请求头导致 UA 异常。详见 [/client/shadowrocket/](/client/app/shadowrocket/)。

**Android / 路由器：** Clash Meta for Android 与 OpenWrt + Mihomo 组合最稳。路由器方案要注意旁路由 DNS 泄漏问题，否则流媒体解锁会从"原生"退化成"DNS 解锁"。
