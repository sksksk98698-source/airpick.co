# 新用户首单优惠 vs 老用户续费折扣：不同身份如何最大化省钱

## 一、TL;DR：先把结论摆在桌面上

如果你只有 60 秒，请记住这五条：

1. **首单优惠的折扣率普遍在 20%–35%，但绝对金额往往小于续费折扣的三年累计节省。** 以年付 300 元的机场为例，首单 8 折省 60 元；而连续三年续费每年用 8 折码 + 邀请返利，累计省下 300–450 元。
2. **"换新账号冲首单"在技术上多数可行，在经济学上多数不划算。** 一次完整换号（注册、付款、重配全设备、迁移规则）平均耗时 40–90 分钟；年付 300 元档的首单差价约 60 元，按时薪折算已接近亏损线。
3. **折扣的真实价值取决于它作用在哪一层。** 作用于"年付价之上"的 8 折，和作用于"月付价"的 8 折，年化差出 30% 以上。
4. **最优解是组合拳，而不是单点最优：** 首单锁定长周期 → 续费叠加打折码 → 邀请返利滚存 → 大促节点集中续费。实测长期年化成本可以压到标价的 55%–70%。
5. **省钱的前提是"买到的没缩水"。** 折扣套餐是最容易被悄悄降级的品类，必须用 `mtr` / `tcping` / TLS 握手耗时做链路体检，判定表见第八章。

## 二、底层机理：机场为什么要发优惠？——从 CAC / LTV 模型说起

要理解"首单优惠"和"续费折扣"为什么力度不同，必须先看清机场的成本结构。

**机场的成本有三个刚性层级：**

| 成本类型 | 计费方式 | 是否随用户量线性增长 |
| --- | --- | --- |
| IEPL / IPLC 专线包段 | 按月包段，固定支出 | 否（关键：边际成本极低） |
| BGP 中转 / 云厂商弹性带宽 | 按带宽峰值或流量计费 | 部分线性 |
| 落地机房与家宽 IP 池 | 按月租用 | 否 |

一条 10Gbps 级别的 IEPL 内网专线，月成本通常在五位数人民币区间，**无论上面跑 500 个用户还是 5000 个用户，这笔钱都要付**。这意味着：在专线未被跑满之前，每增加一个付费用户的边际成本接近于零。

由此推出两个行业铁律：

- **铁律一：规模效应决定了机场极度渴求"长期锁定的用户"。** 年付用户的 LTV（生命周期价值）通常是月付用户的 2–3 倍，因为留存率差异巨大——月付用户月流失率常见 15%–25%，年付用户年流失率通常低于 35%。机场愿意为年付让出 30%–40% 的折扣，本质是买你的"确定性"。
- **铁律二：续费折扣一定低于首单折扣，这是结构性的，不是歧视。** 拉新一个有效付费用户的 CAC（获客成本）在广告、Aff 分佣、SEO 内容投入上通常是 30–80 元；而挽留一个已有用户的成本接近于一条工单。所以首单优惠本质是**把广告预算转移支付给用户**，续费折扣本质是**留存预算**——后者天然更小。

理解了这一点，你就不会再把"老用户不如狗"当成情绪问题，而会把它当成一个可以在合同周期内套利的定价结构。

## 三、身份分层：新用户 / 老用户 / 回归用户的三方博弈

在实际的机场风控与定价体系里，用户其实被分成三档，每一档的议价能力完全不同：

**A 档 · 纯新用户（注册未付费）**
议价能力最强。几乎所有机场都为这一档预留了最大的折扣空间，因为"首次付费转化"是最难的一道坎。这一档的典型福利包括：注册即送体验流量、首单专属码、季付/年付阶梯折扣、渠道专属码（如渠道合作方发放的 8 折码）。

**B 档 · 存量老用户（有过至少一次付费）**
议价能力中等。手里能打的牌是：续费打折码、累计消费升级、邀请返利、节日大促。绝大多数机场**不会主动推送**续费折扣，需要你主动去找——这是一个典型的信息不对称套利点。

**C 档 · 回归用户（订阅过期 30 天以上）**
议价能力反而回升。部分机场会通过邮件或站内弹出定向发放"回归礼包"，力度介于 A 档与 B 档之间。如果你的订阅刚好到期，**不要第一时间续费**，先等 7–14 天看是否有召回触达，这是一个被严重低估的省钱动作。

## 五、新用户首单优惠深度拆解：折扣率是怎么算出来的

很多人看到"8 折"就默认省了 20%，这是错的。折扣作用在哪个价格基数上，结果差异巨大。

**案例演算（标价 30 元/月）：**

- 方案 A：月付 30 元 × 12 = 360 元/年
- 方案 B：年付直降 40% → 216 元/年，折合 18 元/月
- 方案 C：年付 216 元基础上再叠 8 折首单码 → **172.8 元/年，折合 14.4 元/月**

**方案 C 相对方案 A 的真实折扣率是 52%，而不是宣传页上写的 20%。** 这就是"阶梯折扣 + 首单码"叠加的威力，也是绝大多数用户没有用满的额度。

**首单优惠的常见形态与识别方法：**

1. **注册礼包**：注册即送 1–10GB 体验流量。价值不高，但可以用来做链路体检（见第八章）再决定付费。
2. **限时码**：有效期通常 7–15 天，过期作废。识别真伪的方法是看它是否在订单结算页真实减价，而不是"注册后自动发放但实际不生效"。
3. **渠道专属码**：由测评站、社群、Aff 渠道发放，力度通常高于官网公开码。这是首单优惠里价值最高的一类。
4. **阶梯折扣**：季付 9 折 / 半年 85 折 / 年付 7 折 / 两年 6 折。**注意：部分机场的阶梯折扣与首单码互斥**，结算前务必两个都试一遍，比较最终付款金额。

**必须警惕的三个首单陷阱：**

- **陷阱一：折扣只作用于月付。** 有些码写明"新用户 8 折"，但实际只对月付生效，年付仍按原价。结算页金额跳动会暴露真相。
- **陷阱二：折扣伴随倍率上调。** 便宜的套餐把节点倍率从 x1 改成 x2 甚至 x3，等于实际可用流量腰斩，隐性成本远超折扣。
- **陷阱三：折扣套餐被分配到劣质入口。** 这是最隐蔽的一种，需要用第八章的方法实测验证。

## 六、老用户续费折扣：六个入口，你大概率只用了一个

**入口 1 · 续费打折码**
最直接的一类。典型力度 8 折，通常作用于续费订单总额。有效期的规律是：大促前 3 天发放、大促后 7 天失效。建议在续费前先搜索"品牌名 + 优惠码"或直接查看测评站的码库页面 [/airport/type/coupon/](/airport/type/coupon/)。

**入口 2 · 累计消费阶梯**
部分机场按历史累计消费金额自动升级折扣等级（如累计满 500 元享 85 折、满 1000 元享 8 折）。**这一档通常不需要输入任何码，是自动生效的**，但很多用户根本不知道自己的账号已经升级。

**入口 3 · 邀请返利**
老带新。双方各得流量、天数或现金余额。这是老用户唯一能"越用越便宜"的机制——如果你有 2–3 个稳定推荐对象，返利可以覆盖相当一部分续费成本。注意：返利通常以余额形式发放，**不可提现，只能抵扣续费**，所以它提升的是 LTV 而不是现金流。

**入口 4 · 节日大促**
双 11、黑色星期五、春节、品牌周年庆是四大窗口。大促期间常见"年付 5 折 + 赠送 2 个月"。**这是全年折扣最深的时间点**，如果你的订阅周期可以调整，把续费时间对齐到大促节点，是单次收益最高的动作。

**入口 5 · 工单议价**
大额年付用户（单笔 500 元以上）可以礼貌地开一张工单询问"是否有长期客户优惠"。实测成功率不低，尤其在中小型机场。注意措辞要专业克制，不要威胁或施压。

**入口 6 · 套餐升级时的差价折算**
从低配套餐升级到高配时，部分机场支持按剩余天数折算差价。**先升级再续费**，有时比直接续高配更便宜，值得试探。

## 七、换新账号冲首单：技术可行性 vs 真实成本核算

这是本文最需要冷静的部分。

**7.1 技术可行性：机场用什么识别"同一个人"？**

| 识别维度 | 中小机场 | 头部机场 |
| --- | --- | --- |
| 邮箱地址 | 主要手段 | 辅助手段 |
| 支付宝 / 微信支付账号 | 多数不校验 | 强校验 |
| USDT / 加密货币收款地址 | 不校验 | 部分校验 |
| 设备指纹 / 浏览器指纹 | 基本不做 | 部分启用 |
| 注册 IP 归属 | 少数记录 | 多数记录 |
| 优惠码使用历史 | 记录 | 记录并关联 |
| 工单历史与常用节点 | 不关联 | 可关联 |

结论：**在中小机场，换邮箱 + 换支付渠道，成功率较高；在头部机场，支付指纹通常已经足够识别，且有 ToS 条款兜底。**

**7.2 真实成本核算（以年付 300 元为例）**

- 首单差价收益：约 60 元
- 换号耗时：注册 5 分钟 + 付款 5 分钟 + 全设备重配订阅 30–60 分钟（Clash / sing-box / Shadowrocket / 路由器）≈ **60 分钟**
- 隐性成本：旧账号流量统计与节点偏好丢失；若使用过邀请返利，余额清零；若被风控判定，**余额通常不退，且无申诉通道**
- 风险期望值：假设 15% 概率触发封号（头部机场更高），期望损失 = 15% × 300 元 = 45 元

**净收益 = 60（省下的） − 45（风险期望） − 时间成本（按时薪 100 元计 ≈ 100 元） = 负值。**

**7.3 什么情况下才勉强划算？**

只有同时满足以下三个条件时，换号套利才具备微弱经济性：

1. 年付金额 ≥ 600 元（差价绝对值够大）
2. 需要重配的设备 ≤ 3 台，且有现成的规则模板可一键导入
3. 该账号不承担任何关键业务链路（不影响工作、直播、跨境协作）

即便如此，AirPick 的立场依然是**不推荐**。原因很简单：这是一种把长期信任关系一次性折现的行为，而你失去的是未来所有老用户折扣的资格。

## 八、长期续费省钱策略：三条主线与三年复利模型

**策略 A · 以"年"为单位锁价，对抗涨价**
机场的调价方向几乎永远是向上。年付的本质是**用确定性换取价格锁定**。在通胀与带宽成本上升的周期里，一次年付相当于买了一份免费的涨价保险。

**策略 B · 大促节点集中续费 + 折扣码叠加**
把续费动作对齐到四大促节点，并提前 3–7 天收集折扣码。**注意叠加顺序：先看阶梯折扣，再叠码；部分机场会自动取最优，部分需要手动试。**

**策略 C · 主力 + 备用双线架构**
主力线路走 IEPL / IPLC 年付（稳定性优先），备用走轻量套餐或按流量计费（成本优先）。这样主力线的续费可以放心拉长到两年，备用的按月采购，整体成本反而低于单线年付。

**三年复利模型（以标价 30 元/月，年付原价 360 元 为基准）：**

| 策略组合 | 第 1 年 | 第 2 年 | 第 3 年 | 三年合计 | 占标价比例 |
| --- | --- | --- | --- | --- | --- |
| 纯月付，无任何优惠 | 360 | 360 | 360 | 1080 | 100% |
| 年付，无码 | 216 | 216 | 216 | 648 | 60% |
| 年付 + 首单码（仅第 1 年） | 172.8 | 216 | 216 | 604.8 | 56% |
| 年付 + 每年续费码 | 216 | 172.8 | 172.8 | 561.6 | 52% |
| **年付 + 续费码 + 邀请返利（2 人）** | 216 | 145 | 145 | **506** | **47%** |
| 每年换号冲首单 | 172.8 | 172.8 | 172.8 | 518.4 | 48%（风险未计） |

**关键洞察：最后一行是全文的核心结论。** 每年换号的账面成本和"合规组合策略"几乎持平（48% vs 47%），但你额外承担了全部风控风险、隐私暴露与时间成本。**这意味着换号套利在数学上已经没有优势。**

## 九、分平台实操避坑：优惠码在哪里输入，配置怎么不丢

**9.1 优惠码输入位置**
绝大多数机场的结算流程是：选择套餐 → 填写优惠码 → 点击"应用" → 金额刷新 → 支付。**务必确认金额真的变了再付款**。少数机场把优惠码框放在支付页最底部，容易被忽略。

**9.2 支付渠道选择**
支付宝 / 微信通常最稳，USDT / 加密货币适合隐私敏感用户但可能不参与部分活动。**不要使用第三方"代充"服务**——这是账号被盗与资金损失的高发场景。

**9.3 客户端配置的"可迁移性"设计**
省钱策略的前提是"能换、能迁"。建议从第一天就做好三件事：

- 把订阅链接保存到密码管理器中，而不是只在某台设备上
- 导出并备份一份规则文件（Clash 的 `config.yaml`、sing-box 的 `config.json`）
- 用路由器级别的统一入口（如 OpenWrt + 统一订阅），这样更换账号只需改一处

这部分的具体客户端操作，可参考 [/client/](/client/) 下的分平台教程。

## 十、抓包排障诊断手册：验证折后套餐有没有被降级

**核心逻辑：折扣套餐是最容易在链路层被"缩水"的品类。** 便宜的入口、更高的倍率、更差的落地，都不会写在宣传页上。以下命令可以还原真相。

**10.1 链路质量检测（macOS / Linux）**

```bash
# 1. 对订阅入口做 50 次 ICMP 探测，看丢包与抖动
mtr -rwzc 50 your-subscription-domain.com

# 2. TCP 层探测节点端口连通性与握手延迟
#    tcping 需先安装：brew install tcping
tcping -t 5 your-node-domain.com 443

# 3. DNS 解析链路（macOS）
scutil --dns | grep nameserver

# 4. 分段耗时：TCP 连接 / TLS 握手 / 首字节
curl -o /dev/null -s -w "connect=%{time_connect} tls=%{time_appconnect} ttfb=%{time_starttransfer}\n" https://your-node-domain.com/
```

**10.2 判定表（AirPick 实验室经验阈值）**

| 指标 | 优秀 | 可接受 | 异常（疑似降级） |
| --- | --- | --- | --- |
| mtr 端到端丢包率 | `0%` | `< 1%` | `> 3%` |
| 晚高峰（20:00–23:00）丢包 | `0%` | `< 2%` | `> 5%` |
| RTT 抖动（jitter） | `< 10ms` | `10–40ms` | `> 60ms` |
| TLS 握手耗时（`time_appconnect` − `time_connect`） | `< 80ms` | `80–200ms` | `> 350ms` |
| TTFB（`time_starttransfer`） | `< 150ms` | `150–400ms` | `> 800ms` |
| 首次连接耗时（`time_connect`） | `< 60ms` | `60–150ms` | `> 250ms` |

**10.3 高峰对比法（最有效的超售识别手段）**
在 **12:00 与 21:00 两个时间点分别执行同一组命令**，对比丢包率与 TTFB 的劣化幅度。如果晚高峰 TTFB 劣化超过 3 倍，或丢包率从 `0%` 跳到 `5%` 以上，基本可以判定存在超售或 QoS 限速。

**10.4 Windows 侧等价命令**

```powershell
# 持续 ping 观察抖动
ping -t your-node-domain.com

# 路径追踪
tracert -d your-node-domain.com

# TLS 握手耗时（PowerShell 7+）
Measure-Command { Invoke-WebRequest https://your-node-domain.com/ -UseBasicParsing }
```

## 十一、行业常见避坑矩阵

| 宣传话术 | 真实含义 | 验证方法 |
| --- | --- | --- |
