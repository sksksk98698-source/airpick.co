## 一、底层逻辑：为什么"送流量"这件事在成本上完全算得过来

先破除一个常见误解：很多人以为机场送流量是"烧钱营销"。真相是，**流量的边际成本远比你想象的便宜**。

一条香港方向 1Gbps 独享 IEPL 专线，月租在五位数人民币量级。理论上跑满可承载约 324TB，实际按 30%–40% 的平均利用率计算，一条线路每月真实承载大概 100TB 量级转发。折算下来，**每 GB 转发的边际成本大致落在 0.3–0.8 元区间**（视线路类型与套餐批量差异而浮动）。

也就是说：

| 试用赠额 | 服务商成本 | 行业平均注册→付费转化率 | 获客成本对比 |
| --- | --- | --- | --- |
| 1GB | 约 0.5 元 | 1%–3% | 远低于投流 |
| 3GB | 约 1.5–2.5 元 | 3%–8% | 极优 |
| 10GB | 约 5–8 元 | 8%–15%（多为强需求用户） | 依然划算 |

一个付费用户的行业获客成本（CAC）普遍在 40–150 元区间。**只要转化率超过 2%，送 3GB 试用就是稳赚的买卖。**

反过来推导：**任何宣称"永久免费不限量"的服务，其成本结构与商业模式根本不闭环**。它只有三种可能：

1. **流量转卖**：把你的流量再卖给第三方做代理池，你的身份和数据被动暴露；
2. **蜜罐/钓鱼**：收集账号密码、支付信息，或者干脆用于流量分析；
3. **超售到崩溃**：5000 人挤一条 100Mbps，晚高峰体验归零，本质是"免费但不可用"。

所以本文的核心立场很明确：**我们不推荐任何"永久免费"的梯子，只推荐"有节制、有边界、可验证"的注册送流量试用。**

## 二、底层网络机理：看懂这些，你才不会被参数表忽悠

### 2.1 BGP 中转 vs IEPL/IPLC：差的是"路径可控性"

- **BGP 中转**：机场在国内多线机房（电信/联通/移动）落地入口，再经公网出口中转出境。优点是便宜、灵活；缺点是**出口段走公网，QoS 限速与丢包不可控**。晚高峰 20:00–23:00 的跨境链路拥塞，主要就发生在这段。
- **IPLC（International Private Leased Circuit）**：国际私有租用电路，点对点物理专线，不经过公共互联网交换节点。运营商无法对"看不见的流量"做 QoS 整形，因此**晚高峰表现稳定**。
- **IEPL（International Ethernet Private Line）**：本质是 IPLC 的以太网化演进，二层透明传输，带宽粒度更灵活（可按 100Mbps/500Mbps/1Gbps 切分），时延通常比 IPLC 更低 2–8ms。

**实测鉴别方法**：用 `mtr` 看路径跳数。真 IEPL 在第 2–3 跳后进入专线，**中间不会出现大量 `???` 或跨网跳**；伪专线（实为公网中转）会出现明显的 202.97.x.x（电信 163）、219.158.x.x（联通 169）骨干节点。

### 2.2 QoS：晚高峰体验崩塌的真凶

跨境流量在运营商侧被标记为"国际非精品流量"，在拥塞时段按队列丢弃。表现为：**白天延迟 80ms，晚上 22:00 飙到 400ms + 丢包 15%。**

这不是机场的锅，是公网线路的物理宿命。**只有 IEPL/IPLC 能绕开这个队列。** 这也是为什么免费试用期一定要覆盖一个晚高峰——白天测出来的数据毫无参考价值。

### 2.3 BBRv3：丢包环境下的吞吐放大器

Google 的 BBR 拥塞控制算法在 BBRv2 基础上迭代出的 BBRv3（2024 年开源）显著优化了高丢包、高 RTT 场景的带宽利用率。相比传统 Cubic，在 1% 丢包率下，BBRv3 的吞吐可提升 **3–10 倍**。

意味着什么？**同样的线路，服务端内核有没有开 BBRv3，直接决定你单线程下载能跑 5MB/s 还是 25MB/s。** 这也是评测时容易被忽略的隐性变量。

### 2.4 TLS Reality / 协议伪装：决定"能不能连上"

2026 年主流抗封锁协议栈：

| 协议 | 特征 | 适用场景 |
| --- | --- | --- |
| VLESS + XTLS-Vision + Reality | 无需自有域名证书，借用真实站点 SNI | 抗 SNI 阻断首选 |
| Hysteria2（QUIC） | 基于 UDP，弱网高丢包下表现极佳 | 移动网络、跨境抖动线路 |
| Trojan-Go | 完整 TLS 仿真，兼容性好 | 老旧客户端 |
| Shadowsocks-2022 | AEAD 加密，抗重放 | 路由器、轻量场景 |

**试用期重点验证**：切到 Reality 节点能不能秒连、断流重连是否正常。很多机场只在付费节点部署 Reality，试用节点还是老协议——这正是筛选服务商态度的试金石。

### 2.5 双 ISP / 原生 IP：解锁能力的根基

"原生 IP"指 IP 注册地与实际广播地一致。Netflix、Disney+、ChatGPT 的风控系统会比对 IP 的 ASN 归属、注册地与地理库。**双 ISP 出口（同时接入两家运营商）能显著降低被标记为"机房 IP"的概率。**

## 五、细分人群与场景选型

### 5.1 纯尝鲜用户（此前从未用过）

**需求**：先确认"这东西能不能用"，不打算长期投入。
**策略**：选送 1–3GB、有效期 3 天以上的，把试用期完整覆盖一个工作日 + 一个周末晚高峰。
**重点关注**：能不能连上、能不能打开 ChatGPT、晚高峰会不会断。

### 5.2 AI 工具重度用户（ChatGPT / Claude / Gemini）

**需求**：稳定访问 AI 服务，不被风控拦截。
**策略**：试用期直接拿主力 AI 站点做压力测试——连续对话 20 轮、上传文件、调用 API。
**重点关注**：IP 是否被判为高风险（出现"unusual activity"提示即淘汰）、是否有原生 IP。

### 5.3 流媒体党（Netflix / Disney+ / HBO）

**需求**：4K 无缓冲、非自制剧全解锁。
**策略**：判断是"IP 解锁"还是"DNS 解锁"。**DNS 解锁在客户端侧容易被污染，且画质常被降到 720p。**
**验证**：播放非自制剧（如 Netflix 上的《老友记》），看是否报错。

### 5.4 开发者 / 远程办公

**需求**：GitHub 稳定拉取、Docker Hub 不超时、SSH 不断连。
**策略**：测试 TCP 长连接稳定性，用 `ssh -o ServerAliveInterval=30` 挂 30 分钟看是否掉线。
**重点关注**：是否支持 UDP（部分机场禁用 UDP，影响 QUIC/wireguard）。

### 5.5 跨境电商 / 多账号运营

**需求**：独立静态 IP，账号隔离，不被关联。
**策略**：**免费试用基本不满足这个场景**，通常需要独立 IP 的独享套餐。试用期只用来验证服务商是否具备独立 IP 资源。

## 六、分客户端实操配置与深度避坑

### 6.1 Clash Verge Rev / Mihomo（Windows / macOS）

```yaml
# 关键配置项
dns:
  enable: true
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  nameserver:
    - https://1.1.1.1/dns-query
    - https://8.8.8.8/dns-query
  fallback:
    - tls://1.1.1.1:853
```

**避坑点**：
- **TUN 模式 vs 系统代理**：TUN 能接管所有流量（含 Docker、WSL），但会与某些 VPN 冲突；系统代理轻量但不接管非 HTTP 流量。
- **Fake-IP 陷阱**：开启后 `nslookup` 返回 198.18.x.x 是正常的，不要以为是 DNS 被劫持。
- **DNS 泄漏**：务必在 `rules` 里加上 `DOMAIN-SUFFIX,google.com,PROXY` 之类的显式规则，避免走 `DIRECT`。

### 6.2 Shadowrocket（iOS）

- Reality 协议需 **iOS 14+**；
- 开启"UDP 转发"以支持 QUIC；
- 试用节点建议关闭"自动切换"，避免流量被多节点重复消耗。

### 6.4 路由器（OpenWrt + OpenClash / Passwall）

**核心提醒**：**不要在路由器上开"全局代理"跑试用流量。** 家庭网络里 NAS 备份、系统更新、云盘同步会在几小时内把你的 3GB 试用流量烧光。

正确做法：用 `nftables` 或规则列表做**域名分流**，只代理必要域名。

### 6.5 一条几乎所有新手都会踩的坑

**不要在试用期跑 Speedtest。**

一次满速测速（跑 10 秒 @ 200Mbps）就会消耗约 **250MB**。跑三轮就是 750MB，试用流量直接见底。

**正确做法**：先用延迟测试工具（见下一节）评估节点质量，确认要长期用再针对性测速。

## 七、抓包排障诊断手册

以下命令请按顺序执行，能定位 95% 的连接问题。

### 7.1 第一步：链路质量基线

```bash
# Linux / macOS：100 次探测，间隔 0.5s，输出统计
mtr -rwzc 100 -i 0.5 1.1.1.1
```

**关键看什么**：
- 第 2–3 跳（运营商接入）是否高丢包
- 中间是否出现 `202.97.*` / `219.158.*`（说明走了公网骨干）
- 末跳丢包率是否 `< 2%`

### 7.2 第二步：端口连通性与握手时延

```bash
# 需安装 tcping
tcping -t 10 -p 443 your-node.example.com
```

输出中关注 **avg / max / min** 三项。若 max 超过 min 的 5 倍，说明链路抖动严重，晚高峰必崩。

### 7.3 第三步：分段耗时拆解

```bash
curl -o /dev/null -s -w "DNS=%{time_namelookup} TCP=%{time_connect} TLS=%{time_appconnect} TTFB=%{time_starttransfer} TOTAL=%{time_total}\n" https://chat.openai.com
```

### 7.4 DNS 污染排查

```bash
# macOS
scutil --dns | head -30

# 对比默认解析与公共 DNS 解析结果
dig +short chat.openai.com
dig +short chat.openai.com @1.1.1.1
```

若两者结果差异巨大，说明存在 DNS 污染或分流规则失效。

### 7.5 抓包验证（进阶）

```bash
# macOS 查看 utun 接口
sudo tcpdump -i utun6 -n host your-node.example.com -c 50

# Linux
sudo tcpdump -i tun0 -n port 443 -c 50
```

### 7.6 症状 → 原因 → 处置判定表

| 症状 | 可能原因 | 验证命令 | 处置 |
| --- | --- | --- | --- |
| 节点能 ping 通但网页打不开 | DNS 污染 / 规则未命中 | `dig +short` 对比 | 开启 fake-ip + 显式规则 |
| TLS 握手超时 | SNI 被阻断 | `curl -v` 看卡在哪一步 | 换 Reality / Hysteria2 节点 |
| 白天正常，晚高峰断开 | QoS 限速 | `mtr` 看中间跳丢包 | 只能换 IEPL/IPLC 线路 |
| 延迟正常但下载极慢 | 服务端未开 BBR / 单线程限速 | 多线程下载对比 | 换节点或反馈 |
| ChatGPT 提示异常活动 | IP
