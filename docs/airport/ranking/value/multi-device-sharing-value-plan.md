## TL;DR：先把结论摆上桌

- **瓶颈不在流量，在并发。** 多设备共享机场出问题，90% 的情况不是流量跑超了，而是**并发连接数**和**入口带宽**被榨干了。流量是水库，并发是水管，水管细了你水库再大有屁用。
- **"不限连接数机场"是个营销词。** 业界真实的实现只有三种：不限设备数但限单 IP 并发、不限并发但共享节点带宽（超售）、以及高价专线套餐里的真·不限。前两种在 3 台设备以内你感受不到差别，第 5 台开始原形毕露。
- **家庭共享梯子的甜点区是 3-5 台设备。** 年付 BGP 中转或 IEPL 混合专线，月均成本能压到 7-15 元，比每人单独开号便宜 60% 以上，晚高峰 4K 基本无感。超过 6 台设备重度使用，任何机场都会互相拖后腿——这时候该做的是**双账号分流**，而不是硬扛一个号。
- **合租翻墙梯子最大的坑是"人不在你的控制范围内"。** 陌生人拼车意味着你的 IP 会被别人的行为污染，触发风控、被限速、甚至被整号封禁。本文第七章有完整的鉴别矩阵。

一句话：**共享可行，但要挑对线路类型、算清并发账、避开伪不限。**

## 一、重新理解"多设备共享"：共享的到底是什么资源

大部分人把机场套餐理解成"买流量"，这是最根本的认知偏差。一个机场账号在你手里的实际资源是四层：

1. **流量额度**（GB / 月）——最容易被看见，也最不重要。
2. **并发连接数**（同时活跃的 TCP/UDP 会话数）——决定你挂几台设备。
3. **入口带宽**（单用户可用出口 Mbps）——决定每台设备能跑多快。
4. **设备/IP 白名单**（同一时刻允许几个源 IP 认证）——决定会不会被踢号。

多设备共享机场的核心矛盾在于：**你的三台手机、一台电脑、一台电视盒子，在机场后台眼里可能只是"一个账号"，但在节点侧是 5 条独立的源 IP 或 5 组独立会话。**

这里有个反直觉的点：很多客户端（Clash Meta、sing-box、Surge）默认开启 MUX 多路复用，会把几十条应用层连接压缩到 2-3 条 TCP 隧道里。**这意味着开了 MUX 的用户，后台显示的"连接数"远比实际低。** 于是你会看到两种现象：

- 有些机场按"活跃 IP 数"计费——MUX 救不了你，因为你家路由器出口是 1 个公网 IP，但你老婆在公司用 4G 就是第 2 个 IP。
- 有些机场按"TCP 会话数"计费——MUX 是你的救命稻草，但代价是单条隧道拥塞时全部应用一起卡。

**结论：理解你买的机场按哪种口径统计，比对比价格重要十倍。**

## 二、底层网络机理：为什么有些机场一共享就崩

### 2.1 线路类型决定了并发天花板

| 线路类型 | 典型延迟（大陆→美西） | 晚高峰稳定性 | 单 GB 成本 | 建议共享人数 |
| --- | --- | --- | --- | --- |
| 直连（公网出口） | 180-260ms | 差，丢包 5-15% | 极低 | 1 人 |
| BGP 中转（国内多线入口） | 140-190ms | 中，丢包 1-5% | 低 | 2-3 人 |
| IPLC 专线 | 110-150ms | 优，丢包 低于 1% | 高 | 5-10 人 |
| IEPL 专线 | 120-160ms | 优，丢包 低于 1% | 高 | 5-8 人 |
| BGP + IEPL 混合 | 130-170ms | 良，丢包 1-3% | 中 | 3-5 人 |

直连线路在晚高峰走的是国际出口的公网拥塞段，几台设备一起下 4K，丢包率会指数级上升——这不是机场坑你，是物理链路就这样。而 IEPL/IPLC 是运营商级别的点对点专线，**带宽是买断的，不跟公网流量抢**，所以它是多设备共享的天然解。

代价是贵。所以 2026 年性价比最优的形态是**混合方案**：日常走 BGP 中转（便宜、够用），高峰期或大流量任务切换到 IEPL 专线节点。这类方案在多设备共享场景下性价比极高，第七章会给出具体对照。

### 2.2 QoS 限速：单连接限速是多设备杀手

部分机场为了"防滥用"，会对**单条 TCP 连接**做令牌桶限速，比如单连 20Mbps。这时候：

- 1 台设备看 4K（约 25Mbps）→ 直接顶到天花板，缓冲。
- 3 台设备各跑 10Mbps → 看上去都够，但总并发一上来，节点 CPU 打满，延迟抖动。

真正的"不限连接数机场"通常搭配**单连接不限速 + 总带宽整形**，而不是单连限速。这一点在你买之前几乎问不出来，只能靠实测——第六章给方法。

### 2.3 BBRv3 与拥塞控制

2025 年后主流机场节点基本都升级到 BBRv3 或 BBRv2。这对共享场景的意义是：**当多条隧道共用一条物理链路时，BBR 的公平性算法能显著降低"一个人把带宽吃光"的概率。** 如果你的节点还在用 CUBIC，多设备共享时的体验会明显更差，尤其体现在"下载一个文件后，其他人网页都打不开"。

### 2.4 TLS Reality 与抗封锁

VLESS + XTLS-Reality 在 2025-2026 年成为主流，它的意义对多设备共享用户是**协议层面的稳定性**：Reality 通过借用真实网站的 TLS 证书完成握手，被动探测几乎无法区分。相比老旧的 VMess+WS+TLS，Reality 在高并发下不会因为 TLS 握手排队导致首包延迟爆炸。

但注意：**Reality 需要客户端支持。** 老版本的 Clash for Windows 用不了，得换 Clash Verge Rev、Mihomo Party 或 sing-box。这在第五章的配置避坑里会展开。

### 2.5 双 ISP 入口与智能解析

高端机场会在国内部署电信 + 联通 + 移动三线入口，通过 DNS 智能解析把用户丢到最优入口。对家庭共享梯子的直接影响是：**你家宽带是电信，你老婆手机是移动，两个人走不同入口，互不抢带宽。** 这是"同一节点、多人不卡"的隐藏加分项，也是判断机场是否用心做基础设施的硬指标。

下表是评估一个机场"多设备共享友好度"的可操作清单。左边是你要问的问题，右边是及格线和优秀线。

| 同时在线 IP 数 | 决定跨网络共享是否被踢 | 3 个 IP | 5+ 或不限 | ★★★★★ |

| 单连接 QoS 策略 | 是否限制单连接速率 | 单连 50Mbps+ | 不限单连 | ★★★★☆ |
| 拥塞控制算法 | 多流公平性 | BBRv2 | BBRv3 | ★★★☆☆ |

**用法建议**：把你看中的 3 家机场按这个表打分，低于 6 项及格的直接排除。特别注意"同时在线 IP 数"这一栏——它比"设备数"更真实，因为大部分家庭是"手机 4G + 家里 Wi-Fi"两个出口。

## 四、场景化选型：四个人群，四套方案

### 场景 A：个人多设备（手机 + 电脑 + 平板，3 台以内）

这是最常见也最好办的场景。**一个账号足够，重点看客户端配置**，别为了"共享"去买贵套餐。选择 BGP 中转线路、年付 10 元/月档位的产品即可。

### 场景 B：家庭共享梯子（夫妻 / 室友，4-6 台设备）

甜点区。核心诉求是"晚上同时看剧不卡"。建议：

- 线路必须含 IEPL 或 IPLC 节点，晚高峰切过去。
- 选 3-5 个同时在线 IP 的档位。
- 路由器层面统一出口（第五章讲），把家里所有设备收敛到 1 个 IP，能省下大量并发额度。

不要合租一个号。**建议主号 + 备用号双轨**：主号跑固定办公 IP（公司 Wi-Fi 出口），备用号给移动办公。理由是：办公场景对"会话中断"零容忍，一个账号被限速会拖垮整个团队。

## 五、分平台实操配置与深度避坑

### 5.1 Windows：别再用 Clash for Windows

CFW 已停止维护超过两年，不支持 VLESS-Reality，且多设备共享时其 TUN 模式的 NAT 表管理有内存泄漏问题（长时间挂 3 台设备以上会看到内存占用持续爬升）。

**推荐**：Clash Verge Rev 或 Mihomo Party。

**关键设置**：
- 打开 `Mux`，`concurrency` 设为 4-8。太低浪费，太高反而增加队头阻塞。
- `TUN 模式` 开启，`Stack` 选 `Mixed`（gVisor 在某些游戏反作弊下会被拦）。
- 关闭 `UDP 直连`，让 UDP 走代理，否则游戏语音会暴露真实 IP。

### 5.2 macOS：scutil 是排障起点

macOS 上开 TUN 模式后，DNS 泄漏是最常见问题。检查命令：

```bash
scutil --dns | grep nameserver
networksetup -getinfo "Wi-Fi"
```

如果 `nameserver` 里出现运营商 DNS（比如 202.96.x.x），说明 DNS 没走代理，会导致部分流媒体判定你在国内。解决方式是在客户端里启用 `DNS 劫持` 并手动指定 `1.1.1.1`。

### 5.3 iOS：Shadowrocket 的并发陷阱

iOS 上最常被忽略的是**后台保活**。iOS 会在后台冻结网络扩展，导致你切到别的 App 后连接重建，表现为"每次打开都要等一下"。

**解决**：在 `设置 → 通用 → 后台 App 刷新` 中为 Shadowrocket 开启；同时把 `按需连接` 打���，避免频繁重连消耗并发额度。

### 5.4 Android：分应用代理是共享利器

Android 上 Clash Meta for Android（CMFA）支持**分应用代理**。家庭共享场景下，把电视盒子的流媒体 App、家人的社交 App 分别走不同策略组，能有效避免"一个人下游戏更新把带宽吃光"。

### 5.5 路由器 / 电视盒子：一次性收敛全家出口

这是家庭共享梯子最高性价比的玩法：

- 在路由器（OpenWrt / 爱快 / iStoreOS）上跑 Mihomo 或 sing-box，**全家设备统一走 1 个出口 IP**。
- 电视盒子用 `透明代理`，不用装任何客户端。
- 结果是：机场后台只看到 1 个在线 IP，你可以用一个"3 设备"档位的便宜套餐，实际服务 6-8 台设备。

**避坑**：
- 路由器性能不足（比如 MT7621 芯片）跑 TUN 模式会崩，建议至少 ARM 四核 1GHz + 512MB 内存。
- 不要在路由器上开 UDP 全量转发，NAT 表会爆，只对特定端口做规则。

## 六、抓包排障诊断手册

多设备共享出问题，99% 落在三个层面：**本地 → 入口 → 出口**。按顺序排查，别瞎试。

### 6.1 第一层：确认本地是否真的走了代理

```bash
# 看本地代理端口有没有流量
lsof -i :7890 | head -5

# 看真实出口 IP（对比直连和代理）
curl -s https://api.ipify.org
curl -s -x http://127.0.0.1:7890 https://api.ipify.org

# 看 DNS 是否泄漏
scutil --dns | grep nameserver
```

**判定**：两个 IP 相同 → 代理没生效。

### 6.2 第二层：到入口节点的链路质量

```bash
# macOS/Linux：mtr 看全程丢包
sudo mtr -rwzc 100 你的节点域名

# Windows：pathping 替代
pathping -n -q 50 你的节点域名

# TCP 层握手延迟（绕过 ICMP）
tcping -t 20 -i 1 你的节点域名 443
```

**判定表**：

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 前 3 跳丢包 | 本地网络/路由器问题 | 重启路由器，换网线 |
| 中间跳丢包但末端正常 | 运营商互联拥塞 | 换入口线路（电信→联通） |
| 最后一跳丢包 超过 5% | 节点本身过载或超售 | 换节点，或向机场反馈 |
| tcping 延迟正常但丢包高 | 节点 QoS 限速 | 换不限单连的节点 |

### 6.3 第三层：出口质量与真实吞吐

```bash
# 精确测量连接各阶段耗时
curl -o /dev/null -s -w "dns:%{time_namelookup} connect:%{time_connect} tls:%{time_appconnect} ttfb:%{time_starttransfer} total:%{time_total}\n" https://www.youtube.com

# TLS 握手细节（验证 Reality 是否正常）
openssl s_client -connect 你的节点域名:443 -servername www.microsoft.com 2>/dev/null | grep -E "Protocol|Cipher"
```

**判读**：`ttfb` 持续 超过 800ms，说明出口拥塞。此时如果只有你一个人在用，是节点问题；如果家里其他人也在用，就是入口带宽被共享吃满了——这正好验证了本文的核心论点。

### 6.4 多设备并发压测（家庭共享必做）

在客厅电视播 4K、卧室手机刷短视频、书房电脑下大文件，同时执行：

```bash
# 每 2 秒记录一次延迟
while true; do tcping -n 1 你的节点域名 443 | tail -2; sleep 2; done
```

如果延迟从 130ms 飙到 400ms 以上并伴随大量超时，说明你的套餐并发扛不住当前设备数。**要么升级套餐，要么上路由器统一出口。**

## 七、行业常见避坑矩阵

| 宣传话术 | 真实含义 | 鉴别方法 |
| --- | --- | --- |
| "不限连接数机场" | 通常是不限设备数但限单 IP 并发，或共享带宽的伪不限 | 问客服"单账号最大同时 TCP 会话数"，答不上来就是要警惕 |
| "支持 10 人共享" | 只是不主动踢号，带宽无任何保证 | 看是否提供 IEPL/IPLC 节点，无专线的"10 人共享"等于 10 人抢 |
| "4K 无压力" | 指单设备单连接场景 | 要求提供晚高峰 20:00-23:00 的实测截图 |
| "永久解锁 Netflix" | 节点 IP 恰好在解锁池里，随时会掉 | 自己用 `curl` 验证，别信宣传页 |
| "年付 3 元/月" | 大概率是超售到极致的直连线路 | 问清楚线路类型，直连线路多人共享必崩 |
| "无限流量" | 通常有隐性公平使用条款，超量限速 | 看 TOS 里的 Fair Use Policy |
| "免费试用" | 优质机场普遍提供 1-3GB 试用 | 无试用的高价机场优先排除 |

**关于"合租翻墙梯子
