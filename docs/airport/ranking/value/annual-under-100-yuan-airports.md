## 一、百元年付为什么可能存在？先把成本账算清楚

很多用户的困惑是："专线那么贵，凭什么一年只要 100 块？"要回答这个问题，必须把一条机场线路拆成四个成本模块。

### 1.1 入口成本：BGP 中转 vs IEPL/IPLC 专线

**IEPL（International Ethernet Private Line）** 是二层以太网专线，**IPLC（International Private Leased Circuit）** 是点对点租用电路。两者的共同点是：数据包从大陆入口出发，**不经过公网出口设备**，因此天然规避了国际网关的拥塞与 QoS 限速。代价是贵——香港方向的 IEPL 报价通常在每 Mbps 每月几十到上百元量级，一条 100Mbps 的专线一年就是六位数。

**BGP 中转** 则是机场在境内租用多线接入（电信/联通/移动三线优化）的服务器，再通过公网出口或中继节点把流量送到境外落地。它的成本只有专线的十分之一量级，但**出口段完全暴露在公网拥塞之下**——这就是为什么纯 BGP 中转机场在晚高峰会出现明显的速率塌陷。

百元以内年付能做到"看起来不卡"，主流方案是 **混合架构**：核心地区（香港、日本、新加坡）走 IEPL 小带宽做低延迟兜底，美区、欧洲等大流量场景走 BGP 中转摊薄成本。这种架构的关键在于调度策略是否合理，而非技术本身。

### 1.2 超售倍率：低价线路的数学本质

一条 200Mbps 出口带宽，如果卖给 20 个用户、每人标称 200Mbps，超售倍率就是 20:1。**超售不是骗局，而是所有共享带宽服务的商业前提**——飞机也没坐满过。问题在于超售倍率是否与真实用户行为模型匹配。

经验值参考：

- 超售 `8–15 倍`：正常商业区间，晚高峰体验可控
- 超售 `15–30 倍`：敏感区间，取决于用户活跃时段是否错峰
- 超售 `30 倍以上`：基本等于"抽奖"，晚高峰速率会塌到个位数 Mbps

百元以内年付机场因为客单价低，**几乎必然落在 15–25 倍这个区间**。所以你真正该关心的不是"它有没有超售"，而是"它超售之后还能不能跑"。

### 1.3 QoS 整形与 BBRv3：把烂路跑快的技术红利

**QoS（Quality of Service）** 在机场场景里通常表现为两类：入口侧的速率限制（每用户下行限速），以及运营商的流量整形（Traffic Shaping）——后者是导致"白天飞快、晚上龟速"的元凶，因为它会在链路拥塞时优先丢弃非标准端口的 UDP/TCP 流量。

而 **BBRv3** 的出现大幅缓解了这个问题。BBR 是基于带宽和 RTT 建模的拥塞控制算法，不依赖丢包作为拥塞信号。相比传统的 CUBIC，在高丢包链路（比如晚高峰的公网出口）上，BBRv3 的吞吐量可以提升 2–10 倍。**这恰恰是"低价机场也能用"的核心技术基础**——同样的烂线路，开了 BBRv3 的落地端和没开的落地端，实际体验差一个数量级。

选购时可以直接问（或从评测中判断）：服务端是否启用 BBRv3 或至少 BBR。这不是加分项，是**及格线**。

### 1.4 TLS Reality：伪装成本下降带来的价格红利

**REALITY** 是目前主流的抗主动探测方案，它的核心创新是：服务端不需要持有自己的域名和证书，而是借用真实大站的 TLS 握手特征。这带来的直接后果是——机场不需要为每个入口节点购买域名和证书，节点部署成本大幅降低。

对用户的影响有两面：

- 好处：节点数量增加、价格下降，且被动探测识别率显著降低
- 风险：REALITY 依赖服务端的 X25519 密钥与 shortId 配置，配置一旦泄露或轮换不当，节点会批量失效

**注意一个常见误区**：REALITY 对客户端时间不敏感，但 **VMess 的 AEAD 认证要求客户端与服务端时间偏差在 90 秒以内**。如果你用 VMess 节点频繁握手失败，先检查系统时间同步，而不是急着换节点。

### 1.5 出口 IP 类型与"双 ISP"

出口 IP 分三类：**原生 IP**（机房在该地区注册）、**广播 IP**（IP 段属于 A 地区但物理位置在 B 地区）、**住宅 IP**（运营商分配给家庭用户）。

流媒体平台和 AI 服务商的判定逻辑早已不只看 IP 归属，而是综合 ASN、历史行为、并发特征。所谓"双 ISP"通常指入口同时接入两家上行运营商做冗余——**它解决的是可用性问题，不是解锁问题**，两者不要混淆。

- **延迟最低不等于体验最好。** 纯 IEPL 的 35–55ms 很诱人，但如果超售到 25 倍，晚高峰的实际吞吐可能还不如 BGP 中转。
- **流量额度要和你的真实用量对标。** 1080p 视频约 1.5–3 GB/小时，4K 约 7 GB/小时。如果你每天看两小时 1080p，月流量消耗约 90–180 GB，那么 100GB 档会捉襟见肘。
- **"同时在线设备"是软性限制。** 多数厂商靠并发连接数而非设备数做限制，实际能连几台取决于你的使用强度。

## 三、细分人群与场景选型

### 3.1 轻度影音 + 社交用户（月流量 50–150 GB）

首选**混合架构的百元年付**。你的核心诉求是 YouTube 1080p 不转圈、Twitter/Instagram 刷得动，对延迟不敏感但对稳定性有基本要求。重点关注晚高峰丢包率和 Netflix 解锁节点数量。

### 3.2 出海开发者 / 远程办公（稳定压倒一切）

**不建议把百元年付当作唯一线路。** SSH 长连接、Git 推拉、云控制台操作对丢包极其敏感——丢包 3% 时，一个 `git clone` 的耗时可能是丢包 0% 时的 5 倍以上。建议：百元年付做备份，主力用中端专线；或者两台低价线路做故障切换。

### 3.3 跨境 / 多设备家庭（5 台以上）

优先看**设备数限制和是否有路由器级支持（订阅可直接导入软路由）**。百元档里，能同时满足"5 台 + 路由器导入"的产品不多，通常需要向上一档。

### 3.4 只用来登录 ChatGPT / Claude

**这是最容易被坑的场景。** 关键在于出口 IP 是否为原生 + 是否被列入风控名单。低价机场的 IP 池往往被大量复用，一个 IP 上有几百人问过同样的问题。建议专门测试目标节点的 IP 纯净度，而不是看总节点数。

### 3.5 极轻度用户（月流量 30 GB 以内）

**别买年付。** 按量流量包更划算：花 50 块买 200GB，能用大半年，还不用承担跑路风险。

## 四、分客户端实操配置与深度避坑

### 4.1 Windows：Clash Verge Rev / v2rayN

- 内核优先选 **mihomo（Clash Meta）**，对 REALITY、Hysteria2、TUIC 支持完整
- **TUN 模式**能接管所有流量，但需要开启"严格路由"防止 DNS 泄漏；同时注意与 VMware、Docker 的虚拟网卡冲突
- `url-test` 分组建议把 `interval` 设为 300 秒、`tolerance` 设为 50ms，避免节点频繁横跳导致连接中断
- **不要开全局模式。** 规则模式下国内流量直连，能省下大量额度

### 4.2 macOS：Clash Verge Rev / Stash / Surge

- 系统代理模式下，部分 App（如 Electron 系）不读取系统代理，需开 **增强模式/TUN**
- 排查 DNS 泄漏用 `scutil --dns`，确认 resolver 顺序
- 清缓存：`sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`
