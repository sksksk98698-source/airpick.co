## 二、为什么"按量"长期被贴上廉价标签

这不是用户偏见，而是成本结构决定的。

IEPL（International Ethernet Private Line）和 IPLC（International Private Leased Circuit）在运营商侧的计价单位是**带宽 × 月**，不是流量。一条沪港 100 Mbps 的 IEPL 专线，运营商向机场主收取的是固定月租，与你跑不跑满没有任何关系。

这就带来一个矛盾：**专线是固定成本，按量是浮动收入。**

于是绝大多数商家会把专线资源留给包月套餐（可预测的 MRR），把按量套餐当作"引流品"，用直连/中转线路来承接。久而久之，市场上"按量 = 廉价直连"的印象就被固化了。

但反过来看，只要商家愿意把专线池切出一部分做按量，客单价是可以覆盖成本的——因为专线的超售空间比直连小得多，**单位 GB 的真实成本本来就高**，定价 1–3 元/GB 是合理的，而不是割韭菜。

所以问题从来不是"按量能不能高端"，而是"哪家愿意把专线拿出��按量卖"。

## 三、底层技术背景：从物理层到拥塞控制

### 3.1 光速是硬约束，别信"零延迟"

光在石英光纤中的传播速度约为 `2.0 × 10^8 m/s`（折射率约 1.47）。这意味着：

| 路径 | 物理距离（约） | 理论单向延迟 | 理论 RTT 下限 |
| --- | --- | --- | --- |
| 上海 → 香港 | 1,250 km | 6.3 ms | 12.5 ms |
| 上海 → 东京 | 2,000 km | 10 ms | 20 ms |
| 上海 → 洛杉矶 | 12,000 km | 60 ms | 120 ms |
| 上海 → 法兰克福 | 11,000 km | 55 ms | 110 ms |

所以任何宣称"上海到美西 60ms"的，都是在看**单程**数据，或者在偷换概念。判断一条专线是否真专线，第一步就是拿 RTT 去对标物理下限。

### 3.2 BGP 中转 vs IEPL/IPLC

- **BGP 中转**：流量走公网，靠机房多线 BGP 选路。优点是便宜、弹性大；缺点是晚高峰公网拥塞、丢包率波动大，跨境段尤其明显。
- **IEPL/IPLC**：运营商内网专线，从入口机房直接拉一条二层/三层专线到海外落地机房，**不经过公网骨干**。丢包率常年稳定在 `0.01%` 量级，抖动极低。IPLC 传统上是 TDM/SDH，IEPL 是包交换（以太网），后者带宽弹性更好。

高端按量机场的核心价值就在这里：**你买的是那条专线的确定性。**

### 3.3 QoS、超售比与拥塞控制

- **QoS（服务质量）**：运营商在内网给专线打优先级标记（通常 DSCP EF/AF41），保证在链路拥塞时优先转发。这也解释了为什么同样是"过墙"，专线的抗丢包能力远好于公网。
- **超售比**：入口带宽与售卖带宽之比。1 Gbps 入口卖 5 Gbps 是超售 5 倍，属于行业常态；超过 20 倍就属于"晚高峰必崩"。高端按量机场通常把超售比控制在 **3–8 倍**。
- **BBRv3**：Google 的拥塞控制算法第三代。在有一定丢包的链路上，BBRv3 相比 Cubic 能提升 2–5 倍吞吐，且对 bufferbloat 更友好。判断机场是否技术过硬，看它落地机是否升级到 BBRv3/BBRv2，而不是还在用 Cubic。
- **TLS Reality / Vision**：2026 年主流协议栈。Reality 通过"借用"真实网站的 TLS 握手特征，把代理流量伪装成对该站点的正常访问，无需自购域名和证书，抗主动探测能力强。
- **双 ISP 原生 IP**：落地 IP 的 ASN 归属为住宅运营商（如 AT&T、Comcast、NTT 家宽段），而非 IDC 段。这对流媒体解锁、风控识别、账号注册场景至关重要。

## 五、细分人群与场景选型

**① 跨境远程运维 / DevOps（首选 A 档，星岛梦类不限时）**
核心诉求是 SSH 长连接不中断、RTT 稳定。丢包 `2%` 意味着 SSH 会话每分钟都要重传，体验极差。这类用户流量消耗极低（月均 `5–20 GB`），不限时按量是最优解。

**② 独立站 / 外贸后台运营**
需要固定出口 IP（避免风控触发二次验证）。要确认机场是否提供**独享落地 IP** 或至少**固定 IP 段**。流量中等（月均 `20–50 GB`）。

**③ 4K/8K 流媒体重度用户**
单集 4K 剧集约 `3–8 GB`，月消耗可达 `200 GB+`。这类用户按量并不划算，**建议走包月专线**，把按量套餐作为备用。若一定要按量，优先选 B 档且确认解锁方式。

**④ AI 大模型 / 论文检索**
ChatGPT、Claude、Gemini 对 IP 纯净度要求极高。IDC 段 IP 极易触发验证，**必须选原生住宅落地**。这类场景流量小、价值高，按量专线几乎是唯一理性选择。

**⑤ 游戏加速**
对延迟和抖动（jitter）敏感，对带宽不敏感。按量模式非常匹配，但要选**入口离你物理位置近**的节点。

**⑥ 长期备用机**
一年用不了几次，但关键时刻不能掉链子。不限时按量是唯一解——包月套餐的沉没成本太高。

## 六、分客户端实操配置与避坑

### 6.1 按量计费的"电量焦虑"从哪来？

90% 的用户流量是被自己无意烧掉的。常见"漏电"场景：

- **Speedtest 测速**：一次完整测速可能消耗 `1–3 GB`。按量套餐下建议用 `curl` 限字节测试。
- **系统自动更新**：Windows Update、macOS 更新、Steam、App Store 会在后台下载数 GB。
- **BT / P2P**：按量机场基本都禁止，触发即封号。
- **视频网站预加载**：YouTube 默认预加载下一段，Netflix 会缓存整集。
- **CDN 回源 / Docker pull**：开发者最容易踩的坑。

### 6.2 各客户端配置要点

**Mihomo（Clash Meta）/ Clash Verge Rev**
```yaml
# 关键：把测速节点排除在代理之外
rules:
  - DOMAIN-SUFFIX,speedtest.net,DIRECT
  - DOMAIN-SUFFIX,fast.com,DIRECT
  - DOMAIN-SUFFIX,steamcontent.com,DIRECT
  - DOMAIN-SUFFIX,apple.com,DIRECT
```
同时打开 `unified-delay: true` 关闭 URL 测试，改用 ICMP/TCP 握手延迟探测，避免每次切节点都烧流量。

**Surge / Stash（macOS & iOS）**
关闭 `Proxy > Test Group` 的自动测速，或在策略组里把 `interval` 设为 0。开启 `Gateway Mode` 前先确认局域网设备是否需要全程代理。

**Shadowrocket（iOS）**
- 关闭"全局路由"下的 `Proxy All`，改用配置模式；
- 关闭"自动更新订阅"；
- 把 App Store、iCloud 加直连规则（国内 iCloud 走国内 CDN）。

**sing-box / v2rayN（Windows）**
建议开启 TUN 模式配合路由表排除，但务必在规则里显式 `DIRECT` 打掉 `*.windowsupdate.com`、`*.steampowered.com`。

### 6.3 通用黄金规则

1. **按量套餐永远不要设置成全局代理。**
2. **永远只用一份设备连接。** 多设备同时跑，流量是叠加的。
3. **给套餐设置消费告警。** 星岛梦类后台一般有余额阈值提醒，务必打开。
4. **不要在按量套餐上跑大文件。** 需要下载时切回包月套餐或直连。

## 七、抓包排障诊断手册

当体验异常时，按下面顺序排查，别乱换节点。

### 7.1 基础连通性

```bash
# 1) 查看本机 DNS 配置（macOS）
scutil --dns | grep nameserver

# 1') Windows
ipconfig /all | findstr /i "DNS Servers"

# 2) 到机场入口的丢包与路由（Linux/macOS 需装 mtr）
mtr -rwzc 100 entry.your-airport.com

# 3) TCP 层探测（Windows 用 tcping.exe）
tcping -t 10 -i 0.2 entry.your-airport.com 443

# 4) 路由追踪（TCP 模式，避开 ICMP 限速）
traceroute -T -p 443 entry.your-airport.com

# 5) 出口 IP 与 ASN 归属
curl -s https://ipinfo.io/json

# 6) 限字节吞吐测试（只下 30MB，别烧流量）
curl -o /dev/null -w "%{speed_download} B/s\n" \
  "https://speed.cloudflare.com/__down?bytes=30000000"
```

### 7.2 判定表

| 现象 | mtr 表现 | 根因判断 | 处置 |
| --- | --- | --- | --- |
| 延迟正常但速度极慢 | 全链路无丢包，末跳延迟稳定 | 服务器侧限速 / 拥塞控制未开 BBR | 换协议为 Vision/Reality，或反馈工单 |
| 晚高峰必卡 | 第 3–5 跳开始出现 `5%+` 丢包 | 超售严重 或 中转公网拥塞 | 换同商家的专线入口 |
| 特定网站打不开 | 到入口正常，DNS 解析失败 | DNS 污染 / 分流规则误判 | 改 DoH（`https://1.1.1.1/dns-query`） |
| 只有 IPv6 慢 | mtr 显示 v6 路径绕路 | 落地 v6 走了远端出口 | 关闭 IPv6 或指定 v4 优先 |
| SSH 频繁断连 | 抖动 jitter `> 30 ms` | 线路本身在切换路径 | 换 IEPL 而非 BGP 中转 |
| 测速很高但网页慢 | 带宽正常，RTT 抖动大 | MTU / MSS 协商问题 | 降 MTU 到 1400 复测 |

### 7.3 快速判定"真假专线"

连续 24 小时、每 10 分钟记录一次到入口的 RTT 抖动：

```bash
for i in $(seq 1 144); do
  mtr -rwc 10 entry.your-airport.com | tail -1 >> rtt.log
  sleep 600
done
```

- 真专线：RTT 波动区间通常在 `±3 ms` 内，且晚高峰与凌晨曲线基本重合。
- 假专线（BGP 中转）：晚高峰 RTT 抬升 `10–40 ms`，且伴随丢包。

## 八、行业常见避坑矩阵

| 宣传话术 | 真实情况 | 识别方法 |
| --- | --- | --- |
| "IEPL 专线" | 实为中转+专线混合，只有个别节点 | 逐个节点 mtr，看跨境段是否走内网 ASN |
| "不限时流量" | 隐藏 12/24 个月有效期，写在用户协议角落 | 查后台流量详情页的到期字段 |
| "原生 IP 解锁 Netflix" | DNS 解锁（假解锁），IP 仍是 IDC 段 | `curl ipinfo.io` 看 ASN，住宅 ASN 才是原生 |
| "无限速" | 单用户限 100 Mbps，或三设备共享限速 | 用多线程下载压测峰值 |
| "0 超售" | 无人能验证，纯营销 | 看晚高峰压测稳定性，不看宣称 |
| "AI 专属节点" | 只是改名，IP 纯净度无差别 | 用 ChatGPT 实测是否触发人机验证 |
| "永久有效" | 商家跑路即失效 | 看运营年限与口碑，优先 3 年以上老牌 |
| "1 元 100G" | 限速 5 Mbps、仅限低峰时段 | 仔细读套餐说明的限制条款 |

**核心原则：凡是无法用命令行验证的宣传，默认不信。**

## 九、常见问题 FAQ

**Q1：按量套餐单价 2 元/GB，是不是被坑了？**
不一定。先算等效成本。如果包月 30 元给 100 GB（月清零），而你月均只用 8 GB，年支出 360 元。按量 2 元/GB、不限时，一年 96 GB 花费 192 元。**低用量用户按量永远更划算**，单价高不等于贵。

**Q2：流量不限时，商家会不会偷偷清零？**
这是必须警惕的点。建议每月截图保存后台流量余额，一旦发现异常立刻维权。选择运营 3 年以上的老牌商家能显著降低风险。

**Q3：按量套餐可以多设备同时用吗？**
通常可以，但设备数受限（一般 3–5 台）。同时在线会导致流量叠加消耗，且部分机场会按并发数计费。

**Q4：为什么同样的节点，按量套餐比包月套餐慢？**
如果确实存在差异，说明商家在做 QoS 分级，这在行业里并不罕见。挑选时应确认"按量与包月同线路同优先级"，星岛梦等头部商家通常在详情页明确写出。

**Q5：按量套餐能用来跑 AI 工具吗？**
可以，而且非常适合——AI 工具流量小（单次对话几百 KB），但对 IP 纯净度要求高。前提是落地必须是原生住宅 IP。

**Q6：我该买多少钱的按量套餐起步？**
建议首充 50–100 元。既能验证线路质量，也不会一次投入过多。用满一个月再决定是否加购。

**Q7：按量套餐和包月套餐能同时持有吗？**
推荐组合使用：**包月专线做主力**（大流量场景），**按量专线做备用**（应急、出差、特定 IP 需求）。这也是 2026 年资深用户的主流配置。
