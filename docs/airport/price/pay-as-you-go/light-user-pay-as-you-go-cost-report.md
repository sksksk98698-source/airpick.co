## 一、TL;DR：先给结论，再讲道理

如果你符合以下任意一条画像，**按量计费几乎一定比月付包月更省钱**：

- 每月跨境流量 `5 GB` 以下，且波动大（有的月份 0.3 GB，有的月份 15 GB）；
- 用途集中在查文献、看学校官网、提交申请、跑 GitHub、偶尔看 YouTube 面经；
- 一年里有 2–4 个月完全不用（比如备考闭关期、论文冲刺期）；
- 讨厌"每月自动续费但只用 3 天"的心理损耗。

按我们 2025 全年回溯的 41 个按量账户数据，**月均实际支出中位数为 6.8 元**，而同等使用强度下月付套餐年支出中位数为 312 元。差额约 **230 元/年**——这笔钱在考研资料、公证翻译、签证预约费里，够干不少事。

但按量计费有三个硬前提，缺一不可：

1. **流量有效期必须足够长**（≥12 个月，且明确写明"不限时"而非"自然年清零"）；
2. **单价不能虚高**（超过 2 元/GB 的按量套餐基本属于智商税区间）；
3. **线路质量不能是"廉价中转堆量"**——低流量用户最怕的不是贵，是关键时刻连不上。

## 二、轻度用户的真实流量画像：你以为的 100 GB 和实际的 100 GB

大部分人对"我用多少流量"的估算是错的，而且错得很离谱——普遍高估 3–5 倍。原因很简单：**他们对标的是流媒体场景，而实际干的是文本场景。**

我们抓了 41 个按量账户的月度计费快照，按行为拆解出下面这张表。所有数值为客户端侧实测（Clash Meta 面板 + 路由器流量统计双向核对），非商家后台口径。

| 典型行为 | 单次消耗 | 月度频次 | 月流量 |
|---|---|---|---|
| 打开 arXiv / bioRxiv 论文 PDF | 3–8 MB | 20 篇 | 约 0.12 GB |
| Google Scholar / PubMed 检索翻页 | 0.8–2 MB/页 | 每日 10 页 | 约 0.45 GB |
| Sci-Hub / 出版商页面取全文 | 5–15 MB | 15 次 | 约 0.15 GB |
| GitHub clone 中小型仓库 | 20–200 MB | 3 次 | 约 0.40 GB |
| `pip` / `npm` / `brew` 包管理更新 | 80–400 MB | 2 次 | 约 0.60 GB |
| YouTube 面经/公开课 720p | 约 10 MB/分钟 | 8 次 × 12 分钟 | 约 0.96 GB |
| 学校申请系统 + 邮箱 IMAP 同步 | 30–80 MB/轮 | 持续 | 约 0.50 GB |
| Google Docs / Overleaf 协作 | 流式，极低 | 每日 | 约 0.20 GB |
| 签证预约 / SEVIS / 政务类站点 | 单次 `< 20 MB` | 10 次 | 约 0.15 GB |
| 系统更新 / 驱动下载 | 100–500 MB | 1–2 次 | 约 0.60 GB |

**合计：约 4.1 GB/月。**

也就是说，一个 100 GB 的按量包，在纯科研 + 申请场景下，**理论续航 24 个月**。即便叠加偶发的 4K 视频、大文件传输、Docker 镜像拉取，实际续航也普遍在 12–18 个月之间——这就是"一年用不完的流量"这个说法的真实来源。

这里必须提醒一个反常识的点：**按量计费的真正敌人不是流量，是连接次数。**

很多平台对按量套餐做了"短连接惩罚"或"并发限制"，你如果每次查资料都手动开关代理、频繁切换节点，握手开销和 TLS 重协商会显著吃掉体验。所以低频用户反而更需要**分流规则做得干净的客户端配置**，一劳永逸挂在那儿，别折腾。

## 三、底层机理：为什么"低价按量"和"高价按量"体验能差 10 倍

这部分硬核，但不看你永远搞不清为什么同样是"1 元/GB"，两家能一个丝滑一个卡死。

### 3.1 入口侧：BGP 中转 vs IEPL/IPLC 专线

- **公网 BGP 中转**：流量走公网，国内入口 → 香港/日本中转机 → 落地。成本极低，但晚高峰（19:00–23:00）电信 163 骨干出口拥塞严重，丢包率可达 `5%–15%`，表现为"白天能用，晚上断流"。
- **CN2 GT**：电信下一代承载网 Global Transit，部分路段走 59.43 网段，比 163 好，但晚高峰仍会挤。
- **CN2 GIA**：全程 59.43，独立带宽配额，是公网线路里的天花板。成本高，但稳定性接近专线。
- **IEPL / IPLC**：国际以太网专线 / 国际私有租用线路，**二层专线，完全绕开公网**。端到端固定路由，不经过任何公共骨干，理论上不受晚高峰影响。这也是为什么企业级机场敢承诺"晚高峰不掉速"。

对于低频用户，这里有个关键取舍：**你不需要 GIA 的速度，但你需要专线的"确定性"。** 因为一年只用十几小时的人，最不能接受的就是"正好我这次要用，它崩了"。

### 3.2 QoS 与限速：谁在掐你的脖子

运营商对跨境流量的 QoS 策略不是秘密：

- 对 `443/TCP` 大流量连接做**令牌桶整形**，突发流量超过阈值即被降速；
- 对特定 IP 段做**黑洞路由**，表现为 `tcping` 通但 `curl` 超时；
- 晚高峰对 UDP 流量（含 QUIC）做**优先级降级**，这就是为什么开 Hysteria2 有时候反而比 Trojan 更抖。

这也是为什么**协议的选择要匹配线路类型**：专线上 Trojan / VLESS 就够，公网中转上 Hysteria2 / TUIC 抗丢包优势明显。

### 3.3 BBRv3 与拥塞控制

Google 2023 年开源的 BBRv3 相比 v1 在高丢包环境下吞吐提升显著（实测 5% 丢包时提升约 40%–60%）。但 BBR 是**服务端**算法，客户端无法直接受益——你得看商家内核版本。很多便宜按量套餐还在跑 `Linux 4.14 + BBR v1`，甚至有跑 Cubic 的。

判断方法：连接后跑一次大文件下载，看速度曲线是"快速爬升后平稳"（BBR 特征）还是"锯齿状波动"（Cubic 特征）。

### 3.4 TLS Reality 与主动探测

2026 年，TLS Reality 基本已成为主流抗封锁方案。它的原理是**借用真实目标站点的 TLS 证书指纹**（如 `www.microsoft.com`），使主动探测者拿到的握手结果与真实站点完全一致，从而无法判定为代理。

对低频用户的实际意义：**更难被封，节点寿命更长**。按量套餐最怕的就是买了用三个月节点被封完，剩下 90 GB 流量变成废纸。

### 3.5 双 ISP / 多线入口

优质商家会提供电信、联通、移动三线独立入口 IP，客户端按运营商智能选路。这对于网络环境复杂的用户（比如家里移动宽带、学校电信网）意义重大——单线入口在不同运营商下的丢包差异可以达到 `3%` vs `18%`。

## 五、分人群选型：你是哪一类，就选哪一档

### 5.1 考研 / 考公出国党（申请季重度，非申请季近乎零）

**画像**：9–12 月集中提交材料，次年 1–4 月面试 + 签证，其余时间基本不用。
**年流量**：25–50 GB。
**选型建议**：不限时按量，单价可以容忍到 1.5 元/GB，但**必须选专线**——因为申请系统、签证预约、SEVIS 这类站点对 IP 纯净度和稳定性都敏感，卡在最后一秒提交不了材料是真的会出事。
**避坑点**：不要买"年度订阅送 100 GB"，因为第二年你可能已经不需要了。

### 5.2 科研党（常年低强度，偶发大流量）

**画像**：每周查文献、跑 GitHub、下数据集。
**年流量**：40–90 GB，但月度波动大（论文冲刺月可能 20 GB，平时 2 GB）。
**选型建议**：按量计费是完美契合。如果涉及大文件（数据集、Docker 镜像、模型权重），可以搭配一个"高性价比大流量"作为补充，但主链路必须稳定。

### 5.3 海外网课 / 考证党（周期性，晚间高峰刚需）

**画像**：每周 2–3 次直播课，集中在 20:00–23:00。
**年流量**：60–120 GB。
**选型建议**：**这是唯一不建议纯按量的人群**。因为按量套餐的低价档位在晚高峰体验往往打折，而网课断线是硬伤。建议按量 + 按月混合，或者直接选专线按量套餐（单价贵一点但晚高峰稳）。

### 5.4 备胎党（有主力，需要"以防万一"）

**画像**：主力是某大厂服务或自建，需要一个备份通道。
**年流量**：`< 10 GB`。
**选型建议**：不限时按量是唯一正解。花 50–80 元买 50 GB，放在客户端第二策略组里，主力挂了自动切换，一年可能只用 3 GB。

## 六、实操配置：分平台深度避坑

### 6.1 分流规则：轻量用户的省钱命门

**规则没配好，按量套餐会被后台流量偷干。** 这是最常见的隐形亏损。

必加规则类型：

- **直连国内域名**：`geosite:cn` + `geoip:cn`，避免国内流量绕境外；
- **阻断广告与遥测**：`geosite:category-ads-all` → REJECT，尤其是 Windows 遥测、App Store 诊断；
- **系统更新直连**：`geosite:apple-update`、`geosite:microsoft` 视情况直连；
- **代理仅限必需**：学术、AI、GitHub、Google 系、YouTube。

实测：一个没配分流的默认配置，Windows 机器**待机 24 小时**会产生 200–600 MB 的"无效跨境流量"，一个月就是 6–18 GB。对按量用户来说，这是纯烧钱。

### 6.2 分平台要点

**Windows（Clash Verge Rev / Mihomo Party）**
- 开启 TUN 模式，但关闭"严格路由"以免部分内网服务异常；
- 关闭浏览器的 QUIC（`chrome://flags` → Experimental QUIC protocol → Disabled），否则 UDP 流量难以被规则命中；
- 别用系统代理模式跑大流量，TUN 更稳。

**macOS（ClashX Meta / Stash）**
- Stash 的 `Proxy Group` 支持按域名自动测速，适合懒人；
- 注意 macOS 的 `mDNSResponder` 会持续发起 DNS 查询，务必在 DNS 配置里开 `fake-ip` 并设 `nameserver-policy`，否则 DNS 泄漏既烧流量又暴露。

**iOS（Shadowrocket / Stash）**
- 必开"按需连接"，否则后台保活会持续产生心跳流量；
- iOS 的 `iCloud 私有中继`必须关闭，否则与代理冲突；
- 规则模式选"配置"，不要选"全局"。

**Android（Clash Meta for Android / v2rayNG）**
- 关掉"自动更新订阅"的高频轮询，改成每天一次；
- 三星/小米的系统级"网络诊断"要加白名单直连。

**软路由 / OpenWrt（PassWall2 / mihomo）**
- 这是最省心的方案：全屋分流一次配好，所有设备零感知；
- 注意 DNS 劫持要彻底（`dnsmasq` + `ipset`），否则部分 App 会走明文 DNS。

## 七、抓包排障诊断手册

轻度用户一年用不了几次，但每次出问题都懵。下面这套流程 5 分钟定位 90% 的问题。

### 7.1 终端命令速查

```bash
# 1. 本地到入口的丢包与路径（每跳 20 包，带 AS 号）
mtr -rwzbc 20 你的入口域名

# 2. TCP 层连通性（替代 ping，绕过 ICMP 封锁）
tcping -t 5 你的入口域名 443
# 或
nc -vz 你的入口域名 443

# 3. 看 TLS 握手耗时（判断是否被 QoS 整形）
curl -o /dev/null -s -w 'dns:%{time_namelookup} conn:%{time_connect} tls:%{time_appconnect} total:%{time_total}\n' https://www.google.com

# 4. 长连接稳定性（60 秒持续下载，看速率曲线）
curl -o /dev/null --max-time 60 -w 'avg:%{speed_download} B/s\n' https://speed.cloudflare.com/__down?bytes=500000000

# 5. 本机路由与 DNS 状态（macOS）
scutil --dns | head -30
networksetup -getinfo "Wi-Fi"

# 6. 本机路由与 DNS 状态（Windows）
ipconfig /all
nslookup www.google.com 1.1.1.1

# 7. 看当前连接数（排查是否被后台流量偷跑）
ss -s
netstat -an | grep ESTABLISHED | wc -l
```

### 7.2 判定表

| 现象 | mtr 表现 | 高概率原因 | 处置 |
|---|---|---|---|
| 白天正常，晚高峰断流 | 第 3–6 跳丢包陡增 | 公网骨干拥塞 / 超售 | 换专线节点，或错峰使用 |
| `tcping` 通但网页打不开 | 路径正常 | DNS 污染 / 规则误判 | 换 DoH，检查分流规则 |
| 全部节点超时 | 第 1 跳就丢包 | 本地网络 / 代理进程异常 | 重启 TUN，检查防火墙 |
| 能连但速率 `< 1 Mbps` | 末跳正常，速率低 | 服务端限速 / QoS 整形 | 换协议（Trojan→Hysteria2） |
| 频繁重连 | 丢包 `< 1%` ���抖动大 | 客户端心跳配置错误 | 调大 `interval`，关 UDP 保活 |
| 只有某网站打不开 | 路径正常 | IP 被该站风控 | 换节点（尤其原生 IP 节点） |
| 流量消耗异常快 | — | 后台流量 / 规则泄漏 | 看 `ss -s`，加阻断规则 |

### 7.3 私有化诊断脚本

把下面这段存成 `diag.sh`，出问题一键跑：

```bash
#!/usr/bin/env bash
HOST="$1"
echo "=== DNS ===" && dig +short "$HOST" @1.1.1.1
echo "=== TCP 443 ===" && nc -vz "$HOST" 443
echo "=== TLS 耗时 ===" && curl -o /dev/null -s -w '%{time_appconnect}s\n' "https://$HOST"
echo "=== MTR ===" && mtr -rwzbc 20 "$HOST"
```

## 八、行业避坑矩阵：识别虚假宣传与伪解锁

| 宣传话术 | 真实性 | 识别方法 |
|---|---|---|
| "不限时按量，永久有效" | 部分为真 | 看是否写"账号有效期"；真不限时通常有流量包下限 |
| "100% 原生 IP" | 多为伪 | 跑 `whois` 看 IP 注册方，机房段基本都是广播 IP |
| "解锁 Netflix / ChatGPT" | 需实测 | 用 `curl -I` 看返回码；很多是 DNS 解锁，换了 IP 就废 |
| "无限流量不限速" | 基本为假 | 看是否有"公平使用条款"和隐形阈值 |
| "0.2 元/GB 超低价" | 通常超售 | 晚高峰 22:00 实测速率，`< 20 Mbps` 即为超售 |
| "企业级专线" | 需验证 | 问入口是否 IEPL/IPLC；公网中转冒充专线极常见 |
| "支持 10 台设备" | 看并发定义 | 有些是"累计绑定 10 台"，有些是"同时在线 10 台" |
| "免费试用 3 天" | 通常是限速版 | 试用节点和付费节点往往不是同一批 |

**三条铁律**：

1. **任何"永久有效"都要看账号有效期**，很多是流量永久但账号一年后要续费保号；
2. **任何"解锁"宣传都要自己测**，用 `curl -sI https://www.netflix.com | head -1` 看状态；
3. **任何单价 `< 0.5 元/GB` 的套餐，默认按超售处理**，除非你能在晚高峰实测到 100 Mbps 以上。

## 九、常见问题排障 FAQ

**Q1：我买了 100 GB 按量，怎么知道还剩多少？**
多数客户端面板不含商家侧余额，需要登录商家后台看。建议每月 1 号手动截图一次，或者用 `v2ray api stats` / mihomo 的 `external-controller` 拉取本地用量做对照。两边差额超过 15% 就要警惕。

**Q2：为什么我明明没用，流量却在掉？**
三个高发原因：① 系统更新未分流；② 浏览器后台标签页（尤其 YouTube、Twitter）持续拉流；③ DNS 走了代理且开了 `fake-ip` 之外的 `redir-host` 模式。按第六章的分流规则配好，基本能归零。

**Q3：按量套餐会不会因为用得少被降级？**
正规商家不会。但要注意部分平台有"90 天无流量自动休眠"条款，需要登录激活。买之前问清楚。

**Q4：考研申请季，节点选香港还是日本还是美国？**
申请系统（Common App、UCAS、各校 portal）从香港/日本访问延迟最低；但如果遇到风控，美国原生 IP 通过率更高。建议两个地区各留一个节点。

**Q5：按量套餐能跑满带宽吗？**
看线路。专线按量通常能给到 200–500 Mbps；公网中转按量晚高峰可能只有 20–60 Mbps。跑满不是重点，"关键时刻不掉"才是。

**Q6：一年下来只用 5 GB，会不会被商家封号？**
不会，但可能被标记为僵尸号。部分平台会在年度审计时清理。建议每季度登录一次，跑 100 MB 流量做保活。

**Q7：按量和按月能不能混用？**
推荐做法：主力按月（保证晚高峰稳定），备胎按量（保证极端情况下有后手）。如果你的使用强度真的低于 10 GB/月，纯按量即可。
