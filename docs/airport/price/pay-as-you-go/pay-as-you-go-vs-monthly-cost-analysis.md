# 按量计费与包月套餐经济账对比：你到底属于哪类翻墙用户

## 结论先行（TL;DR）

先把账算清楚，再谈选哪个：

**盈亏平衡月流量 = 包月月费 ÷ 按量单价（元/GB）**

- 包月 ¥25/月、给 200GB，按量套餐 ¥2.0/GB 不限时 —— 平衡点 = 25 ÷ 2.0 ≈ **12.5GB**。你每月真实用量低于 12.5GB，按量更省钱；高于它，包月更划算。
- 但这条公式有个致命前提：**包月的 200GB 你能用完**。绝大多数机场包月套餐的有效期只有 30 天，月底清零，用不完的额度不结转、不退现。按量套餐的不限时额度是可累积资产，包月的额度是易腐库存。两者的成本结构根本不同。

一句话选型：

| 你的画像 | 推荐模式 |
| --- | --- |
| 每月真实流量低于 15GB、使用频次低而不稳 | **按量计费** |
| 只是备用线路、主线路在别家、偶尔应急 | **按量计费** |
| 多设备长期挂机、4K 流媒体、AI 大模型重度调用 | **包月大流量** |
| 企业/团队、需要专线 SLA 与固定出口 IP | **包月/独享，按量只作备份** |
| 学生党、季度性出差、海外版 App 低频验证 | **按量计费** |

## 一、底层机理：两种计费模式在网络上到底卖的是什么

要理解价格差异，必须先理解机场的成本结构。

**包月套餐卖的是"并发带宽的分时复用权"。**

机场向运营商买的是两条东西：一条固定带宽的专线出口（比如 500Mbps IPLC），和一个流量池。包月模式下，机场把这条 500Mbps 卖给 3000 个用户，靠的是统计复用 —— 假设同时在线并跑满的用户不超过 3%。这就是**超售比**，行业里 30:1 到 100:1 都算常见，做得好的是 20:1。

超售意味着：晚高峰 20:00–23:00，当同时在线率超过设计水位，QoS 策略就会介入。你在机场后台看不到任何提示，但感受得到 —— 从 4K 秒开变成 1080p 都卡、晚高峰丢包率从 `0.1%` 飙到 `5%`、`mtr` 显示某跳延迟从 40ms 变 200ms。这就是包月最大的隐性成本：**你买到的是"平均可用带宽"，不是"峰值带宽"**。

**按量计费卖的是"流量本身"。**

按量模式下，机场不担心并发，因为用户自己会节制 —— 用一点扣一点，用得越多付得越多。因此按量套餐的节点通常是**高成本专线（IPLC/IEPL）直接切出一部分**，超售比可以压到 5:1 以内，甚至 1:1。因为流量计费天然自限，运营方不需要靠超售来摊薄成本。

这里有个反直觉的结论：**同一家机场，按量套餐的 QoS 优先级往往高于包月套餐，即使按量用户的月付金额更低。** 原因是按量用户贡献的是"边际高毛利流量"，而包月用户挤占的是"固定带宽存量"。很多机场的 QoS 分级策略里，按量流量走 `priority 1`，包月流量走 `priority 2`。

### 1.1 线路等级决定了成本底线

- **BGP 中转**：多线接入，动态选路。成本最低，晚高峰抖动最大。常见于 ¥10–20/月套餐。
- **IEPL（国际以太网专线）**：二层/三层专线，端到端 SLA，抖动可控在 5ms 内。成本是 BGP 的 3–8 倍。
- **IPLC（国际私有租用线路）**：物理点对点专线，不经过公网路由，延迟曲线几乎是一条直线。成本最高，通常只在高价套餐或按量套餐里出现。
- **双 ISP 入口**：入口侧做两家运营商冗余，避免单点接入段拥堵。这是 2025 年后中高端机场的标配。

如果你的按量套餐单价在 ¥1.5–2.5/GB 区间，基本可以确认走的是 IPLC/IEPL 专线切片 —— 因为 BGP 中转的按量成本撑不起这个定价下的利润。低于 ¥1/GB 的"不限时按量"，要么是 BGP 中转套壳，要么流量池是共享的、限速严重。

### 1.2 BBRv3 与 TLS Reality 对流量账的影响

这两个技术点直接影响你的实际流量消耗和计费准确性：

- **拥塞控制算法 BBRv3**：相比 CUBIC，BBRv3 在丢包 2% 的环境下能把吞吐提升 3–10 倍。副作用是**它会主动探测带宽，重传率上升**，实际计费流量可能比 CUBIC 高出 3%–8%。如果你做的是大文件传输，这个差异一年下来不是小数目。
- **TLS Reality / XTLS-Vision**：这类协议做的是"零额外开销"封装，握手阶段不暴露证书，抗主动探测能力强。但要警惕某些老旧的 VMess+WS+TLS 链路，TLS 封装本身会带来 5%–12% 的协议开销 —— 你传输 1GB 内容，计费可能算 1.1GB。选支持 Vision / Reality 的客户端（如 sing-box 1.11+、Clash Meta / Mihomo 内核）能省下这部分。

## 三、翻墙流量消耗测算：你的月流量到底是多少

几乎所有人在估算自己流量时都会高估 2–3 倍。下面是实测口径下的真实消耗：

| 使用场景 | 单位消耗 | 月消耗估算（假设强度） |
| --- | --- | --- |
| 网页浏览 / 搜索 / 文档 | 60–150MB/小时 | 每日 1h → 约 3GB |
| YouTube 1080p | 1.4–1.9GB/小时 | 每日 1h → 约 50GB |
| YouTube 720p | 0.6–0.8GB/小时 | 每日 1h → 约 21GB |
| YouTube 4K | 6.5–8GB/小时 | 每日 1h → 约 220GB |
| Netflix 1080p | 2.5–3.2GB/小时 | 每日 1.5h → 约 130GB |
| Zoom / Meet 1080p | 1.5–2.5GB/小时 | 每周 5h → 约 40GB |
| 语音通话（WhatsApp/TG） | 30–60MB/小时 | 每周 5h → 约 1GB |
| AI 大模型对话（纯文本） | 3–15MB/轮 | 每日 30 轮 → 约 5GB |
| AI 多模态 / 图片生成 | 20–80MB/次 | 每周 20 次 → 约 6GB |
| GitHub clone / Docker pull | 单次 0.5–5GB | 每周 3 次 → 约 30GB |
| 在线游戏（协议流量） | 40–120MB/小时 | 每日 2h → 约 5GB |
| App Store / 系统更新 | 单次 1–8GB | 每月 2 次 → 约 10GB |

**三个关键洞察：**

1. **"看视频"是流量黑洞，其它都是零头。** 不看流媒体的话，一个重度办公用户 + AI 用户的月流量也就 40–60GB。一旦沾上 4K，直接冲到 200GB+。
2. **代理流量 ≠ 你的总流量。** 只有走代理规则的流量才计费。分流规则写得好的话，国内视频、微信、部分 CDN 直连，能砍掉 30%–60% 的代理流量。这是最容易被忽略的省钱手段，具体配置见第五节。
3. **上行流量通常不单独计费，但会算入总量。** 视频会议、直播推流的上行用量是下行的一半左右，测算时别漏。

**实操建议：先跑 30 天真实统计再决定。** 在客户端里开启流量统计（Mihomo 内核的 `/traffic` API、sing-box 的 clash_api 都能读到），或者用路由器端的 `iptables` 计数。拿到真实数字后再套第一节的平衡点公式，误差不会超过 15%。

## 四、细分人群选型推荐

**人群 A｜低频验证型（月流量 0–10GB）**
特征：只看推特、查资料、验证海外 App、偶尔 Google Scholar。使用时间不规律，可能一周不用一次。
→ **明确选按量。** 买 100GB 不限时包，能用一年以上，年均成本比包月低 70%。

**人群 B｜备用冗余型（主线路在别家）**
特征：主力机场是包月，但需要第二条线路防主线路跑路或晚高峰崩。
→ **明确选按量。** 备用线路的价值在"随时可用"，不在"用满额度"。包月备用线每月 20 元、一年 240 元，全是沉没成本。

**人群 C｜中度日常用户（月流量 20–60GB）**
特征：每天刷 YouTube 1080p 一小时，不看 Netflix 4K，正常办公。
→ **模糊区，按平衡点算。** 大多数情况下按量仍占优，除非单价高于 ¥1.5/GB。

**人群 D｜重度流媒体用户（月流量 150GB+）**
特征：Netflix/Disney+/HBO 常驻，4K 观影，多设备。
→ **选包月大流量或流媒体专线套餐。** 按量在这个量级会失控，单价再低也是几百元。

**人群 E｜企业与团队**
特征：需要固定出口 IP、SLA、审计日志、工单响应。
→ **包月/独享，按量作为灾备。** 企业侧真正买的是可用性承诺和合规凭证，不是流量单价。

## 五、分平台实操配置与深度避坑

### 5.1 分流规则：决定你账单的最大变量

无论按量还是包月，**分流规则写得好 = 直接打折**。

Mihomo（Clash Meta）内核推荐配置骨架：

```yaml
rules:
  # 国内直连，不计代理流量
  - GEOIP,CN,DIRECT
  - GEOSITE,cn,DIRECT
  - GEOSITE,private,DIRECT
  # 流媒体走专用策略组（按量用户可考虑排除）
  - GEOSITE,netflix,Streaming
  - GEOSITE,youtube,Streaming
  # AI 服务走稳定节���
  - GEOSITE,openai,AI
  - GEOSITE,anthropic,AI
  - MATCH,Proxy
```

**按量用户的专属优化**：把 `Streaming` 策略组指向 DIRECT（如果你不介意国内平台体验差异）或者干脆让 Netflix 走你不常用的低优先级节点 —— 但更有效的做法是：**按量套餐不要用来跑 4K**。

### 5.2 平台侧注意事项

- **iOS / Shadowrocket**：开启"按需连接"与"流量统计"，能实时看到本月代理流量。注意 Shadowrocket 的统计口径包含协议开销，比机场后台数字高 5%–10%。
- **macOS / Clash Verge Rev**：使用 TUN 模式时，所有流量都过内核，统计最准。若用系统代理模式，部分 App 会绕过代理，统计偏低。
- **Android / sing-box**：开启 `clash_api` 或 `v2ray_api`，配合 `box for Magisk` 可做应用级分流，把国内 App 彻底排除在计费之外。
- **路由器 / OpenWrt**：用 `nftables` 计数或 PassWall 的流量统计模块，全屋设备统一口径。

### 5.3 通用避坑清单

1. **不要在按量套餐上挂 BT / PT。** 上行流量会瞬间打穿余额，且多数机场明令禁止 P2P。
2. **关闭自动更新。** Steam、App Store、Windows Update 走代理一次就是几个 GB。
3. **关掉云盘同步。** iCloud、OneDrive、Google Drive 在后台上传，你可能完全无感。
4. **慎用"全局模式"。** 全局模式意味着所有流量都计费，和分流模式的差距可以达到 3 倍。
5. **注意 UDP 计费口径。** 部分机场 UDP 流量按 1.5–2 倍计费，QUIC 协议（HTTP/3）会走 UDP。可以在客户端禁用 QUIC 强制走 TCP。

## 六、抓包排障诊断手册

流量对不上、速度掉到脚踝、怀疑被限速 —— 用下面的命令链路逐层定位。

### 6.1 链路质量诊断

```bash
# 1. 端到端路径与丢包（推荐 100 包样本）
mtr -rwzbc 100 1.1.1.1

# 2. 代理入口的 TCP 握手延迟（需安装 tcping）
tcping -t 10 your-node-domain.com 443

# 3. 多次采样 HTTPS 建连耗时
curl -o /dev/null -s -w "connect:%{time_connect} tls:%{time_appconnect} total:%{time_total}\n" https://www.google.com

# 4. 纯吞吐压测（需对端 iperf3 服务）
iperf3 -c your-node-domain.com -p 5201 -t 30 -P 4

# 5. Linux 侧查看网卡累计流量，验证客户端统计
ip -s link show
```

macOS 补充：

```bash
# 查看当前 DNS 解析路径，确认是否被污染
scutil --dns | head -40

# 查看无线链路质量与信号
networksetup -getinfo Wi-Fi

# 查看当前 TCP 连接与重传
netstat -s -p tcp | grep -Ei "retrans|drop"
```

Windows 补充：

```powershell
tracert -d -h 20 1.1.1.1
nslookup www.google.com
Get-NetTCPConnection -State Established | Measure-Object
```

### 6.2 判定表

| 现象 | 高概率原因 | 处置动作 |
| --- | --- | --- |
| 第 1–3 跳延迟正常，中间某跳延迟陡增且持续 | 出境口拥堵或 QoS 限速 | 换入口 / 换协议 / 反馈机场 |
| `mtr` 丢包集中在某一跳且后序跳恢复正常 | ICMP 限速，非真实丢包 | 忽略，用 tcping 复核 |
| `tcping` 握手正常但 `curl` 首字节慢 | TLS 握手被干扰或节点过载 | 换协议为 Reality / Vision |
| 速度稳定在某个整数（如 10Mbps、30Mbps） | 被客户端软限速或被 QoS 整形 | 检查订阅里的限速字段 |
| 客户端统计远大于机场后台 | 分流规则失效或 UDP 双倍计费 | 核对规则集与 UDP 口径 |
| 白天飞快、20:00 后崩 | 超售触发，典型包月症状 | 升配或换按量线路 |
| DNS 解析结果异常（0.0.0.0 / 无响应） | DNS 污染或劫持 | 改用 DoH / 加密 DNS |

### 6.3 排查顺序原则

**先分层，再定性。** 顺序永远是：物理链路 → ���地网络 → DNS → 代理握手 → 协议封装 → 节点出口 → 目标站。一次只改一个变量，否则你永远不知道是哪一步修好的。

## 七、行业常见避坑矩阵

| 宣传话术 | 真实含义 | 识破方法 |
| --- | --- | --- |
| "不限量 / 无限流量" | 通常有 Fair Use 暗条款，超量限速到 1–3Mbps | 找服务条款里的"合理使用"章节 |
| "不限时" 与 "永久" 混用 | 不限时 = 12 个月有效；永久 = 账号存续期内有效 | 直接问客服，要求书面确认 |
| "IPLC 专线" | 可能只是国内段 BGP + 海外段 IEPL 拼接 | 用 `mtr` 看是否有点对点跳数特征 |
| "4K 解锁" | 常见为 DNS 解锁，非原生 IP | 用流媒体检测脚本查 `residential` 判定 |
| "1 元试用 100GB" | 试用流量不计入正式包，且限速 | 关注试用期后的转化定价 |
| "年付 5 折" | 拉长跑路风险敞口 | 首年尽量月付或按量试水 |
| "节点 200+" | 大量是同一落地机的不同入口 | 测延迟分布，看是否高度雷同 |
| "秒开 4K" | 单线程测试无意义 | 用 `-P 4` 多线程 iperf3 复核 |

**三条铁律：**

1. **按量套餐的跑路风险天然低于包月。** 你最多损失未用完的余额；年付包月一次损失可能是 300–1500 元。
2. **任何"看起来太便宜"的按量套餐，流量池一定是共享的。** 单价低于 ¥1/GB 的"不限时"，请在购买前用 `mtr` 验证线路等级。
3. **新机场不要年付。** 先按量买 50GB 试一个月，观察晚高峰抖动、工单响应速度、续费定价是否变动，再决定是否升级。

## 八、常见问题排障 FAQ

**Q1：按量套餐的流量用完了会怎样？**
通常有两种处理：一是直接断流，需要续费；二是进入"限速不限量"降级模式（速率 1–5Mbps）。购买前务必确认。星岛梦等主流按量服务商采用前者，额度独立、不清零、不降级。

**Q2：为什么机场后台显示的流量比我客户端统计的多？**
三个常见原因：① 协议封装开销（VMess+WS+TLS 可达 8%–12%）；② UDP 流量按倍率计费；③ 客户端统计未覆盖 TUN 模式下的部分系统流量。以机场后台为准，这是计费基准。

**Q3：包月套餐到期后剩余流量能结转吗？**
绝大多数不能。少数支持"结转 30 天"或"按比例折算到按量余额"。这是包月模式最大的一笔隐性损耗 —— 也是我们建议低频用户转向按量的核心理由。

**Q4：我同时用包月和按量，客户端怎么配置？**
用策略组做双线：主策略组指向包月节点，备用策略组指向按量节点，配合 `fallback` 或 `url-test` 健康检查。主线路探活失败时自动切到按量，既保体验又控成本。

**Q5：按量套餐可以多人共享吗？**
技术上可以，但注意并发设备数限制（常见 3–5 台）。多人共享时流量消耗是叠加的，且一人挂 P2P 会拖垮整个账号。家庭场景建议包月多设备套餐。

**Q6：为什么我按量刚充 100GB，一天就掉了 20GB？**
九成是以下之一：全局模式 + 云盘同步、系统更新走代理、QUIC/UDP 倍率计费、或 P2P 后台上传。按第六节的命令链路先确认流量去向，再查规则。

**Q7：按量和包月可以互相转换吗？**
部分机场支持"按量余额抵扣包月"，多数不支持反向折算。购买前的策略是：**先用按量试水验证线路质量，确认满意后再考虑包月**。反过来做，沉没成本更高。
